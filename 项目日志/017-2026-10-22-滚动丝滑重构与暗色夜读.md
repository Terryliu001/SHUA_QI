## 1. 用户报障与需求

1. 滚动模式**滑动不丝滑**；
2. 按设计哲学（谷歌灵动 + iOS 优雅简练、服从长时间读 PDF 场景）做**一套暗色环境下的质感设计**。

## 2. 滚动不丝滑的根因（三条，都在代码里可指认）

### 2.1 每帧全树重建（主因）

`onScaleUpdate` 与甩动 ticker 每帧 `setState` → 整个 `LayoutBuilder` 以下全部重建：
`GestureDetector → ClipRect → Transform → SizedBox → Stack → Positioned × N → PageLayer × N → PaperEffect`。
平板 120Hz 帧预算 8.3ms，这套 Dart 侧重建 + element diff 占 6–18%。
**注意：不是位图问题**——pdfrx 渲染不走 UI 线程（T0.4 实测 12ms/页），
每帧也没有请求新尺寸位图（`qualityWidth` 冻结机制第四版已立）。

### 2.2 滚动期间零预热

`_reportCurrentPage / _prefetchNeighbours` 只在**停手后**调用。持续拖动 / 甩动时，
新进入视口的页现渲染 + 现上传：dpr 2.5 下 fit-width 位图 3000×4243 ≈ 51MB，
200MB 缓存只装 3–4 页，不进缓存就现渲，每进一新页一次可见等待。

### 2.3 甩动太短

衰减常数 `0.0025^dt` → 时间常数 ≈166ms，甩一下就走一点点，手感发涩。

## 3. 丝滑三改（scroll_view.dart 第五版）

| 改动 | 做法 | 为什么这样做 |
|---|---|---|
| **矩阵独立成层** | `ValueNotifier<_Camera>` + `ValueListenableBuilder` 只包住 `Transform`；页面列表作为**静态 child** 传入，只在**可见集变化**时 `setState` 重建 | 每帧只改矩阵 → renderObject 标记重绘、element 树不动、引擎复用子图层只改变换；页面列表一个都不重建 |
| **滚动中按方向预热** | 每帧算可见集 + 主可见页（`ScrollMath` 纯函数，µs 级）；向"正在去的方向"预热**下一页**；停手 220ms 清晰度升级后按新宽度补一次 | 51MB/页只预热 1 页（当前 + 邻居 + 预热 ≈153MB < 200MB 上限）；反向现渲染 12ms 来得及 |
| **fling 调校** | 衰减 `0.12^dt`（时间常数 ≈470ms，接近原生滚动）；触发 60px/s、停止 50px/s、撞边即停 | 原来 166ms 太短；470ms 是"甩一下能过一两页"的量级 |

配套：
- `PageLayer` 加 `ValueKey(page.index)`：可见集平移时"离开的 dispose、进入的新建"。
  无 key 时按索引配对，会出现**两个 PageLayer 同时换页重载**的闪烁帧。
- 主可见页 / 页码上报改为每帧计算、**仅变化时**上报父级（原来只在停手后算，
  `_current` 陈旧导致预热 token 也陈旧）。
- 转屏重排后补一次页码上报（`_pendingReport`）：竖横屏互转每页高度全变，
  不上报的话页码条停在上一个方向。
- 每帧计算抽成 `domain/reader/scroll_math.dart`（纯 Dart，可单测）：
  `visibleRange`（带 early-break，300 页也只扫附近几页）/ `mainVisiblePage` /
  `clampOffset`。

**没做的**：分块渲染（>2× 清晰度，T1.5.1 未做项）；滚动模式降低 dpr 乘数省内存
（规格未授权降质，fit-width 1:1 像素是对的）。

## 4. 暗色夜读质感（T1.6 返工）

### 4.1 从"黑罩"升级为"duotone 夜读"

旧实现是 0.18 纯黑叠色：纸面 255→209（82% 亮度的中性灰），字仍纯黑。
问题不在对比度（实测 ~13.8:1 是够的），而在**夜间整屏亮度**——82% 亮度的纸在
暗色界面里"发光"，四周越黑它越刺眼。

新实现（`domain/reader/night_tint.dart`，纯函数 + 单测）把亮度轴翻转：

```text
白纸 → 暖黑纸 #191612（10% 亮度）     黑字 → 暖白墨 #E9E3D5
y = 0.2126r + 0.7152g + 0.0722b        out_c = ink_c + (paper_c - ink_c)·y
```

- 对比度 ~14.5:1（与旧罩持平，不降）；
- 页面亮度 82% → 10%，夜间环境真正暗下来；
- 暖黑纸 / 暖白墨是浅色模式"纸感暖色 / 墨色"的**镜像延续**——这是设计哲学
  「暗色下纸感让位给暗色遮罩」的升级解：遮罩从"一层灰"变成"一套夜读配色"；
- 走 `ColorFilter.matrix` 一次 GPU pass，与浅色乘法染纸同量级，切换零成本；
- **只作用背景层**，笔迹层（第 2 周）是兄弟节点，永不吃这个滤镜（REQ-15 红线）。

代价（记录在案）：彩色内容（红印章、彩色插图）退化为双色暖调，像旧照片。
夜读可接受；真要保彩色只能回到"只压亮度"的罩，那是另一个取舍，留给以后。

### 4.2 app 骨架：冷灰阶梯 + 发丝线

seed 蓝派生的暗色偏紫灰，与"暖纸"不搭。暗色 `ColorScheme` 改为**手调覆盖**
（值在 `tokens.dart` 的 `ShqDark`）：

- 表面六级阶梯（surface / ContainerLowest…Highest）只靠亮度差分层，全低饱和冷灰；
- 发丝线 `outline #5D6B76` / `outlineVariant #35424B`（暗底下线要比浅色亮才可见）；
- 主色提亮 `#8CB8F4` + 深蓝 on 色；错误色按 M3 暗色规范换淡红；
- **卡片暗色取消投影**（`CardThemeData elevation 0` + 表面色分层）——阴影在暗底显脏；
- AppBar 暗色滚动时用 2dp 色高差分层（`surfaceTint` 关掉，不用紫色罩）。

浅色**一行未动**（seed 派生已真机验证过）。

### 4.3 页面级细节

| 细节 | 浅色 | 暗色 |
|---|---|---|
| 页面投影 | 黑 0.18 / blur 6（`ShqPaper.lightPageShadow`） | 暖黑 0.35 / blur 10（`ShqNight.pageShadow`） |
| 页面边缘 | 无 | 1px 白 6% 发丝边（`ShqNight.pageEdge`）——暗色下页面与背景只差亮度，没这道边"纸"不显形 |
| 缩略图抽屉 | 原图 | 自动吃 duotone（PageLayer 默认 original → PaperEffect 暗色分支），**夜读一致性** |
| 显示浮层文案 | — | 「深色模式下纸感让位给夜读配色：暖黑纸 + 暖白墨，长时间读更省眼」 |

设计语言一句话：**冷灰的桌面，暖黑的纸，暖白的字**。界面退后，纸浮上来。

## 7. 待你手指复验（3 步）

1. **滚动手感**：滚动模式单指长拖 + 用力甩动 → 跟手不卡；甩动能过 1–2 页；
   穿页时底部页码实时变；停手约 220ms 后画面"变清晰一次"（设计如此）；
   甩到卷首/卷尾干脆停住，不露背景。
2. **暗色夜读**：系统切深色 → 书架/AppBar/抽屉变冷灰；PDF 页变"暖黑纸 + 暖白字"；
   缩略图同步夜读；点显示浮层看深色说明文案；**翻页/缩放不卡**（滤镜是 GPU 一次 pass）。
3. **浅色回归**：纸感五预设 + 强度滑条照旧；分页模式左右按钮翻页/页内缩放照旧；
   「原图」一键可回。

## 8. 有意偏离规格的地方（记录在案）

| 偏离 | 理由 |
|---|---|
| 深色从"暗色遮罩"改为 duotone 夜读 | 用户明确要求"暗色质感设计"；遮罩方案页面 82% 亮度在夜间发光，duotone 把页面压到 10% 且延续暖色基因；对比度不降（13.8→14.5） |
| 删除 `ShqPaper.darkScrimAlpha` | 被 NightTint 取代；留着会让后人误以为还有一层罩 |
| 暗色 Card 取消投影 | 暗底阴影显脏，表面色分层才是 M3 暗色的正确表达 |
| `PageLayer` 白底/阴影颜色字面量改 token | 原代码违反 §10「widget 不写颜色字面量」，顺手修正 |
