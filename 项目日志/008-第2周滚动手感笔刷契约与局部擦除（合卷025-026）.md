> 本卷为历史合卷（截至当日）。后续变更与最终结论以编号更大的日志（027–031）为准；被推翻的旧结论已在正文标注。

> 合并自 025（滚动跟手 + 笔刷配色/粗细 + 荧光笔 + 三个真 bug，08:55–09:40）与 026（橡皮改局部擦除 + 三档大小 + 补验，12:45–13:15）。结论：`flutter analyze` 0 问题、测试 121 → **128 全绿**；滚动最差帧 **30.7ms → 5.0ms**；局部擦除缺口宽度做到像素级可验证。

## 1. 滚动跟手性：先量化，再改四处

### 1.1 量化（先有 HUD，才有资格谈优化）

新增 `ui/reader/debug_hud.dart`：`SchedulerBinding.addTimingsCallback` 采集最近 60 帧的 **build / raster 中位耗时、超 60Hz 预算占比、最差帧**，同时显示当前页笔画/点数、位图缓存占用与页数。设置页「开发」分组可开关，`kReleaseMode` 下连入口都没有。

改动前实测（OPPO OPD2601 / profile / 100% / 4 页卷）：

| 场景 | raster 中位 | 超预算帧 | 最差帧 | 位图缓存 |
|---|---|---|---|---|
| 打开后第一次滑动 | 4.5ms | 2% | **30.7ms** | **146MB / 3 页** |
| 写过 8 笔后再滑 | 2.5ms | 0% | 4.6ms | **194MB / 4 页**（≈200MB 上限） |

结论：帧率中位数本身不差，**顿挫来自“边滑边淘汰纹理”**——一页 A4 在 3000px 宽下 51MB，4 页就顶到 200MB 上限，于是每进一页都要 dispose 旧纹理 + 上传新纹理；再加上“打开文档到第一次滑动之间完全没有预热”。

### 1.2 四处改动（100% 不跟手的完整解法）

| 改动 | 为什么 |
|---|---|
| `PageImageCache` 上限 200MB → **320MB** | 工作集（视口 2 页 + 预热 1 页 + 刚离开 1 页）正好 204MB，卡在上限上就是**每次都 churn** |
| 新增 `deferEviction`：手势/甩动期间**暂停淘汰**，停手后一帧 `trim()` | 滑动中淘汰 = 每页重新渲染 + 重新上传 51MB 纹理，这正是 30.7ms 的来源 |
| `build()` 里也预热下一页 | 打开卷后用户还没碰屏幕时就把下一页烘好 |
| 笔优先门槛 **800ms → 200ms** + 新增 `_penDown` | 原规则“笔最近 800ms 出现过就冻结单指滑动”的实际副作用是：**写完抬笔后 0.8 秒内滑页面毫无反应**。现在笔压着屏幕时一律冻结，笔抬起 200ms 后立刻可滑；且手势“从手掌开始”的那一整段仍然冻结、不甩动 |

另给墨迹层补 `RepaintBoundary`（页面级 + 已提交/活动双层各一层）：相机矩阵每帧变化时 `RenderTransform` 会把整棵非边界子树重新 paint，**写满一页的页签在滚动时每帧都会重画所有笔画**（`getBounds()` 也要重算）。这条同时是 2.3 的诱因。

## 2. 三个真 bug（排查中掉出来的，价值比功能大）

### 2.1 水平 / 竖直笔画整笔不画

- **现象**：横着画一条线毫无反应，斜着才行；下划线、表格线全中招。T2.2 起就存在。
- **根因**：`InkRibbon.draw()` 用 `path.getBounds().isEmpty` 判断“这一档有没有内容”。**完美水平线**的包围盒高度为 0 → `Rect.isEmpty == true` → 整笔被跳过。
- **修法**：每档一个 `_levelUsed` 布尔，替代几何判空，顺带省掉每帧对 24 条 Path 调 `getBounds()` 的 O(点数) 开销。回归测试：三种笔刷各画一条水平线，必须至少有一个档位被使用。

### 2.2 荧光笔落笔先黑、抬笔才变荧光

- **现象**：慢速画荧光笔，笔尖出来的是黑线，抬笔瞬间才变半透明黄。
- **根因**：**两层各自拼一半参数**——已提交层知道荧光笔要 `multiply` + 荧光色，活动层只传了 `style` 和**墨色**，`blendMode` 用默认 `srcOver`。
- **修法**：只留一条构造路径——新增 `InkBrushSpec`（样式 + 颜色 + 粗细 + 混合模式，一次算完），活动层与已提交层都从它取。
- **验证**：真机慢速画，中途抓帧与抬笔后抓帧的像素颜色**完全一致 (245,230,174)**。

### 2.3 荧光笔在合成层里一个像素都画不出来

- **现象**：加了 `RepaintBoundary` 后荧光笔整笔消失；日志显示 360 个点已提交、已绘制，像素扫描 **0 个黄色像素**。
- **根因**：`multiply` / `screen` 这类**依赖目标像素**的混合模式，在“透明背景的合成层”里算不出可见结果。
- **修法**：荧光笔改为**半透明 + srcOver**——视觉上是一道透光色带，下方文字仍清楚（REQ-03 要的是“文字可读”，不是“必须乘算”），且与合成层无关。夜读纸实测：黄条清晰、纸下文字可读。

### 2.4 附带：重构时漏了 `paint.color`

- **现象**：调色板选红色，画出来全是黑。
- **根因**：`InkRibbon._paintFor` 重写后忘了 `..color = spec.color`，`Paint` 默认不透明纯黑；像素扫描确认笔画是 `(0,0,0)`。
- **修法**：单测直接断言 `Paint` 上的颜色/混合——**几何断言永远抓不到这类问题**。

## 3. 笔刷颜色 / 粗细契约与迁移

### 3.1 契约（必须在 T2.4 落盘前定版）

| 项 | 决定 |
|---|---|
| 颜色 | 语义 6 色（墨黑/蓝/红/绿/橙/紫）+ 荧光笔专用 4 色（黄/绿/粉/蓝） |
| 暗纸 | 每个索引都有“夜读版”（同色相提亮），切到夜读时旧笔迹**自动变亮** |
| 粗细 | 当时每支笔 3 档：钢笔 0.8–2.4 / 1.2–3.2 / 1.8–4.4；圆珠笔 1.6 / 2.4 / 3.2；荧光笔 12 / 18 / 24 |
| 入库 | `InkStroke` 增 `colorIndex` + `widthLevel` → SIF v1 stroke 头变为 `style\|color\|width\|flags\|nPoints\|bbox\|t0`（每笔 +2 字节） |
| 每支笔记住自己的色/粗 | 切钢笔↔荧光笔不丢设置；落盘格式 `tool:color:width;…`（旧格式 `pen` 仍可读） |

> 顺序纪律：**SIF 一旦按旧格式写出去，以后加颜色就要写迁移**。所以颜色 + 粗细 + 局部擦除三件都在 T2.4 之前收口。

### 3.2 迁移

- `colorIndex` / `widthLevel` 用默认值 **0 / 1** 兜住老数据，**老数据不迁移**；
- `setting_keys.dart` 的 `ink.default_brush` 值格式升级为 `tool:color:width`，**旧值兼容**；
- 颜色索引是**契约，只能追加**，不允许插入/重排——否则历史笔迹集体变色。

### 3.3 工具条两形态（用户拍板，默认浮钮）

- **浮钮（默认）**：右下角 56dp 圆钮，常态只显示“当前笔图标 + 当前颜色小点”，点开向上展开工具/颜色/粗细三段，再点收起。
- **顶栏（设置可切）**：设置 →「书写」→ 固定到顶栏，变成 AppBar 下一条 52dp 工具带，三段并排、零展开。
- 撤销/重做搬进 AppBar：按“当前页”取 `canUndo/canRedo`，没得撤时是灰的。

## 4. 橡皮：从“删整笔”改成“把笔画切开”

### 4.1 行为契约

```text
原笔 ────────────────      一条长横（一笔，uid=H）
擦         ●●              橡皮（半径 12pt）划过中间
结果 ──────      ──────      变成两笔（uid 换新），缺口 = 橡皮直径
```

- 擦到哪删到哪；擦端头只剩一段；一划扫过整条则整笔消失；
- **碎片继承原笔的样式/颜色/粗细**，uid 换新；
- 单点笔画要么整体擦掉，要么不动；
- 一次拖动里的所有切分，抬笔时合成**一步撤销**。

### 4.2 算法（`domain/ink/eraser.dart` 完全重写）

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 橡皮路径 → 圆盘 | 按步长 `min(radius, 4pt)` 采样成一串圆盘 | 圆盘与线段的交集有**精确解**（二次方程） |
| 线段 ∩ 圆盘 | 解 `At² + Bt + C ≤ 0`，与 [0,1] 求交 | 精确，无采样误差（单测断言缺口 = 直径，误差 < 0.01pt） |
| 多圆盘区间 | 排序后合并成“被覆盖的 t 区间” | 一次可能被多个圆盘覆盖 |
| 切分 | 逐段走：区间外保留、区间内丢弃，断口用 `lerp` 生成插值点 | 碎片首尾正好贴着擦除边界 |
| 预筛 | `mayTouch()` 只比包围盒 | 一页 5000 笔，每个 move 都全量求交会直接卡死 |

### 4.3 命令层（`undo_stack.dart`）

```dart
typedef ErasePatch = ({int index, InkStroke original, List<InkStroke> fragments});
class EraseStrokes extends InkCommand   // 把 idx 处原笔替换成碎片（就地，保 z 序）
class EraseBatch extends InkCommand     // 一次拖动 = 多步替换，抬笔合成一条
```

- `apply`：**从后往前**替换，避免前面的下标被列表长度变化带偏；
- `revert`：先摘掉所有碎片 uid，再按原下标插回原笔（从大到小插）；
- `EraseBatch.revert` 按**相反顺序**还原（后发生的先撤），否则下标对不上。

### 4.4 绘制层缓存失效：新增 `epoch`

`CommittedInkCache` 原本是“只追加”的增量缓存，抬笔只 append 一笔。局部擦除会让**一笔变两笔**——长度可能刚好对得上，只比 `strokeCount` 会漏判，结果就是“数据改了、画面没改”。

修法：`InkEditState.epoch` 只在**非追加**改动（擦除 / 撤销 / 重做 / 清空 / 重载）时 +1；绘制层 `sync(doc, epoch)` 见 epoch 变化即整体重建。纯追加仍走增量。

> 排查坑：橡皮“没生效”和“生效了但绘制层没重建”在截图上**长得一样**，必须靠日志/像素测量区分。

### 4.5 三档大小（复用“粗细档”）

| 档 | 半径 | 适用 |
|---|---|---|
| 小 | 6pt | 抠单个字符/符号 |
| 中 | 12pt | 默认，规格值 |
| 大 | 22pt | 扫一片草稿 |

- **复用 `InkBrush.widthLevel` 当“大小档”**：不新增字段、不新增持久化键，且每支笔（含橡皮）本来就分别记忆设置；
- 工具面板里橡皮不再显示“颜色/粗细”，改成一排**空心圆** + 一句说明。

### 4.6 像素测量（不靠肉眼）

先在 y=900 画一条长横（`#14161A`，实测 21854 个像素），再逐项测：

| 操作 | 测量结果 |
|---|---|
| 中号橡皮，横划 100px（1400→1500） | 断成 `297→1344` 与 `1557→2504`，**缺口 213px ≈ 42pt** ✅ |
| 撤销 | 恢复成**单段 `297→2504`**，与擦之前完全一致 ✅ |
| 重做 | 缺口精确回到 `1344→1557`（确定性）✅ |
| 小号橡皮，点擦（700 附近） | 缺口 **63px ≈ 12pt** ✅ |
| 大号橡皮，点擦（2100 附近） | 缺口 **225px ≈ 44pt** ✅ |

三档缺口宽度肉眼可分辨（**63 / 213 / 225px**），且都没有误伤相邻笔画。

### 5.3 已知限制

| 限制 | 说明 |
|---|---|
| 荧光笔不再与下方墨迹“乘算” | 合成层里 `multiply` 不可用；现为半透明覆盖，视觉接近，文字可读 |
| 每支笔的颜色/粗细是**全局**的（不分卷） | 与原有笔刷语义一致；“每篇文档记住上次笔型”（T2.2 尾项）未做 |
| 换纸会重建整层笔迹缓存 | 一次性 O(笔画数)，用户手动动作，可接受 |
| 擦除按“折线”切分，不引入曲线拟合 | 断口是直线段，放大 400% 看是平的；做曲线会让碎片数暴涨 |
| 一次拖动擦很多次会产生较多碎片 | 正常一划通常只切 1–3 片 |
| 橡皮大小与“粗细”共用字段 | 语义不冲突（橡皮没有笔画宽度），读代码时要知道 |
| 杀进程仍丢笔迹 | **T2.4** 已补（见 031） |

### 5.4 设计纪律（两轮共同结论）

- **能点但没反应，就是假功能**。滚动“不跟手”的元凶不是帧率，而是“写完抬笔 0.8 秒内滑动毫无反应”；橡皮最吓人的故障不是没删掉，而是“数据改了、画面没改”。两者都必须靠**真实输入 + 像素/日志测量**验收。
- 一次只留一条构造路径（`InkBrushSpec`）、一处状态推进点（`epoch`）、一个阈值来源（`widthLevel`）：重复的那一半参数，迟早会拼错。
- 数据格式先定版，再落盘：颜色/粗细/局部擦除都在 SIF 之前收口，避免写迁移。
