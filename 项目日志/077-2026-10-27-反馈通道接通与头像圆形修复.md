## 2. 头像：圆框里的方形裁切边

### 2.1 现象

设置头像后，页首左下角的**圆形**头像框里能看到的不是"图铺满圆"，
而是"一个带圆角的方框"：上下左右四条**直边**落在圆里，左上角最明显
（深色页首底色下尤其明显）。用户把它描述成"还能看到矩形的裁切边界"。

### 2.2 根因（一句话：边框把图片向内挤了 2.5dp）

`profile_header.dart` 里头像原来写的是：

```dart
Container(
  width: 78, height: 78,
  decoration: BoxDecoration(shape: BoxShape.circle, border: Border.all(width: 2.5), ...),
  clipBehavior: Clip.antiAlias,
  child: Image.file(..., fit: BoxFit.cover),
)
```

`Container` 会把 `decoration.padding`（`BoxDecoration` 的 padding = 边框宽度）
加进**子节点内边距**：图片实际只有 `78 - 2×2.5 = 73` 见方；
而 `ClipPath` 用的裁剪圆仍是 **78** 直径（`BoxDecoration.getClipPath` 用整个 size）。

于是可见区域 = 73 方 ∩ 78 圆：
- 四条边的中点被**图片直边**截断（圆还没到，图没了）；
- 四个角被圆裁掉。

结果就是"圆角方框"，也就是用户看到的"矩形裁切边界"。
不是裁切算错了，是**显示层的内边距比裁剪圆小了 5dp**。

### 2.3 修法

1. **边框改画在图片上层**：`decoration` 只留形状/底色/阴影，
   `foregroundDecoration` 画 2.5 的圆环。`foregroundDecoration` 不参与布局、
   也不产生内边距，图片按 78×78 铺满，再被 78 的圆裁掉 —— 圆内 100% 是图。
2. **头像输出也改成圆形**（`image_crop_sheet.dart`）：确认时先 `clipPath(圆)`
   再 `drawImageRect`，输出 PNG 的圆外是**透明像素**。
   这样即使未来某个界面忘了 `ClipOval`，也不可能再露出方形边界；封面仍是直角矩形。
3. 顺带保留 072 的 `imageEpoch`（换 Key 强制重新解码）。

## 3. 反馈通道：从"只存本机"到真正送达

### 3.1 架构（先落盘，再发送，失败可重试）

```
用户点提交
  └─ FeedbackOutbox.submit()
       ├─ enqueue：vault/feedback/<id>.json + <id>-<i>.img   ← 先落盘（网络之前）
       └─ send：GitHubFeedbackGateway
            ├─ PUT /repos/{owner}/{repo}/contents/feedback/<id>/N.png（截图）
            └─ POST /repos/{owner}/{repo}/issues（正文 + 手机号 + 截图链接）
       ├─ 2xx → status=sent + issue 号
       └─ 失败 → status=failed + 原因（内容不丢，可重试）
```

- **`FeedbackOutbox`**（`app/feedback/feedback_outbox.dart`）：本机草稿箱 + 发送队列。
  列表按时间倒序；`retryPending()` 从旧到新补发，遇到网络类失败就停（不挨个撞）。
- **`GitHubFeedbackGateway`**（`app/feedback/github_feedback_gateway.dart`）：
  - 截图落到私有仓库 `feedback/<提交id>/`，重试复用同一个 id；
  - 重复上传返回 **422 视为"已存在"**（幂等）；
  - **只有拿到 2xx 才算 `delivered`**；
  - 不读、不列、不删仓库里的任何东西。
- **配置**：`--dart-define=FEEDBACK_GH_TOKEN=...`（owner/repo/branch 有默认值，
  仓库固定为 `Terryliu001/SHUA_QI_feedback`）。老的
  `FEEDBACK_ENDPOINT`（Cloudflare Worker）路径保留，优先级低于 GitHub。
- **界面**：`用户反馈` 页在提交后显示"已提交给开发者（#N）"或"没发出去 + 原因"，
  下面新增「我提过的反馈」：状态胶囊（待发送 / 已送达 / 发送失败）、时间、摘要、
  远端 issue 号、失败原因、复制 / 重试 / 删除；有积压时显示「全部重试」。
- **自动补发**：`ui/app.dart` 在**启动一帧后**与**回到前台**时各补发一次（5 分钟节流），
  不依赖用户停在反馈页。
- **设备信息**：`MainActivity` 新增 `deviceInfo` 方法通道，只回
  `厂商 + 型号 / Android 版本 / API 级别`（不取 IMEI / 序列号 / 广告 id / 账号）。
- **兼容**：2026-10-26 那版旧草稿（没有 `status` / `attempts` 字段）能读，
  按 `pending + 0 次` 处理，升级后可自动补发 —— 见 §3.3 的 #2。

### 3.4 安全边界（必须记住）

- token 由 `--dart-define` **编译进 APK**，这是用户拍板的方案 A 的代价；
  因此 token **只给**这一个私有仓库的 `Issues: RW` + `Contents: RW`，**不用账号主 token**。
  泄露最坏情况 = 别人往这个私有仓库灌 issue；GitHub 上吊销重发即可。
- token **不进 git**：本地放在 `_verify/.gh_app_token`（`.gitignore` 已含 `_verify/`），
  构建脚本 `tool/build_release.ps1` 读它、且**不打印**。
- 手机号只进私有 issue；仓库是 private，公开页面 / 公开仓库都看不到。
- Worker 通道还留着：以后想"App 里完全不存凭证"，照 `server/feedback-worker/README.md`
  部署后换成 `--dart-define=FEEDBACK_ENDPOINT=...` 即可，客户端不用改。

## 5. 不要改坏的约定

### 头像

- **边框必须走 `foregroundDecoration`**。`decoration` 里写 `border` 会变成
  `Container` 的内边距，把图片挤成 73×73 —— 就是这次的 bug 本身。
- 图片必须铺满 78×78 再由圆裁；不要在圆与图之间再插 padding。
- 头像输出是**圆形 alpha**（圆外透明）；封面仍是矩形。
- 裁剪窗的 `OverflowBox + ClipRect + contain`（073）不要改回去。

### 反馈

- **先落盘再发送**：任何失败都不能丢用户写的东西。
- `sent` 只由远端明确回执产生，禁止"提交即成功"。
- 重试**复用同一个提交 id**，否则每重试一次就在仓库里留一批孤儿图。
- 图片重复上传的 422 是"已存在"，不是错误。
- 自动补发有 5 分钟节流；别改成"每次 build 都发"。
- 设备信息只取型号 / Android / API，不取任何设备标识符。
- 老草稿的 JSON 字段名不要改（`images` 是相对路径数组）。

## 6. 遗留 / 风险

1. **token 在 APK 里可被提取**（方案 A 的已知代价）：只影响私有反馈仓库；
   轮换方式：GitHub 上新 token → 替换 `_verify/.gh_app_token` → 重新构建发布。
2. **没有回复通知**：开发者回了 issue，App 不会推送；用户得自己看（已写进版本说明的限制）。
3. **临时仓库待删**：端到端测试时建过一个公开临时仓库
   `Terryliu001/shuaqi-feedback-e2e-tmp`，现有 token 没有 `Administration: write` 删不掉，
   需要维护者手动删（或给 token 加权限）。
4. **设备上的测试数据**：页首还是测试头像（品红/截图），「我提过的反馈」里有 #2 / #3；
   发布前可「移除头像」+ 删除列表项。
5. 未做：失败退避（现在只有 5 分钟节流）、issue 回复通知、上传前压缩大图（>6MB 直接拦）。
6. 300 页压力 / 20 页导出实测仍按 `071`/`074` 的口径没做，不要对外声称已验。
