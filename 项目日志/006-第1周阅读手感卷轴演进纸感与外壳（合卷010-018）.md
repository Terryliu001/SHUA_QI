## 1. 阅读器手感第一轮（预渲染 / 缩放策略）

### 1.1 翻页顿挫：目标页“翻到了才开始画”

| 项 | 内容 |
|---|---|
| 现象 | 连续翻页每页顿一下，用户原话「翻页和放大不够丝滑」 |
| 根因 | 目标页直到翻到眼前才 `render`（3–12ms），并解码、首帧 `setState`，这段全在翻页动画里 |
| 修法 | `PageImageCache.prefetch()`：翻当前页时预热 `-1 / +1 / +2` 三页；滚动侧给 `scrollCacheExtent`（视口 0.8 倍）让下一屏提前构建 |
| 验证 | 真机（OPPO OPD2601 / 4 页真实试卷）连续翻页无顿挫 |

### 1.2 缩放卡顿：手势过程中反复重新渲染

- **根因**：`TransformationController` 的监听里每换一个倍率档就 `setState` 换图，缩放期间 CPU 全被渲染抢走。
- **修法**：手势期与结束期分开——手势中只在“是否已放大”翻转时 `setState`（只为切 `PageView` 的 physics，代价极小）；`onInteractionEnd` 才决定是否换更高分辨率的图。
- **附带**：`filterQuality` 从 `medium` 降到 `low`（缩放瞬间不需要精致，松手后反正换清晰图）。

### 1.3 翻页后第一次放大不跟手：控制器被重新挂载

| 项 | 内容 |
|---|---|
| 现象 | 「有放大操作之后翻页逻辑有问题了，翻页之后我直接放大操作就不能立马跟手」——要再捏一次才生效 |
| 根因 | 之前只给“当前页”挂同一个控制器：`transformationController: index == _current ? _zoom : null`。翻页瞬间 `_current` 变，控制器从旧页摘下来挂到新页，这个重新挂载会**打断正在进行的捏合手势**。`onPageChanged` 里还调 `_zoom.value = identity()`，在翻页动画中触发重建，本身也是卡顿源 |
| 修法 | **每页各自持有一个 `TransformationController`，永不重新挂载**：`_controllers.putIfAbsent(index, …)`；监听器按 index 判断是否当前页；翻页时不重置任何页的缩放；`_zoomed / _renderScale` 从新页控制器读取 |
| 验证 | 在放大状态下点击边缘翻页到 2/4，**翻页后立刻双击 → 立刻 2 倍** |

### 1.4 分页模式的最终分工：按钮翻页

| 之前 | 之后 |
|---|---|
| 左右边缘 15% 区域点击翻页 | 删除 |
| `PageView` 滑动翻页 | `NeverScrollableScrollPhysics` **恒禁用** |
| 页面同时承担“翻页手势 + 缩放手势” | 页面**只负责缩放**（捏合 / 双击 / 放大后平移） |
| 翻页入口 | 左右两个半透明圆形按钮（垂直居中，首末页置灰） |

**为什么更稳**：放大后 `PageView` 的 physics 需要在“滑动”与“禁用”之间切换，而切换瞬间会打断进行中的手势。改成按钮后，页面区域完全不再处理翻页，手势竞技场里只剩缩放手势。顺带修了一个隐藏 bug：`panEnabled` 之前使用 build 时的局部变量，缩放后不重建，导致放大后无法平移；改用随缩放重建的 `_zoomed`。

其它定案：双击在 fit-width ↔ 2× 之间切换；`minScale` 0.5 → 1.0；缩放后 `didUpdateWidget` 重新对齐当前页。

| 第一轮验证（真机） | 结果 |
|---|---|
| 双击放大/缩回 | ✅ 2 倍、公式清晰可读，页码仍 2/4；缩回 fit |
| 按钮翻页（放大状态下） | ✅ 翻到 3/4，新页是 1x 清晰态 |
| 页面横向滑动 | ✅ 不再翻页，仍停在 2/4（刻意） |
| 放大后单指平移 | ✅ 内容跟随拖动 |
| 双指捏合的跟手度 | ⏳ adb 无法注入多指，必须手验 |

## 2. 滚动卷轴五代演进（重点）

### 2.0 版本总表

| 版 | 布局模型 | 缩放入口 | 解决 | 引入 | 结局 |
|---|---|---|---|---|---|
| **v1**（010） | 外层横向 `SingleChildScrollView` + 内层纵向 `ListView` | 档位 100/125/150/200% | 两个轴向各管各的手势，滚动模式终于能放大 | 不是“哪里放大就放大哪里”，换倍率要重排 | 档位控件保留；缩放模型被 v2 推翻 |
| **v2**（011–012） | `ListView` + 每帧改页宽后重排 | 双指捏合（`Listener` 数指针）+ `Transform.scale` 预览、松手提交 | 双指可用，单指滚动仍归列表 | 预览是假放大；布局宽跟手 → 每帧一张新位图 | **整版推翻**（012 自认设计错误） |
| **v3**（013–014） | 内容排一次版固定，屏幕位置 = `Matrix4(translate × scale)` | 焦点缩放公式 | 错位叠压、慢半拍、位图风暴 | 裁剪盒尺寸 = 内容宽 → 切边/黑边 | “布局与变换分离”保留；裁剪被 v4 推翻 |
| **v4**（015） | 同 v3，但外层 `SizedBox` = 视口，1 倍 = fit-width | 同上 + 档位制清晰度 | 右侧被裁、放大黑边 | 每帧 `setState` 重建整棵树 → 不丝滑 | 三条硬规则保留；重建被 v5 推翻 |
| **v5**（017） | 矩阵独立成层，页面列表作静态 child | 同上 | 每帧全树重建、零预热、甩动太短 | 视口紧约束压扁内容（命中区）→ CameraViewport 收口 | 现行 |

> 编号说明：013 与 014 是同一版的两个部分（013 定“画布”模型，014 修“每帧改布局”的实现错误），版本号以 014/015/017 的自述为准。

### 2.1 v1：嵌套滚动 + 档位放大（010）

- **为什么不能直接做**：不能用 `InteractiveViewer` 包整个列表——它的 `ScaleGestureRecognizer` 把单指纵向拖动也当作缩放手势的平移分支，双指缩放与竖向滚动互相打断，画面抖。
- **做法**：横向滚动放外层（`SizedBox(width: 页宽 × zoom)`），纵向列表放内层；`zoom == 1` 时不套外层。
- **验证**：真机切滚动出现「100%」控件；200% 页面变宽、文字放大、底部出现横向滚动条；纵/横滚互不干扰。
- **代价（当场记录）**：滚动模式的放大是**档位**，不是捏合。捏合与纵向滚动在 Flutter 里没有不打架的实现方式。→ 这个“架构上做不了”的判断，本轮之内就被 v2 推翻了。

### 2.2 v2：数指针 + 预览提交（011–012）

**解决手势竞技场冲突**：不用 `InteractiveViewer`（`panEnabled: false` 也不行——它的识别器仍然占用位置），改用 `Listener` 收原始指针事件：

| 指针数 | 行为 |
|---|---|
| 1 | 什么都不做，完全交给 `ListView` |
| ≥2 | 自己算两指距离 → `Transform.scale` 实时预览（纯 GPU，零布局成本） |
| 全部离开 | 把预览倍率**提交**成新页宽并重新布局 |

两指期间 `physics` 临时换 `NeverScrollableScrollPhysics`。位图侧引入**冻结**：`PageLayer` 新增 `qualityWidth`，布局 `width` 与位图 `qualityWidth` 解耦，缩放中 `_qualityZoom` 冻结、停手 250ms 才跟上。锚点补偿：记录焦点所在页索引 + 页内比例，重排后把滚动位置修正为 `新页顶 + 比例 × 新页高 − 焦点屏幕Y`。

**为什么整版被推翻**（012 的三处根因）：

1. **预览不真实**：`Transform` 只拉伸已渲染位图，放大越多越糊；松手重排后“从糊突然变清晰 + 位置跳一下”。
2. **位图风暴**：让布局宽跟着手指走，则每一帧页宽都不同 → 每帧向缓存请求一张全新宽度的位图。一次捏合约 60 帧 ≈ 60 张 12–50MB 位图。
3. **慢半拍**：`setState` → 重排 → post-frame `jumpTo` 校正，视觉总比手指晚一帧以上。

### 2.3 v3：可缩放画布 + 固定布局（013–014）

**更换模型**：内容排一次版就固定不动，屏幕位置由仿射变换算出：`屏幕坐标 = 内容坐标 × scale + offset`。`scale / offset` 是唯一状态；单指只改 `offset`；双指同时改两者；只渲染与视口相交的页面。

**焦点缩放**：

```dart
focalContent = (focalScreen - offset) / scale;      // 手势开始
scale'  = clamp(startScale * gestureScale, 1, 4);
offset' = focalScreen - focalContent * scale';      // 每一步反解
```

**第一版实现仍然错误**：`onScaleUpdate` 里改每个 `Positioned` 的 `top / height`——等于每帧重排一次。缩小时浮点尺寸逐帧累积误差、间隙被反复四舍五入，**页与页边界错开、互相叠压**。只要“缩放 = 改布局”，这个误差就必然存在。

**固定布局（014）**：内容坐标系永不改变，屏幕坐标系是唯一可变项（矩阵 = `translate(offset) × scale`）：`ClipRect > Transform(alignment: topLeft) > SizedBox(baseWidth, contentH) > Stack(页们)`。三个保证：页的相对位置终身不变；只有矩阵参数变；`PageLayer.width` 恒定。AppBar 百分比与画面不同步 → 菜单只调 `setScale()`，标签由 `onZoomChanged` 回调更新，**单一数据源**。位图宽度上限 4096px。

> **已经推翻的结论**：014 侧记“第 2 页右侧文字被切是原卷 PDF 排版溢出页框”——**错**。015 用分页模式同页截图证明该判断错误：这是滚动侧的裁剪 bug。

### 2.4 v4：裁剪边界钉在视口（015）

**现象**：① 滚动模式显示不完整，页面右侧内容被切；② 双指缩放后出现黑边框。

**根因**：v3 的链路 `ClipRect → Transform → SizedBox(内容宽)` 里，`ClipRect` 与 `Transform` 的尺寸都只有“内容宽”；外层 `Column` 又按默认 `crossAxisAlignment.center` 居中一次。于是布局盒宽 880、`_clampOffset` 又把它右移了 160，纸面从 320 开始，而裁剪盒本身只到 1040。

**截图像素量测**：

| 项 | 修复前 | 修复后 |
|---|---|---|
| 纸面横向范围 | x 800..2598（320.0..1039.2 逻辑） | x 0..2998（0..1199.2 逻辑） |
| 左/右边距 | 320 / 161（**不对称**，右侧硬切） | 0 / 0（铺满） |
| 页面内容 | 每行右侧 160pt 被裁 | 完整 |

**三条硬规则**：① **自身撑满视口**；② **1 倍 = fit-width**；③ **缩放只改矩阵不改布局**。

| 配套修正 | 原因 |
|---|---|
| `reader_page` 的 Column 加 `crossAxisAlignment.stretch` | 双保险：不允许阅读视图被“按自身宽度居中” |
| 重排时保留“当前页 + 页内比例” | 转屏/换窗不跳页 |
| 主可见页改为“重叠高度最大” | 原 `offset / 页高` 在 A4/A3 混排时会错 |
| 位图清晰度改**档位制** | 捏合中冻结、停手 220ms 升一档 |
| 预热只做下一页 | 整页 3000×4243 ≈ 51MB，预热两页会挤爆 200MB 缓存 |

**真机验证**：滚动 100% 纸面 x 0..2998 铺满、文字完整、页码 2/4；200% 整屏纸面无黑边、可拖动；200% → 100% 往返与进入前逐像素一致；竖屏旋转自动重排、铺满、仍停第 3 页。

**焦点缩放的定量验证**：A(100%) 中 (1060,1264) 的纹理块，按焦点缩放预测应在 B(200%) 的 (620,1404)；实测最佳匹配偏移 **(1,−1)px = (0.4,−0.4) 逻辑像素**，平均像素差 **7.1**（对照组故意错位 40px 处为 **67.6**，相差 10 倍）。

### 2.5 v5：矩阵分层 + 滚动预热 + fling（017）

| # | 根因 | 证据 |
|---|---|---|
| 1 | **每帧全树重建（主因）**：`onScaleUpdate` 与甩动 ticker 每帧 `setState` | 平板 120Hz 帧预算 8.3ms，Dart 侧重建 + element diff 占 **6–18%**。**不是位图问题** |
| 2 | **滚动期间零预热** | 拖/甩时新进视口的页现渲现传：dpr 2.5 下 51MB/页，200MB 缓存只装 3–4 页 |
| 3 | **甩动太短**：衰减 `0.0025^dt`，时间常数 ≈166ms | 甩一下只走一点点 |

| 改动 | 做法 |
|---|---|
| **矩阵独立成层** | `ValueNotifier<Camera>` + `ValueListenableBuilder` 只包住 `Transform`；页面列表作为**静态 child**，只在**可见集变化**时 `setState` |
| **滚动中按方向预热** | 每帧算可见集 + 主可见页（`ScrollMath` 纯函数，µs 级）；向“正在去的方向”预热**下一页**；停手 220ms 清晰度升级后按新宽度补一次 |
| **fling 调校** | 衰减 `0.12^dt`（时间常数 ≈**470ms**）；触发 60px/s、停止 50px/s、撞边即停 |

配套：`PageLayer` 加 `ValueKey(page.index)`；主可见页/页码上报每帧计算、**仅变化时**上报；转屏重排后补一次上报（`_pendingReport`）；每帧计算抽成 `domain/reader/scroll_math.dart`（`visibleRange` 带 early-break / `mainVisiblePage` / `clampOffset`）。

### 2.6 v5 收口：CameraViewport 与 RepaintBoundary

**CameraViewport（视口紧约束压扁内容 → 命中区）**。v4 为了“裁剪边界 = 视口边界”给外层加了 `SizedBox(视口)`，这给下面的是**紧约束**，沿代理链一路传下去，`BoxConstraints.enforce` 把内容盒压回视口高：内容要 848×12000，实际拿到 848×1050。绘制看不出问题，但 `RenderBox.hitTest` 第一步是 `size.contains(position)`，内容坐标 y > 1050 的落笔全被丢弃——表现为“滚动模式只能写第一页上半屏，后面的页看得到、写不上”。宿主机 widget 测试量过：内容盒 5000 被压成 600，远处落笔**命中 0 次**。
修法固化为 `CameraViewport`：`SizedBox(视口) > ClipRect > Stack(clipBehavior: none) > Positioned(left/top，**不给 width/height**) > Transform > 内容`。回归测试 `test/camera_viewport_test.dart`。

**RepaintBoundary**：相机矩阵每帧在变，但 `RenderTransform` 只有子树 `needsCompositing` 时才推真正的合成层；否则那一层的整页位图 + 噪点会被逐帧重新光栅化（2 页 A4 ≈ **12.8MP/帧**），120Hz 必掉帧。给背景层套 `RepaintBoundary` 后，平移只是合成器搬贴图；同时把“墨迹层每帧重绘”与“PDF 位图”隔开。

## 3. 纸感与暗色夜读

### 3.1 乘法染纸，而不是半透明叠色

规格 §6.9.3 写“叠色 + `ColorFilter.matrix`”，实现改为**乘法**（对角增益）：

```text
叠色：out = src×(1-α) + paper×α   → 黑字也被纸色罩灰，对比度下降
乘法：out = src × gain(paper)      → 白→纸色、黑→黑，文字保持墨色
gain_c = 1 - (1 - paper_c/255) × t     t = intensity/100
```

`t=0` 恒等（原图），`t=1` 白底完全变纸色；默认 55 时白底约 (250,246,239)。实测暖白 55% 页面白底采样 (240,236,230)，R>B 差 10，与公式一致；**文字仍是墨黑**。

滤镜是 GPU 合成，没有 CPU 逐像素计算、没有 PNG 编码：切换样式天然 ≤1 帧（规格 ≤100ms，实测无感），**且不需要**按 `(page,style,intensity)` 建位图缓存（缓存反而更慢更耗内存），“≤8ms/页”以 0ms 达成。`PaperRenderer` 契约保持不动，留给 T7 导出/缩略图。

### 3.2 纸感三态与深色互斥

| 态 | 触发 | 渲染 | 备注 |
|---|---|---|---|
| 原图 | 默认 | 零处理路径（中性白 248,248,248） | 首开见原卷更可信；偏离规格的 warm 默认，理由记录在案 |
| 染纸 | 浅色 + 五预设色块 + 强度滑条 | 乘法增益 + 3% 噪点平铺 | 强度滑条在 original 时置灰不可拖 |
| 夜读 | 深色（当时规则，023 改为纸样式独立） | 强制 `original`，走 duotone | 016 时是 0.18 暗色遮罩，017 升级 |

深色下浮层整块置灰并给一句说明——**能点但没反应是假功能，置灰 + 一句话才是真交互**。

### 3.3 T1.6 红线：纸感只作用背景

`PageLayer` 的结构是 `RepaintBoundary(边框/投影) > PaperEffect(Container(白底 + 位图))`。**第 2 周墨迹层必须作为 `PaperEffect` 的兄弟节点**（在它上面），绝不能放进它内部，否则笔迹会被纸感滤镜/夜读 duotone 染色（REQ-15 红线）。同理，页面投影与发丝边留在滤镜**外层**——它们在滤镜里会被 duotone 一起反色（黑投影 → 暖白发光）。

### 3.4 暗色夜读：从“黑罩”升级为 duotone

旧实现是 0.18 纯黑叠色：纸面 255→209，字仍纯黑。问题不在对比度，而在**夜间整屏亮度**——82% 的纸在暗色界面里“发光”。

新实现 `domain/reader/night_tint.dart`（纯函数 + 单测）把亮度轴翻转：

```text
白纸 → 暖黑纸 #191612（10% 亮度）    黑字 → 暖白墨 #E9E3D5
y = 0.2126r + 0.7152g + 0.0722b      out_c = ink_c + (paper_c - ink_c)·y
```

对比度 ~**14.5:1**，页面亮度 **82% → 10%**；暖黑纸/暖白墨是浅色“纸感暖色 / 墨色”的镜像延续。仍是 `ColorFilter.matrix` 一次 GPU pass，**只作用背景层**。
代价：彩色内容退化为双色暖调，像旧照片。夜读可接受；要保彩色只能回到“只压亮度”的罩。

### 3.5 暗色骨架与页面细节

seed 蓝派生的暗色偏紫灰，与“暖纸”不搭 → 暗色 `ColorScheme` 改为**手调覆盖**（`ShqDark`）：表面六级阶梯只靠亮度差分层、全低饱和冷灰；发丝线 `outline #5D6B76` / `outlineVariant #35424B`；主色提亮 `#8CB8F4` + 深蓝 on 色；错误色按 M3 换淡红；**卡片取消投影**；AppBar 滚动时用 2dp 色高差。浅色一行未动。

| 细节 | 浅色 | 暗色 |
|---|---|---|
| 页面投影 | 黑 0.18 / blur 6 | 暖黑 0.35 / blur 10 |
| 页面边缘 | 无 | 1px 白 6% 发丝边 |
| 缩略图抽屉 | 原图 | 自动吃 duotone |

设计语言一句话：**冷灰的桌面，暖黑的纸，暖白的字**。

## 4. 外壳 / 书架 / 设置页（018）

### 4.1 四 tab + 自适应导航

| 决策 | 理由 |
|---|---|
| 四个主 tab：书架 / 记录 / 错题本 / 设置 | P0 的四个常驻面。**阅读器不进 tab**——全屏 push 路由，刷题是主流程 |
| 宽屏（≥600 逻辑宽）`NavigationRail`，窄屏底部 `NavigationBar` | 主战场平板；600 阈值下平板任何方向都走 rail，手机走 bar |
| `IndexedStack` 保活 | 书架滚动位置、导入中状态，切去设置再回来不该丢 |
| 路由表顶层只剩一条（`AppRoutes.shell`） | tab 切换是外壳内部状态，不进路由栈——否则返回键会一级级退 tab |

### 4.2 书架四件套

| 项 | 做法 |
|---|---|
| 长按菜单 | 底部浮层（24 圆角 + 拖拽把手）：重命名 / 删除 / 导出。**导出置灰 + 锁形角标 + “规划在 T7”** |
| 重命名 | 对话框预填标题；空标题当作取消（库里 `title NOT NULL`） |
| 删除 | 确认框说清连带范围；**先删库后删目录**——残留目录由 `sweepOrphans` 收掉，反过来会留永远打不开的幽灵记录 |
| 搜索 | AppBar 标题位原位换 `TextField`；`filterByQuery` 纯函数（标题包含、忽略大小写、trim）；“有卷但无结果”单独空态 |
| 下拉刷新 | `RefreshIndicator` + `invalidate` 后等新 future 完成；`AlwaysScrollableScrollPhysics`（空结果态也要能拉） |
| 损坏态 | `workbookHealthProvider`（探测 `source.pdf`）：整卡 55% 不透明 + 缩略图红色“文件缺失”角标 + 点击提示“长按可删除后重新导入” |

### 4.3 设置页（T6.1 先行子集）

- **真实生效·主题**：跟随系统 / 浅色 / 深色 → 写 `app.theme_mode`，重启保持。
- **真实生效·阅读默认**：默认模式 + 默认纸感（五色块，填充按当前强度混合）+ 默认强度 → 写 `reader.default_*`。语义：**只影响之后新读取的卷**。
- **诚实置灰**：AI 配置（T6.1）、存储统计（T7.5）——置灰 + 锁形角标 + 一句规划位置。
- **关于**：名称 + tagline + 版本（`AppInfo` 与 pubspec 0.1.0 同步）。

偏好持久化本身在 016 落地：单卷键 `reader.view.<wbId>` 回落 `reader.default_*`，非法 JSON 回落默认不抛；**阅读模式也持久化**。

### 4.4 踩坑（对后人有用）

1. **Riverpod 3.4.3 已移除 `StateNotifier` / `StateNotifierProvider`** → 主题模式改 `Notifier` + `NotifierProvider`；依赖在 `build()` 里 `ref.watch` 取。
2. **`FutureProvider.family` 的声明类型是函数类型**（`FutureProvider<bool> Function(String)`），直写 `FutureProvider<bool>` 会 `invalid_assignment`。
3. **Dart 的 const 字符串插值合法**：全是 const 成员时整个 `Text` 可以是 const；本项目要求 analyze 零 issue，`prefer_const` 的 info 也必须逐个消。

### 5.2 真机结论（OPPO OPD2601 / Android 16）

- 分页：双击放大 2×、按钮翻页、放大后平移、翻页后立刻放大跟手——全 ✅；页面滑动不翻页（刻意）。
- 滚动：100% 铺满（x 0..2998）、200% 无黑边、往返逐像素一致、竖屏旋转不跳页、页间距 8dp、单指拖动跟手且页码同步——全 ✅。
- 纸感：五预设即时生效、滑条实时、杀进程重启仍在、深浅两模式都生效、深色遮罩下翻页缩放无掉帧——全 ✅。
- **始终缺一项**：双指捏合（adb 无法注入多指）。已用“同一条数学路径 + 像素比对”（误差 0.4 逻辑像素、平均差 7.1 对 67.6）证明公式与坐标系正确，剩下的只是输入分发，必须手指验。

### 5.3 遗留

| 项 | 说明 |
|---|---|
| >2× 分块渲染（T1.5.1） | 当前位图宽上限 4096px，4× 略软；分块可让 400% 全清晰，内存从“整页 51MB”降到“每块几 MB” |
| 缩略图抽屉分页加载 | 300 页卷不能一次性构建 |
| 分页放大后露白 | 可平移过头露出背景；若要“相册”手感改 `constrained: false + boundaryMargin`，未做 |
| 20+ 卷书架性能、300 页卷 fps/内存 | 缺样本与 DevTools |
| 记录/错题两 tab | 占位，等 T5.5 状态机后换会话列表 |
