## 1. 题面「点开后清晰一点」

### 1.1 现象与口径

056 的看题页把图放进 `maxHeight: 320` 的容器，且收藏时只按 1.6×pt 裁（上限 1024×1600）。
平板横屏逻辑宽 1200dp、物理 3000px，一张 1024px 的源图铺到 ~1470px 显示区必然发虚；
迁移来的老收藏**根本没有 `stem.png`**。用户原话：「查看收藏题目点开后清晰一点」。

### 1.2 三层做法

| 层 | 做法 | 落点 |
|---|---|---|
| 收藏时刻 | 题面图按 **2.8×pt、上限 1800×2600** 渲染（作答页内笔迹裁切 2.4×/1600×2400） | `reader_page._buildFavoriteCapture` + `answer_crop_renderer.renderAnswerCropPng(scale/maxWidth/maxHeight)` |
| 打开时 | 现有图 PNG 头宽 <1400 就从 `source.pdf` 重新裁一张，**写回同一个 `favorites/<id>/stem.png`**（路径/契约不变）；原卷已删或渲染失败静默跳过，继续用旧图 | 新增 `app/favorite/favorite_stem_service.dart`（app 层，不碰 Widget） |
| 查看时 | 图改为「内存字节 + `gaplessPlayback`」渲染，升级完直接换图；高度上限按屏幕 56%/42% 自适应；整块可点 → 全屏查看器（双指 5× 缩放、点一下关掉） | `ui/favorites/favorite_image.dart`（`FavoriteImage` / `FavoriteImageView` / `showFavoriteImage`） |

为什么按需升级要**覆盖原文件**而不是另存 hd：  
- 快照目录语义就是「这道题的当前题面」，多一份 `stem_hd.png` 会让"看哪一份"变成新规则；
- 覆盖写走 Vault 的原子写，不会出现半截 PNG；
- 升级只在打开时发生一次（宽 ≥1400 直接返回 null），对打开耗时无感。

### 1.3 证据（真机文件系统）

三份老收藏的 `stem.png` 在第一次打开看题页/二刷页后变大（`run-as ... ls -l files/vault/favorites`）：

| 收藏 | 升级前 | 升级后 |
|---|---|---|
| 四级第 1 题（迁移收藏，原先只有 8KB 低清图） | 8,256 B | **84,926 B**（15:44，打开看题页时） |
| 数学分析第 3 题 | — | **18,323 B**（15:35，组卷连刷打开时；宽扁公式图压缩率高） |
| 习概第 6 题 | ~? 1024 宽 | **172,906 B**（15:37，看题页触发；1800 宽文字图） |

## 2. 单题重刷（T8.3b）

### 2.1 数据契约（新增）

| 项 | 值 |
|---|---|
| 笔迹路径 | `favorites/<favoriteId>/ink/pN.sif`（第 0 张 `p0.sif`，备份 `p0.sif.bak`）→ `VaultPaths.favoriteInkSif/…Backup` |
| 存储实现 | 新增 `infra/ink/favorite_redo_ink_store.dart`（SIF v1，页尺寸 1000×600，isolate 编解码，`.bak` 回退） |
| provider 路由 | session 前缀 `fav:<favoriteId>`（`state/ink_providers.dart` 的 `favoriteRedoSessionId/parseFavoriteRedoSession`），画布 `InkPageKey(session, 0)` |
| 为什么按**收藏 id** 而不是按组卷 | 同一道题不论从「单题重刷」还是「组卷连刷」进来，写的是**同一份笔迹**：刷到一半换入口还能接着写；也让"重刷"成为这道收藏自己的状态 |

### 2.2 页面（`ui/favorites/favorite_redo_page.dart`）

- 单题与组卷共用一个页面：`RedoArgs{favoriteIds, title, setId?, initialIndex}`；
- 结构：AppBar（题名 + `第 i / N 题` + 题目列表/回看出处/清空）→ 52dp 工具带（钢笔/圆珠笔/荧光笔/橡皮、6/4 色、粗细 0–100、撤销/重做）→ 可收起的题面卡（点图全屏）→ 横线答题纸（1000×600，InteractiveViewer 缩放/拖动切换）→ 底栏（上一题/进度/下一题，最后一题变「完成」）；
- 切题时**先 flush 当前笔迹**再换题（500ms 防抖还没到也不丢）；返回时 `PopScope` 再 flush 一次；
- 清空只清重刷笔迹，**不动收藏时的 `answer.png` 与判题**（二次确认写明这一点）；
- 「完成」给出「本轮 N 道题都翻过了，重刷笔迹已逐题保存。原作答不受影响」。

### 2.3 看题页回显重刷

- 看题页读同一份 SIF → `renderInkDocPng`（白底 + 笔迹，1000×600）→ 新增「重刷（原作答不受影响）」一段；
- 「我的作答」改名「我的作答（收藏时）」，避免与原作答混淆；
- 从重刷页返回会重新加载这一段（`_startRedo` 里 await + `_loadRedo`）。

### 2.4 真机证据

- 组卷连刷里写两笔 → 撤销一笔 → 翻到第 2 题 → 翻回第 1 题：**剩下的一笔还在**（截图 `09/11`）；
- 从看题页「重刷」进入同一题：**看到组卷里写的那一笔**（截图 `16-single-redo-shared-ink.png`）——证明单题/组卷共享同一份 SIF；

## 4. 顺手修的两个真 bug

### 4.1 SIF `readPageSize` 用了大端（**数据事故级**）

- 现象：`answer_ink_store_test` 期望恢复后 `x≈100`，实际 **241.79**；
- 根因：`SifCodec.readPageSize` 用 `ByteData.getUint16(offset)` 的默认**大端**，而 `_Writer.u16/_Reader.u16` 都是**小端**。1000×600 被读成 **413.5×2869.5**；
- 后果：`AnswerInkStore._fit`（以及本轮新加的 `FavoriteRedoInkStore._fit`）每次都"尺寸不一致"→ 按 `1000/413.5=2.42` 与 `600/2869.5=0.209` 缩放笔迹。**不抛错，只是字被拉宽压扁**，属最难发现的一类；
- 修法：`getUint16(…, Endian.little)`；新增回归测试（`sif_codec_test`：1000×600 roundtrip 必须读回 1000×600）；
- 验证：`scaled x=99.98`（修复前 241.79），`answer_ink_store_test` 由红转绿。

### 4.2 书架最窄卡片 chip 溢出 6.8px

- 来源：跑被排除的 `bookshelf_grid_layout_test` 时暴露——`_Chip` 的文字只包了 `ConstrainedBox`，父级 `Flexible` 给的可用宽更小时硬顶出去；
- 修法：文字外层加 `Flexible`（能继续收缩 + 省略号）；
- 该测试本身仍不能在宿主跑（见 §7），但这条 UI bug 已修。

## 8. 已知限制 / 遗留

1. **二刷只有一张纸（1000×600）**：证明题可能不够写；如果要"每张纸一张 SIF + 张数切换"，可照答题卡的多张方案接（`pageIndex` 已经预留）。
2. **二刷不判题**：重刷完没有"判我的作答/AI 判"；目前判题仍只针对原卷作答（快照里保留的是收藏时的判题）。
3. **组卷不能拖动排序**：题序 = 加入顺序；要调整只能移出再加。下一步可接书架树那套拖动。
4. **看题页的 AI 追问仍只写快照**，与原卷"问 AI"互不相通（056 已确认口径）。
5. 老收藏的**作答图**没有按需升级（只有题面升级）：作答图来自页内笔迹裁切，重渲染需要读原卷 SIF，成本更高；当前 1024px 在缩小显示时够用。
6. 组卷目前没有"重命名/删除时更新列表滚动位置"之类的细节打磨；卡片墙仍是整组重建（收藏量几十级无感）。
