## 3. 三个关键设计（决定这份 spike 的数据可信不可信）

### 3.1 三层画布，落笔只重绘最上层

| 层 | 何时重绘 |
|---|---|
| 占位背景 | 从不（`ui.Picture` 在 initState 生成一次） |
| 已提交笔迹 | 只在"抬笔"时重绘一次 |
| 正在写的那一笔 | 每次 `onPointerMove`（`ValueNotifier` 驱动 `CustomPainter.repaint`） |

**这一条是 T0.2 数据成立的前提。** 若把三层合成一个 `CustomPaint` 每帧重画，测出来的必然是"Flutter 画不了字"——而那是实现的问题，不是框架的问题。

### 3.2 已提交笔迹用 Path 增量 append，不重建

`Path` 是可变对象。抬笔时对目标档位的 Path 做 `moveTo` + `lineTo`，成本 O(本笔点数)；
若每次重建成全量 Path，成本是 O(累计点数)，写到第 3 分钟才崩——正是清单里点名的坑。

**取舍**：已提交的笔画按压力分 3 档固定线宽（1.6 / 2.6 / 4.2），压感细节只在"正在写的那一笔"上逐段体现。
这样既避免了 O(n) 重建，也不至于整页糊成一根粗细。产品化（T2.2）再做真正的按段变宽。

### 3.3 落笔路径上只有三样东西

`_onPointerMove` 全文只有：坐标变换（除 `scale`）、距离阈值丢点、`_activePoints.add`、`_activeTick.value++`。
没有 `await`、没有 `setState`、没有 IO、没有 JSON。

落盘在「抬笔 2 秒后」的 `Timer` 里（防抖），并且**异常不再被吞**——`_persist()` 把成功/失败都写进 HUD 的「落盘」栏。

证据文件在 `main/build/spike_shots/`（build 目录，不入库）：`s1`–`s6.png`、`ink_spike.json`。

### 4.2 落盘实际位置（踩坑记录）

`Directory.systemTemp` 在 Android 上**不是** `/tmp`，而是应用的
`/data/user/0/com.shuaqi.shuaqi/code_cache`。实际文件：

```text
/data/user/0/com.shuaqi.shuaqi/code_cache/shuaqi_ink_spike/ink_spike.json
```

我一开始去 `cache/`（少看一层 `code_cache`）找，白折腾一次。这个结论写进 MEMORY 了。

> 第一次实现只用了 `Directory.systemTemp`，写盘失败时异常被 `unawaited` 静默吞掉，HUD 还显示"未落盘"却不知道为什么。
> 现在 `SpikeStore` 按 `systemTemp → /data/user/0/<pkg>/cache → /data/data/<pkg>/cache → current` 依次探测，
> 并把失败原因直接显示在 HUD 上。**产品化（T2.4）必须换成 `path_provider`，不许硬编码包名。**

### 4.3 模拟器专有的"非笔输入"开关

`Listener` 默认只收 `stylus / invertedStylus`（为手掌防误触打底）。但模拟器只有鼠标/触摸，
所以 spike 顶栏加了一个 `非笔输入` 开关，默认关闭。

**这个开关只允许存在于 spike 里。** 产品代码不得出现"允许触摸落笔"的路径。

### 4.4 帧数据（**不可作为验收依据，仅证明采集链路通**）

| 时点 | build 中位 | raster 中位 | 抖动率 |
|---|---|---|---|
| 刚启动 | 19.1ms | 14.1ms | 90.6% |
| 写 4 笔后 | 1.5ms | 2.3ms | 39.3% |
| 写 3 笔后（新装） | 1.9ms | 2.4ms | 4.2% |
| 切页后 | 1.8ms | 2.5ms | 26.1% |

**为什么不能当验收**：debug 模式的 Dart 编译器不优化、Impeller 走 OpenGLES 软路径、
且模拟器用的是宿主机 CPU。这三项叠加后数字没有物理意义。
它只证明一件事：`FrameTiming` 采集 → 中位数 → 抖动率这条链路是通的，真机直接就能读。

## 5. 待真机补测（T0.2 的剩余部分）

平板到手后按这个顺序做，**不要跳过第 2 步**：

1. `flutter install --profile`（或 `flutter build apk --profile -t spikes/ink_spike/main.dart` 后手工装）
2. **关掉「非笔输入」开关**，用真实手写笔写 —— 这一步同时验证"只收 stylus"是否真的把手指/手掌滤掉了
3. 连写 10 分钟（页面自带计时器），结束时看 `页笔画` 是否等于实际下笔次数（丢笔数 = 差值）
4. 另开一页测 3000 笔：每 500 笔记一次 `估算内存` 与 DevTools Memory，算增量
5. 视觉延迟：手机 120fps 录像 → 数「笔尖接触」到「像素出现」的帧差 ÷120 → 重复 5 次取中位
6. 把 5 组数字填进 §1 表格，然后决定 §14 的 `canvas:` 字段

**决策规则不变**：V1（延迟 > 30ms）或 V2（多页对位不准）不达标 → 转自建画布，不打补丁。
