## 2. 加题不收原框（一次改错又改回来，值得记）

**先改错了**：我以为"虚线框"是紫色**作答框**（`AnswerMark`），于是给作答框也挂了动作条、并在加题后写"隐藏标记"收掉它。用户指出："不是这个虚线框，是那个灰色的虚线框（不确定的切题）"。
→ 已经把这一串改动全部撤回（`AnswerSheetEntry.suppressed` 字段、控制器 `suppress/remove`、作答框浮条），不留死代码。

**真正的原因**：`region_overlay` 里 `mark.level == 1 → 画虚线`。**灰色虚线 = 大题容器框**（切题把一段切成了 level 1）。用户在它上面点「加题」，意思是"这块其实是一道题"。

**修法**（`reader_page._applyAction` 的 `addQuestion` 分支）：
```dart
await edit.run(AddQuestionCorrection(...));      // 新题（同 rect，随后可拖）
if (bundle.question.level == 1) {                // 原来是灰色虚线容器
  await edit.run(DeleteCorrection(key: key));    // 把原容器框一并去掉
}
```
`DeleteCorrection` 只标记**它自己** `deleted`（子题各自独立），所以容器下的小题不会丢。
真机验证：数学分析卷第 3 页选中「三、」虚线框 → 点加题 → 虚线框消失、出现实线框「7.」，其余「四、五、六」不受影响。

顺带把浮条改成**按传入动作渲染**（原来 `_ActionBar` 死写"改题号/并入上题/删除"三个按钮，`actionsOf` 只用来置灰）：
- 题目框仍只有 merge/rename/delete，且**只画此刻真能做的**（第一题没有"并入上题"就不出现）；
- 去掉"禁用态"（灰按钮既解释不清也点不动）。

## 3. 导出 PDF（阶段 10）

### 3.1 交互：4 个预设 + 3 个开关

`ui/bookshelf/export_sheet.dart`。同一份 `ExportOptions` 驱动两段 UI，点预设 = 把开关拨到那个组合，底部永远显示"将导出：原题 + 笔迹 + 答题卡"。

| 预设 | 组合 | 用途 |
|---|---|---|
| 纯试卷 | 原题 | 打印/分享干净卷子 |
| 试卷 + 笔迹 | 原题 + 笔迹 | 我做过的卷子（默认） |
| 完整存档 | 原题 + 笔迹 + 答题卡 | 归档 |
| 只要答题卡 | 答题卡 | 题目 + 作答的整理稿 |

规则集中在 `ExportOptions`：**关掉原题时笔迹一起关掉**（笔迹没有落点）；只剩空组合时导出按钮禁用。

### 3.2 生成：自己写 PDF，不引包

- `app/export/pdf_writer.dart`（纯 Dart，白名单外的包一个不加）：
  每页一张整页 RGB 位图 → `/FlateDecode` + PNG 预测器（`/Predictor 15 /Colors 3 /Columns w`）→ 手写 catalog/pages/page/image/content 对象 + xref 偏移。
  中文标题走 UTF-16BE 十六进制串（PDFDocEncoding 存不下 CJK）。
- `ui/bookshelf/workbook_export.dart`：
  1. `PdfrxSource.openFile` 开卷 → `PageImageCache` 取页位图（导出宽 1700px）；
  2. 画白底 → 铺 PDF 页 → `CommittedInkCache` 叠该页笔迹 → `toImage` → `rawRgba` → 去 alpha 成 RGB；
  3. 答题卡段：每题一页（A4 宽），标题「第 N 题 · 题型」+ 判定，题图裁切，下面接作答；
  4. `SimplePdfWriter.build()` → `savePdf` 通道落「下载/SHUAQI」。

### 3.3 答题卡段的口径（本轮最重要的判断）

用户是**在卷面上直接写**的，答题卡画布基本是空的。第一版只收 `sessions/<sid>/answers/*.sif`，导出只有 1 页"答题卡"，等于没做。
现在"有作答"的口径扩成四条，满足任一即收：
1. 答题卡画布有笔迹；
2. **页内该题作答区域有墨迹**（用笔画 bbox 与作答框求交）；
3. 作答框调过并识别过（有 OCR 文本）；
4. 有作答原图（crop）。

渲染也分两支：有答题卡纸 → 画纸（多张纵向排）；否则 → 把"作答区域整块（含页内墨迹）"裁出来画。这样"完整存档"对页内书写的卷子同样有意义（真机：线性代数 2 页原题 + 3 页答题卡）。

### 3.4 坑

- **`/Length` 与 stream 必须严格一致**：多算少算一个字节，PDF 阅读器就报"文件损坏"。测试用 latin1 摊字节（不能用"只留 ASCII"过滤——图片流里全是 >=128 的字节，一过滤偏移全乱）。
- **`Rect`/`RegionRect` 没有现成相交判定**：`RegionRect` 只有 left/top/width/height/right/bottom，自己写 `_overlaps`。
- **纸张比例不能用默认值**：答题纸可能是 A4 竖（842×595），用 `AnswerCanvas` 的 1000×600 会把竖纸压扁 → 必须读该题自己的 `AnswerPaper.widthPt/heightPt`。
- **toast 判断落点**：MediaStore 返回 `content://media/external/downloads/...`（小写），`contains('Download')` 判不出来，改成 `toLowerCase().contains('download')`。

## 5. 已知限制

1. 导出为**整页栅格**（1700px 宽）：不可选中文字，A4 单页约 150–500KB（纯文字页小、有笔迹的页大）。
2. 答题卡段只取"最新 draft 会话"的笔迹；交卷后的二刷不进同一份导出。
3. 导出没有取消按钮（一次几秒到十几秒）；多卷合并导出未做。
4. 灰虚线容器现在**加题即删**：如果那个容器下挂着真小题，删的只是容器本身（小题保留，但失去父级）。
