## 1. 问题一：翻页后第一次放大不跟手

### 根因（不是调参能解决的）

之前的写法是**只给"当前页"挂同一个 `TransformationController`**：

```dart
transformationController: index == _current ? _zoom : null,   // ← 错在这里
```

翻页瞬间 `_current` 变了，控制器从旧页摘下来挂到新页。这个"重挂"会把正在进行的
捏合手势打断——表现就是「翻页后第一次放大没反应，要再捏一次才行」。

### 修法

**每页各自持有一个控制器，永不重挂**：

```dart
final Map<int, TransformationController> _controllers = {};
TransformationController _controllerFor(int index) =>
    _controllers.putIfAbsent(index, () => TransformationController()
      ..addListener(() => _onZoomTick(index)));
```

配套调整：
- 监听器按 index 判断"是不是当前页"，非当前页的缩放不触发 setState；
- 翻页时**不重置**任何控制器（各页各自保留自己的缩放状态）；
- 翻页后 `_zoomed` / `_renderScale` 从**新页**的控制器读取。

顺带修掉一个隐患：之前 `onPageChanged` 里会 `_zoom.value = identity()`，
这在翻页动画进行中触发重建，本身也是卡顿源。

## 2. 问题二：滚动模式不能双指缩放

### 根因：手势竞技场

`InteractiveViewer` 内部是 `ScaleGestureRecognizer`，它把**单指拖动**也当作缩放手势的平移分支，
于是会赢下手势竞技场、把 `Scrollable` 的纵向拖动吃掉。
反过来把 `panEnabled` 关掉也不行——识别器仍然占位，列表照样滚不动。
这就是"缩放与滚动互相打架"的本质。

### 修法：不参与竞技场，自己数指针（photo_view 的思路）

用最底层的 `Listener` 接收原始指针事件（`Listener` 无论子级是否赢下手势都能收到）：

| 指针数 | 行为 |
|---|---|
| 1 | **什么都不做**，完全交给 `ListView`，滚动手感与原生一致 |
| ≥2 | 自己算两指距离 → `Transform.scale` 做**实时预览**（纯 GPU，零布局成本） |
| 手指全部离开 | 把预览倍率**提交**成新的页宽并重新布局（避免每帧重建位图） |

两指期间 `ListView.physics` 临时换成 `NeverScrollableScrollPhysics`，否则画面会一边缩放一边跑。

放大后页面比视口宽，横向由外层 `SingleChildScrollView` 负责，纵向仍归列表——两个轴向各管各的。

## 3. 真机验证（OPPO OPD2601）

| 场景 | 结果 |
|---|---|
| 第 1 页双击放大 | ✅ 2 倍 |
| **放大状态下**点右边缘翻页 | ✅ 翻到 2/4（程序化翻页不受 physics 限制） |
| **翻页后立刻双击放大** | ✅ 立刻放大到 2 倍（控制器未重挂） |
| 切滚动模式 | ✅ 回到 100%，无残留缩放 |
| 滚动模式单指上滑 | ✅ 正常滚动，看到页面底部（没有回归） |
| 滚动模式**双指捏合** | ⏳ **adb 注入不了双指，必须用手验** |

## 4. 已知的、需要手指验证的两个点

1. **捏合的跟手程度**：现在手势中是 `Transform` 预览（GPU），松手才重排。
   理论上跟手，但**松手瞬间会有一次跳变**——预览是绕"屏幕中心"缩放，
   而重排后是"页宽变大、从页首重新对齐"，两者落点不一致。
   如果跳变明显，下一步做「按捏合焦点提交」：记录捏合中心的页面坐标，
   重排后把纵向偏移调整到让该点仍在屏幕中心。
2. **分页模式的捏合上限**：`maxScale = 4`，超过会硬停。是否要在 4 倍时给个轻微阻尼反馈，可再议。
