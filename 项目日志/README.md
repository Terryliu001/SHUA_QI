# 项目日志 · 索引与规则

> 本目录是「刷起 SHUAQI」的**开发过程记录**，全部为 Markdown。
> 上游权威规格在 `D:\SHUAQI_project_dev\SHUAQI项目开发指导`（只读，不在本仓库内）。
> 日志不重复规格内容，只记录：**做了什么 · 实测到什么 · 卡在哪 · 下一步**。

---

## 1. 两类日志

| 类型 | 文件名 | 用途 | 写法 |
|---|---|---|---|
| **事件日志** | `NNN-YYYY-MM-DD-主题.md` | 每次实质性会话一篇（启动、体检、踩坑、决策、返工） | 追加式，**写完不再改历史结论**，有新结论就新写一篇并在末尾「推翻/修正」里指向旧篇 |
| **阶段日志** | `阶段N-名称.md` | 一个阶段（0–8）一份，跟踪该阶段全部 `T-x.y` 的进度与验收 | 随任务推进**持续更新**；阶段结束时在末尾写「交接记录」三行 |

命名规则：
- `NNN` 三位数字，全局递增，不复用、不补号。
- 日期为实际发生日（本地时区 GMT+8）。
- 主题用中文短语，能一眼看出这篇在讲什么，例如 `001-2026-10-22-项目启动与环境实检.md`。
- 不写 `日志1`、`新建文档`、`未命名` 这类无信息名字。

## 2. 每篇必带的头部

```markdown
| 项 | 值 |
|---|---|
| 日期 | YYYY-MM-DD |
| 阶段 / 任务块 | 阶段0 / T0.1（未开工则写「阶段0 前置」） |
| 本轮范围 | 一句话写清做了什么、**明确没做什么** |
| 结论 | 通过 / 部分通过 / 阻塞 |
```

## 3. 硬规矩

1. **只写事实与可复现的结论**，不写「应该没问题」这类判断。没实测就标「未验证」。
2. **命令与输出要留证**：贴关键命令与关键行，不贴整屏日志。
3. **数值带单位与口径**：`≤200ms` 要说明在哪台设备、什么模式（debug 数据一律标注「无参考价值」）。
4. **未决问题单列一节**，写清「选项 / 我的倾向 / 需要谁拍板」，不埋在正文里。
5. **不记录敏感信息**：API Key、设备序列号、用户名路径以外的个人信息。
6. 阶段结束时在 `阶段N-*.md` 末尾写三行交接：实际耗时 / 遗留问题 / 对下一阶段的提醒。
