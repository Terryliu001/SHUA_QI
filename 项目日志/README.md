## 2. 两类日志与命名

| 类型 | 文件名 | 用途 |
|---|---|---|
| **事件日志** | `NNN-YYYY-MM-DD-主题.md` | 每次实质性会话一篇，追加式；写完不改历史结论 |
| **阶段日志** | `阶段N-名称.md` | 当前未单独建，进度汇总在本 README §5 |

命名：`NNN` 三位递增，**不复用、不补号**；**合卷沿用首篇编号**并在标题标「（合卷 X–Y）」；日期为本地实际发生日。

## 3. 每篇必带的头部

```markdown
| 项 | 值 |
|---|---|
| 日期 | YYYY-MM-DD |
| 阶段 / 任务块 | 阶段N / T-x.y |
| 本轮范围 | 一句话写清做了什么、**明确没做什么** |
| 结论 | 通过 / 部分通过 / 阻塞 |
```

## 4. 硬规矩

1. **只写事实与可复现的结论**；没实测标「未验证」，不写「应该没问题」。
2. **命令与输出留证**：贴关键命令与关键行，不贴整屏日志。
3. **数值带单位与口径**；debug 数据标「无参考价值」。
4. **未决问题单列**：选项 / 倾向 / 需要谁拍板。
5. **不记录敏感信息**（API Key、设备序列号以外的个人信息）。
6. **数据契约优先**：SIF / 表结构 / JSON 布局这类格式变更，先定版再落盘。
7. **压缩不删根因**：合卷可删过程与重复背景，「现象 → 根因 → 修法 → 证据」必须完整。

## 6.5 设计哲学（改动前先读）

**谷歌的灵动 + iOS 的优雅简练 + 功能优先 / 性能轻量化，一切服从场景（刷题 / 手写 / 长时间读 PDF）。**

- 灵动：动效有目的有反馈（100ms 级）、标准 easing；不为炫技加动效。
- 优雅：低饱和单主色 + 中性灰、1px 发丝线、留白、统一圆角、线性图标、短文案。
- 契合场景：视觉让位于内容（纸感暖色、墨色非纯黑、低干扰）。
- 性能只守三条底线：**不卡 / 不抖 / 不爆**；优化必须带设备与场景的数字，不做没实测的过早优化。
- 令牌纪律：颜色 / 字号 / 间距 / 圆角 / 时长只从 `ui/theme/tokens.dart` 取，widget 不写字面量。

细节（暗色夜读 duotone、架构分层、环境坑）见 `.workbuddy/memory/MEMORY.md`。
