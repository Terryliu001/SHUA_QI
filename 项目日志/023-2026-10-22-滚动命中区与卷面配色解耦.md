## 1. 问题一：滚动模式「看得到、写不上」——内容是画对了，命中区被压扁了

### 1.1 先怀疑、再量化（不猜）

前两轮（021/022）验证过"滚动 100%/200% 能写"，所以这次先假设**不是所有位置都能写**。
用一个一次性 widget 探针把怀疑变成数字（`test/zz_probe_test.dart`，验证完已删）：

| 结构 | 内容盒子实际尺寸（期望 800×5000） | 内容坐标 y=2300 处落笔命中 |
|---|---|---|
| 旧：`SizedBox(视口) > ClipRect > Transform > SizedBox(整卷)` | **800×600**（= 视口高，被压扁） | **0 次** |
| 新：`SizedBox(视口) > ClipRect > Stack > Positioned > Transform > SizedBox(整卷)` | 800×5000 | **1 次** |

### 1.2 机制

1. 视口必须撑满父级（日志 015 立的规矩：否则裁剪边界退化成内容宽度）；
2. 于是 `SizedBox(视口)` 给下游的是**紧约束**，沿代理链一路传下去；
3. `SizedBox(整卷高)` 的尺寸被 `BoxConstraints.enforce` **压回视口高度**；
4. 绘制不受影响（`Stack` 的 `clipBehavior: Clip.none` 照样按 `Positioned.top` 画），
   但 `RenderBox.hitTest` 第一件事是 `size.contains(position)` ——
   **内容坐标 y > 视口高的落笔全部被丢弃**；
5. 所以在 848×1050 的视口里，只有"整卷最上面那一屏"能写：第 1 页上半页正常，
   第 2 页往后、以及滚下去的任何位置都写不上。用户说的"滚动模式仍有不能书写"就是它。

前两轮之所以测不出：`input stylus` 注入点都落在文档顶部（内容坐标 y < 视口高），
恰好是唯一能写的区域。**这是"测在能写的地方"造成的假通过**，记在案。

### 1.3 修法

新增 `ui/reader/camera_viewport.dart`：把"视口 / 裁剪 / 矩阵"三件事收进一个 widget，
并把那条不能改回的结构约束写死在里面 ——

```text
SizedBox(视口) > ClipRect > Stack(clipBehavior: none)
                                └─ Positioned(left:0, top:0)   ← **故意不给 width/height**
                                     └─ ValueListenableBuilder<Camera> > Transform > 整卷
```

`Positioned` 只给 `left/top` 时子节点拿到的是**无界约束**，`Transform` 因此是整卷尺寸，
命中链能走到内容坐标系里的正确位置；`Stack` 自己是视口尺寸，裁剪交给外层 `ClipRect`
（只裁显示，不裁命中范围）。相机状态从私有 `_Camera` 提升为 `Camera`（值相等，可单测）。

回归测试 `test/camera_viewport_test.dart`（5 例）：内容盒尺寸、1 倍/2 倍命中、纸外不命中、
相机变化不重建内容子树。

### 1.4 真机验证（`input stylus` 注入 + 截图逐条确认）

| 场景 | 结果 |
|---|---|
| 滚动模式 → 连甩到第 3/4 页 → 写两笔 | ✅ 两笔都落在第 3 页，位置精确（修复前这里是死区） |
| 同一页 → 菜单 setScale 200% → 写一笔横、一笔竖 | ✅ 笔画中心与注入坐标逐一吻合 |
| 书写期间页面不跑、页码不乱跳 | ✅ |

## 2. 问题二：深色主题不该把 PDF 也变黑

### 2.1 旧设计与它为什么错

旧规则（T1.6）是"App 一进深色 → 所有卷面强制 duotone 夜读"。它把**界面配色**和
**纸面配色**绑成了一件事，于是出现两个错：

- 深色界面下**没法看白底黑字**的卷子（暗光批卷、投影、彩色插图都会失真）；
- 浅色界面下**也选不到**夜读（代码里根本没有这个选项，只有主题里那一条路）。

用户拍板：黑底白字只作为一种**风格选项**，白底黑字必须随时可用，深色≠PDF 变黑。

### 2.2 新规则：纸样式与 App 主题正交

| 关注点 | 谁决定 | 管什么 |
|---|---|---|
| App 主题（跟随系统 / 浅色 / 深色） | `themeModeProvider` | 书架、AppBar、浮层、抽屉等**骨架** |
| 纸样式 `PaperStyle` | `reader.*` 偏好（全局默认 + 每卷覆盖） | **卷面**配色：原图 / 暖白 / 象牙 / 浅灰 / 护眼 / **夜读** |

- `PaperStyle` 新增 `night`（夜读）——它是**一种纸样式**，浅色界面下也能选；
- 新增 `PaperStyle.isDarkPaper`（extension）作为"暗纸亮墨"的**唯一判定**，
  UI 层不许再写 `style == PaperStyle.night`，更不许看 `Theme.brightness`；
- 废止 `ReaderPrefs.forSurfaceBrightness`（旧耦合的实现，已无调用方）；
- 墨色跟着**纸**走（`inkColorFor`）：夜读纸 → 暖白墨，其余 → 深墨。
  已画的笔**自动换色**（几何是数据，颜色是呈现），这样切到夜读不用重写一遍；
- 页面底色 / 发丝边 / 投影也跟纸走，并且**画在滤镜之外** ——
  放在滤镜里会被 duotone 再反一次色（黑投影变成一圈脏光）。

### 2.3 真机验证（设备当前就是深色主题）

| 场景 | 结果 |
|---|---|
| 深色主题 + 「原图」 | ✅ 纯白纸 + 黑字（**旧版这里会把整页涂成夜读**） |
| 深色主题 + 「夜读」 | ✅ 暖黑纸 + 暖白印刷字；旧笔迹自动变暖白墨；新写的笔也是暖白墨 |
| 显示浮层 | ✅ 六个色块（多出「夜读」）在深色下**全部可点**，不再整块置灰 |
