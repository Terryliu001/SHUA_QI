## 1. 滚动模式：从"只能贴满屏"改成"可缩放的卷轴"

### 1.1 用户的判断是对的

旧实现 `1.0 = fit-width = 页宽正好等于屏宽`，还只能放大（`_minScale = 1`）。这带来两个必然结果：

1. **横向被夹死**：内容宽 == 视口宽，任何横向位移都被 `clampOffset` 吃掉；
2. **没有留白**：页面永远贴着两侧边缘，1px 的抖动都看得见。

### 1.2 新规则

| 量 | 旧 | 新 |
|---|---|---|
| 默认 | 1.0（贴满屏） | **0.86**（页宽占 86%，两侧留白，和翻页模式观感一致） |
| 最小 | 1.0（不能缩小） | **0.45**（整页浏览；横向自动居中） |
| 最大 | 4.0 | 4.0（不变） |
| 档位菜单 | 100/125/150/200% | **60 / 86 / 100 / 150 / 200 / 300%** |

- 100% 仍是 fit-width（语义不变，老习惯不受影响），只是默认不再是它；
- 清晰度档位向下扩展到 0.45/0.6/0.75/0.86 —— 缩小后位图按缩小后的像素出图，
  0.45 档一页只要 ≈11MB，省下来的内存正好给预热用；
- 横向居中/夹紧本来就写在 `ScrollMath.clampOffset`（"内容窄于视口 → 居中"），
  这次只是终于用上了。

### 1.3 顺手修掉三处"不顺滑"的真实来源

| 问题 | 根因 | 修法 |
|---|---|---|
| **拖动起手有死区、之后一直落后手指 18dp** | `GestureDetector` 默认 `DragStartBehavior.start`，`onScaleStart` 的焦点取的是"越过触摸阈值那一刻"的位置，前面那 18dp 位移被永久丢掉 | `dragStartBehavior: DragStartBehavior.down` → 焦点基准取按下点，越过阈值时一次补上，之后 1:1 |
| 拖动中整页重建 | `_updateCurrentPage` 回调 `onPageChanged` → `ReaderPage.setState`（顶栏/工具条/两个视图全重建）**发生在拖动过程中** | 手势/甩动期间只更新内部页码，**抬手后补发一次**（`_pendingPage` + `_flushPendingPage`） |
| 跨页频繁重建页面列表 | 构建范围就是可见集，贴着视口边界时来回跨页 | 构建范围左右各多一页（离屏预烘一张），拖动中重建次数从"每页几次"降到"最多一次" |

### 1.4 量化证据（真机，可复现的脚本化测量）

**跟手性**：慢速拖动 80px（2 秒），用"页间缝隙的 y 坐标"测量内容实际位移：

| | 内容位移 |
|---|---|
| 修复前（按 1:1 应该走 80px，实际差一个触摸阈值） | ≈16–20px |
| **修复后** | **80px（1:1，无死区）** |

**帧耗时**（HUD，与 026 同口径）：raster 中位 2.1–3.3ms、超 60Hz 预算 0–2%、最差帧 5.0ms。

## 2. 笔/橡皮粗细：三档 → 0..100 多级

- `InkStroke.widthLevel(0..2)` → **`brushWidth(0..100)`**：整数正好 1 字节，
  SIF 的代价与三档枚举一样，所以数据契约不用再改；
- 映射（`InkWidth.baseOf`）：
  | 笔 | 0 | 100 |
  |---|---|---|
  | 钢笔 | 0.8pt | 5.2pt（再乘压感系数 0.55–1.20） |
  | 圆珠笔 | 1.0pt | 4.0pt（等宽） |
  | 荧光笔 | 6pt | 36pt（等宽） |
  | 橡皮 | 4pt 半径 | 28pt 半径 |
- UI：面板里一条滑条 + 右侧"真实大小"参考点；顶栏形态是 168dp 的紧凑滑条。

### 2.1 落笔处的大小参考圈（用户点名的"绘画软件做法"）

改粗细 / 换工具时，在**最后一次落笔的位置**浮出一个真实大小的圆，1.4 秒后淡出：

- 用 `ValueNotifier<Offset?>` 驱动，不 setState、不碰墨迹层缓存；
- 直径按真实大小，但**不小于 14dp**（钢笔最细档 0.9pt 按原尺寸只有 3px，等于没提示）；
- `IgnorePointer`，绝不挡落笔。

真机验证：切到荧光笔（粗细 60% ≈ 24pt）时，笔画末端确实浮出一个 ≈34dp 的淡圈。

### 2.2 一个必须记下来的坑：旧持久化值被当成新语义

粗细从三档变 0..100 后，`setting` 里旧的 `pen:2:2` 会被解析成 **2%（极细）**，
真机上笔迹直接细成发丝（截图对比确认）。修法：持久化串加 **格式版本前缀**：

```text
新：v2:pen:0:50;v2:highlighter:2:85
旧：pen:0:2        → 按 0/1/2 映射到 15/50/85
```

`test/ink_brush_test.dart` 用 6 例钉住（新格式往返、旧值迁移、脏数据不抛、换工具收敛颜色、粗细夹紧）。

## 3. 工具条：顶栏 ↔ 浮窗双向切换（不用绕去设置页）

- 顶栏形态右侧新增「改为浮窗」按钮；
- 浮窗面板顶部新增「⤒ 固定到顶栏」动作；
- 两者都读写同一个 `inkToolbarPinnedProvider`（落盘 `ink.toolbar_pinned`），
  设置页里的开关仍然保留（三处入口，一份状态）。

真机验证：顶栏点「改为浮窗」→ 工具带消失、右下角圆钮回来；浮窗面板点「固定到顶栏」→ 反之，且重启后保持。

## 4. 书架管理：文件夹 + 标签 + 重命名 + 查找

### 4.1 数据层（迁移 v3，只追加不改历史）

```sql
ALTER TABLE workbook ADD COLUMN folder TEXT NOT NULL DEFAULT '';
ALTER TABLE workbook ADD COLUMN tags   TEXT NOT NULL DEFAULT '';
CREATE INDEX idx_workbook_folder ON workbook(folder);
```

- 老数据自动落到「未分类 / 无标签」，不需要回填；
- 为什么不用独立的 folder/tag 表：卷子是几十级的、书架是平铺列表，
  单层文件夹 + 逗号串足够；不建关联表就不会出现"空文件夹"这种要单独维护的状态。
- `WorkbookTags`（domain，纯函数）负责规范化：中英文逗号都认、去空、去重、
  单个 ≤12 字、最多 8 个。

### 4.2 交互

| 能力 | 入口 |
|---|---|
| 分类筛选 | 书架顶部 chip 行：全部 / 未分类 / 各文件夹 |
| 移动到文件夹 | 长按卷 → 移动到文件夹（含"新建文件夹…"） |
| 标签 | 长按卷 → 编辑标签（一行逗号分隔） |
| 重命名 | 长按卷 → 重命名（原有，保留） |
| 查找 | 右上角搜索，命中 **标题 / 标签 / 文件夹名** |
| 卡片显示 | 文件夹 chip（带图标）+ 标签 chip（`#tag`） |

真机验证：长按第一卷 →「移动到文件夹」→「新建文件夹…」→ 输入 `calculus` → 保存
→ 顶部出现 `calculus` chip、该卷卡片出现 `📁 calculus`、toast「已移到「calculus」」。
迁移 v3 在真机上正常执行（未崩溃、数据保留）。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| **双指捏合缩小到 <45% 无法自动验证** | `adb input` 单指针；数学上 clamp 已覆盖（`ScrollMath` 有单测），但"手感"要你实机确认 |
| 滚动"顺滑"仍是主观判断 | 我能给的是：帧耗时达标（0–2% 超预算）+ 拖动 1:1；剩下的顺滑感需要你的手 |
| 单层文件夹、标签不做层级 | 卷子数量级决定；以后要"文件夹树"再改（迁移只需再加列） |
| 文件夹名重命名会**批量**改它下面所有卷 | `renameFolder` 已实现但没有 UI 入口（等 UI 重构时一起做） |
| 搜索不匹配拼音/首字母 | 打字 → 匹配子串，够用 |
