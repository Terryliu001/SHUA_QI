## 1. 项目概览

SHUAQI（刷起）是一款**本地优先**的 PDF 刷题 / 手写笔记 App：用户导入 PDF 试卷，App 自动切题、识别题号，用户在题面上手写作答、荧光笔标注；支持自动/AI/人工判题、收藏跨卷快照、错题二刷组卷、作答记录时间线、个人空间等。所有数据留在用户设备，`vault/` 目录即全部状态。

- **当前平台**：仅 Android（arm64，minSdk 26 / Android 8.0+）。
- **版本**：`0.1.2+3`（`main/pubspec.yaml`），DB `v9`（`main/lib/infra/db/migrations.dart:251`）。
- **包体积**：release arm64 约 36.7 MB（`Rpage/download/shuaqi-0.1.2.apk`，38,509,535 字节，SHA-256 `A30425EB…30BFB6B6`）。
- **关键外部依赖（白名单，锁定版本）**：`pdfrx 2.9.0`（带 pdfium 原生资产）、`google_mlkit_digital_ink_recognition 0.16.1`（手写识别，GMS 依赖）、`flutter_riverpod 3.4.3`、`archive`（zlib）。**新增依赖需先请示**，不编造 API。

> 移植含义：所有"数据契约"（SIF 二进制、Vault 路径、DB 表、切题/批改 JSON）是**跨平台不变的**；变的是"平台能力"（落盘到系统相册、MediaStore、ML Kit、pdfium 原生构建、`dart:io` 网络）。本文第 13 节给出逐条替换清单。

## 3. 目录结构与分层架构

### 3.1 三层依赖方向（由 `test/architecture_test.dart` 强制）

```
ui   →  state  →  domain
app  →  infra  →  domain
```

- **`domain/`**：纯 Dart，**不得** `import 'package:flutter/'`、`dart:io`、`dart:ui`、`dart:html`；**不得**反向依赖 `app/infra/ui/state`（`architecture_test.dart:10-49`）。几何、判题、SIF 编解码、切题、批改模型全在这里，可脱离 Flutter 单测。
- **`infra/`**：平台/三方能力的薄封装（DB、Vault、pdfrx 包装、OCR、SIF 落盘、AI 协议）。**不得** `import Material/Widgets/Cupertino`（`architecture_test.dart:51-72`）。
- **`app/`**：带副作用的编排层（切题调度、判题控制器、收藏 store、记录服务、反馈、备份、导出）。可依赖 `domain + infra`，不得碰 Widget。
- **`state/`**：Riverpod providers，连接 `app/domain` 与 `ui`。允许 import Material。
- **`ui/`**：Widget 树，允许 import Material。

> 移植含义：只要遵守分层，`domain/` 几乎零成本跨平台复用；移植工作量集中在 `infra/` 与 `app/` 的平台通道、`ui/` 的少量平台相关渲染。

### 3.2 `main/lib` 关键子目录

- `domain/ink/`：`sif_codec.dart`（SIF 二进制）、`ink_doc.dart`、`ink_store.dart`（纯模型仓库）。
- `domain/region/`：切题（split、scan_split、confidence、grading_rules、grading_policy）、`correction.dart`（覆盖层 op）。
- `domain/model/`：`grading.dart`（判题模型）。
- `domain/reader/`：`night_tint.dart`（夜读 duotone，纯 Dart）。
- `infra/db/`：`migrations.dart` + `dao/`。
- `infra/vault/`：`paths.dart`（路径唯一拼装入口）、`corrections_store.dart`、原子写工具。
- `infra/ink/`：`sif_ink_store.dart`、`answer_ink_store.dart`、`favorite_redo_ink_store.dart`（SIF 落盘，各自带 `.tmp`+rename+`.bak`）。

## 4. 数据库与持久化（`infra/db/migrations.dart`）

**铁律**：迁移**只追加，不修改历史版本**（`migrations.dart:1-7`）。已发出的 v1 永远是那 6 张表的样子。最后一个 `Migration.version` 即 `kDatabaseVersion`（当前 **9**，`migrations.dart:251`）。迁移里**不许写业务数据**（默认值用列 `DEFAULT`）。

### 4.1 表清单（按引入版本）

**v1 — 六张核心表**
- `workbook(id PK, title, sha1 UNIQUE, page_count, page_size, source_path, created_at, opened_at, last_session_id, layout_status DEFAULT 'none')`
- `wb_page(id PK, workbook_id→workbook ON DELETE CASCADE, idx, w, h, UNIQUE(workbook_id, idx))`
- `session(id PK, workbook_id→workbook CASCADE, seq, state DEFAULT 'draft', started_at, submitted_at, last_page DEFAULT 0, UNIQUE(workbook_id, seq))`
- `question(id PK, workbook_id→workbook CASCADE, ordinal, label, level DEFAULT 2, parent_id, kind DEFAULT 'unknown', stem_text, confidence DEFAULT 0, source DEFAULT 'rule')`
- `question_region(id PK, question_id→question CASCADE, page_id→wb_page CASCADE, x, y, w, h, role DEFAULT 'mixed', confidence DEFAULT 0, locked DEFAULT 0)`
- `ink_state(page_id PK→wb_page CASCADE, session_id→session CASCADE, revision, stroke_count, byte_size, dirty DEFAULT 1, last_ocr_at, sif_path, dirty_since)`

**v2** — `setting(k TEXT PK, v TEXT NOT NULL)`（阅读/AI 等键值偏好）。
**v3** — `workbook` 加 `folder TEXT DEFAULT ''`、`tags TEXT DEFAULT ''` + 索引 `idx_workbook_folder`。
**v4** — `folder(id PK, name, parent_id DEFAULT '', color DEFAULT '', sort)`、`workbook.folder_id DEFAULT ''` + 索引；`tag(name PK, color DEFAULT '')`。
**v5** — `llm_usage(id AUTOINC, at, model, task, tokens_in, tokens_out, estimated DEFAULT 0, ok DEFAULT 1)` + `idx_llm_usage_at`。
**v6** — `favorite(...)`**无外键**（卷删后收藏仍保留，`source_deleted` 标记来源卷已删）；`favorite_set` / `favorite_set_item(set_id→favorite_set CASCADE, favorite_id→favorite CASCADE, sort, PK(set_id,favorite_id))`。
**v7** — `answer_log(id AUTOINC, at, day, workbook_id, workbook_title, question_id, label, kind, page_index, source DEFAULT 'ink', verdict DEFAULT 'none', hits DEFAULT 1)`，**无外键**；唯一索引 `idx_answer_log_q_day ON (question_id, day)`（一天一题一行，day=**本地** `yyyy-MM-dd`）。
**v8** — `answer_log` 加 `origin DEFAULT 'workbook'`、`origin_title DEFAULT ''`；唯一索引改为 `(question_id, day, origin)`（重刷单独计一次）；加 `idx_answer_log_origin`。
**v9** — `answer_log` 加 `attempt_id DEFAULT ''`、`favorite_id DEFAULT ''`；唯一索引改为 `(question_id, day, origin, attempt_id)`（多次重刷逐次查看）；加 `idx_answer_log_attempt`。

### 4.2 移植要点

- **无外键的两张核心表**：`favorite` 与 `answer_log` 都**不设外键**——卷删不级联，因为"我做过/收藏过"这件事在卷删后仍然成立，卷名/题号在写入时抄一份快照（`favorite.workbook_title`、`answer_log.workbook_title/label`）。移植到任何 DB 引擎（SQLite/Realm/其他）都要保留"无外键 + 快照冗余字段"的语义。
- **`day` 是本地日期**：避免跨凌晨把"晚上做的题"掉到第二天。任何平台都要用设备本地时区的 `yyyy-MM-dd`，不要 UTC。
- **状态码/枚举用 `name` 字符串**：`verdict`/`source` 用 `AnswerVerdict.name`/`GradeSource.name` 存（`domain/model/grading.dart`），解码失败回退到 `none`/`auto`，不抛异常——跨语言移植照此实现。
- **`sha1` 唯一**：`workbook.sha1` 去重导入（`sha1OfFile` 流式算，见 Vault）。

## 5. Vault 文件系统（`infra/vault/paths.dart`）

**唯一拼装入口**是 `VaultPaths`（`paths.dart:9`）。除本文件外**任何地方不许手写 `workbooks/xxx/yyy` 这类字符串**——路径是数据契约，改了老用户文件就找不到，等同丢数据。

### 5.1 顶层根目录

- `workbooks/`：所有卷（每卷 `workbookDir = workbooks/<id>`）。
- `favorites/`：收藏库（**跨卷、卷删后仍保留**，孤儿清理只扫 `workbooks/` 不碰这里）。
- `profile/`：个人空间（头像 `avatar.img`、页首背景 `cover.img`），与卷无关。
- `feedback/`：反馈草稿（**不属于任何卷，清理缓存时禁止碰**）。

### 5.2 一卷内部（`workbookDir`）

- `source.pdf` / `source.pdf.tmp`（写时 `.tmp`→fsync→rename，避免半个文件），**原卷永不被滤镜污染**。
- `meta.json`：人可读冗余元数据，**以 DB 为准**。
- `thumb/pNNN.png`：缩略图，**0-based 页码补零 3 位**，目录排序即页序。
- `layout/`：切题产物目录：
  - `text.json`（L0 文本层，自动结果，可删重建）
  - `regions.v1.json`（**自动结果，只读**，用户编辑不许改它）
  - `corrections.json`（**用户覆盖层**，重算自动结果时保留）
  - `answers.v1.json`（文末答案区，可重抽）
  - `answers_ai.v1.json`（AI 补的答案，**重切题不得覆盖**，与上面分开存）
  - `answer_sheet.v1.json`（作答框 + 本地识别/原图）
  - `answer_crops/<qid>.png|ink.png|sheet.png`
  - `question_order.v1.json`（手动排序，保留）
  - `grading.v1.json`（判题结果，**用户手改不被自动判覆盖**）
  - `ai_chat.v1.json`（问 AI 对话历史，保留）
  - `answer_paper.v1.json`（答题卡纸张配置）
  - `favorites.v1.json`（**v6 起废弃**，仅用于迁移）
- `sessions/<sessionId>/`：一次作答全部产物（二刷目录必须唯一）。
  - `ink/pNNN.sif`（**页笔迹**，`.tmp`+`.bak` 原子写，500ms 防抖）
  - `answers/<qid>.sif`（答题卡笔迹，按 session 分开，二刷不覆盖第一次；第 0 张 `<qid>.sif`，之后 `<qid>_p1.sif…`）
- `exports/`：交卷快照/分析产物。

### 5.3 收藏内部（`favorites/<favoriteId>/`）

`stem.png`（题面）、`answer.png`（作答含笔迹）、`chat.json`、`grading.json`、`answer.json`、`ink/p0.sif`（二刷笔迹）、`paper.json`（答题纸配置）、`redo/<attemptId>/`（每次重刷独立目录，含 `meta.json`/`paper.json`/`ink/pN.sif`）。

### 5.4 移植要点

- **原子写范式**：`.tmp` 写 → fsync → rename 覆盖 → 旧的 rename 成 `.bak`。这套依赖 POSIX/Windows 的原子 rename，跨平台都要保留（iOS 沙盒、Desktop、Web 用 IndexedDB/Blob 时需等价语义）。
- **`sweepOrphans`**：只扫 `workbooks/`，按 `VaultPaths.workbookIdOf()` 反推 id，清掉 DB 里已无记录的卷目录——**绝不**误伤 `favorites/`/`profile/`/`feedback/`。
- **`_safeId`**（`paths.dart:266`）：文件名仅允许 `[A-Za-z0-9_-]`，题 id 是 ULID 但防御性替换，移植时字符约束保持一致。

## 6. 领域层契约（跨平台不变的核心）

### 6.1 SIF v1 笔迹二进制（`domain/ink/sif_codec.dart`）

**纯 Dart、可单测**，是手写笔迹的落盘格式。**这是移植中必须逐字节对齐的数据契约。**

文件结构（整文件 zlib 压缩）：
```
zlib( Header 16B | Stroke × n | Footer 4B )
Header: 'SIF1' | flags u8 | pageW u16 | pageH u16 | nStrokes u32 | reserved 3B
        pageW/pageH 单位 = 0.1pt（841.89pt → 8419）
Stroke: style u8 | color u8 | width u8 | flags u8 | nPoints u16
        | bbox 4×u16 | t0 u32 | points(dx,dy zigzag varint) | pressure(4bit×n)
Footer: crc32(body) u32      // body = Header + Strokes
```

- **字节序**：**必须 little-endian**（`sif_codec.dart:97-116`，2026-10-25 修过一个读成 big-endian 导致笔迹被错误缩放的严重 bug）。
- **坐标量化**：`q = round(v / pageSize * 16383)`，`quantMax=16383`（`sif_codec.dart:47`）。往返误差 ≤ pageSize/(2×16383)，A4 高约 0.026pt。页尺寸用 **0.1pt 定点**存 u16，避免长边累积误差。
- **压力**：**4bit**（15 级，`pressureLevels=15`），打包在坐标之后，两个点一字节（低半字节=前一点，`sif_codec.dart:221-228`）。钢笔粗细靠它。
- **CRC-32**：IEEE 802.3 多项式 `0xEDB88320`（`sif_codec.dart:392`）。
- **单笔上限 4096 点**（`maxPointsPerStroke`）；超长笔拆成多笔同款式碎片。`maxStrokes=1000000`。
- **UID 不进文件**：解码时重新生成（`sif_codec.dart:339`），UID 是会话内身份，不是跨进程事实。
- **笔型编码是数据契约**：`style u8` 写的是 `InkStrokeStyle.index`，枚举**只能追加不能重排**。
- **解码严格性**：任何结构错误抛 `SifCorruptException`（magic 非 SIF1、CRC 不匹配、坐标越界、压力块长度不对等）。
- `readPageSize()` 只读页尺寸（不改笔画），用于"换了答题卡纸张后按比例搬旧笔迹"。

> 移植要点：SIF 编解码是纯 Dart，**可直接复用**。但解码较重，**建议在 Isolate 中执行**（避免主线程卡顿），尤其 Web/Desktop 大页。`zlib` 用 `package:archive` 的 `ZLibEncoder/Decoder`（跨平台可用）。

### 6.2 切题（region）：只读自动结果 + 用户覆盖层

- `regions.v1.json` 是**自动结果，永远只读**（格式版本 `kRegionDocumentVersion=1`，`region_builder.dart:325`）。
- 切题算法代号 `kCutterVersion=5`（`region_builder.dart:337`）：只要切题逻辑变了就 +1，打开卷子发现库里是旧代号会在后台**静默重切**（用户无感）。v5 = 文末答案区抽到 `answers.v1.json` + 重切保留覆盖层。
- 用户所有修改写进 `corrections.json`，读取时 `effective = applyAll(auto, ops)`（`correction.dart:8-12`）。直接改自动结果 → 下次重切全丢。

**覆盖层 11 种操作**（`correction.dart` 的 `RegionCorrection.fromJson` 分发，`t` 字段）：

| `t` | 类 | 作用 |
|---|---|---|
| `move` | `MoveCorrection` | 拖动整框（当前页那一段） |
| `resize` | `ResizeCorrection` | 缩放（拖边/角） |
| `addSlice` | `AddSliceCorrection` | 在某页给题加一段（跨页题） |
| `removeSlice` | `RemoveSliceCorrection` | 去掉某页那一段 |
| `add` | `AddQuestionCorrection` | 手画新框（新题） |
| `confirm` | `ConfirmQuestionCorrection` | **就地确认**虚线大题容器为实题（level 1→2，题号/位置/id 全不变） |
| `delete` | `DeleteCorrection` | 软删除（保留记录，重切后可按 anchor 找回） |
| `merge` | `MergeCorrection` | 并入另一题，被并者标记删 |
| `split` | `SplitCorrection` | 在某页 atY 处拆成上下两段 |
| `rename` | `RenameCorrection` | 改题号（会重算 anchor key） |
| `lock` | `LockCorrection` | 锁定/解锁（锁定框不参与重算） |

- `CorrectionLog.maxOps=200`（`correction.dart:607`，也是文件最多留多少条操作）。撤销 = 弹最后一条重算。
- **anchor key**：`题号|页|y`，改标签/分段会改 key，apply 完必须 `regionKeyOf()` 重算，否则后续 op 对不上（`correction.dart:754` 的 `withKey`）。
- `questionDeltaOf()` 只数真正改题数的 op（add/split +1，delete/merge −1），给面板显示"手改了几道"。

### 6.3 判题（grading）：`QuestionGrade` / `GradingData`（`domain/model/grading.dart`）

- `AnswerVerdict`：`none / correct / wrong / pending`（**注意 `pending≠错`**，文案须明说）。
- `GradeSource`：`auto / manual / ai`。**一键改卷不覆盖 `manual`/`ai` 结论**（`grading.dart:42-45` 注释）——否则刚花 token 判完的主观题会被打回 pending。
- `RegionGrade` 是**切题置信度**（green/yellow/red），跟"答对了没"无关——两者同名不同义，历史上踩过坑（`grading.dart:1-6`）。**灰虚线框 = `level==1` 大题容器**，不是紫色作答框。
- `grading.v1.json` 存 `question_id → QuestionGrade`；用户手改永久保留。

### 6.4 答题卡 / 作答纸（answer paper）

- 每题一份 SIF（`answer_ink_*`），与 PDF 页笔迹分开；按 session 分开，二刷不覆盖第一次（`paths.dart:164-189`）。
- 答题卡坐标体系：**1000×600**（`layoutAnswerSheet` 注释、`answerSheetExport`）。
- 二刷 attempt 独立目录（`redo/<attemptId>/`），一次重刷一个 id，时间线才能打开"那一次"的笔迹。

## 7. 基础设施层（移植主要改动区）

### 7.1 PDF 渲染：`pdfrx 2.9.0`（**原生 pdfium 资产**）

- `infra/pdf/pdf_source.dart`、`paper_renderer.dart` 包装 pdfium。
- **移植含义**：pdfium 是 C++ 原生库，`pdfrx` 用 **native assets** 机制。iOS/Desktop 各自需要 pdfium 的对应原生构建；**Web 没有 pdfium 原生绑定**，需换方案（`pdf.js` 或后端渲染）。这是平台移植最大的单点依赖。
- 页位图缓存 `PageImageCache`（`ui/reader/page_image_cache.dart`）直接持有 `ui.Image`（GPU 纹理），**Web 上无 `dart:ui` 的 `ui.Image` 等价物**，需重新设计。

### 7.2 手写识别：`google_mlkit_digital_ink_recognition 0.16.1`（**Android / GMS 依赖**）

- `infra/ocr/mlkit_ink_engine.dart`、`ocr_engine.dart`。
- **首次需联网下载模型**（Rpage FAQ 明确写明）。GMS（Google Mobile Services）在国产 Android / iOS / 桌面都不存在。
- **移植含义**：iOS 用 `Apple PencilKit`/`Vision` 或自建；桌面/Web 需服务端 OCR 或 WASM 模型。**这是非 Android 平台的硬性替换点。**

### 7.3 AI 客户端：`dart:io HttpClient`（**Web 不兼容**）

- `infra/ai/openai_client.dart:3` 直接 `import 'dart:io'`（`sif_codec` 之外 AI 层不用 `package:http`）。
- 理由（代码注释）：SSE 按行边收边吐最直接、不新增依赖、超时/取消/连接错误自控（`openai_client.dart:12-15`）。
- 自己实现 SSE 解析（`SseParser`）、`stream_options`/深度思考不支持时自动去掉重试（`openai_client.dart:66-91`）。
- **移植含义**：Web 没有 `dart:io`，必须换成 `package:http` 或 `fetch` 流；其余协议层（`buildChatRequestBody`/`parseChatCompletion`/`SseParser`）是纯 Dart 可复用。**这是 Web 化的硬性替换点之一。**

### 7.4 反馈通道（见 §12）

- `app/feedback/github_feedback_gateway.dart`：`dart:io` HttpClient 直连 GitHub 私有仓库 Issues/Contents API。token 经 `--dart-define=FEEDBACK_GH_TOKEN` 注入，**不进 git**。
- `http_feedback_gateway.dart`：自建 HTTP 端点（Cloudflare worker）。
- `feedback_config.dart`：二选一；都没配 → 只落本机草稿箱，**不假装成功**。

## 8. 状态与 UI 核心（渲染红线）

### 8.1 状态管理：Riverpod 3.4.3

- R3 中 `autoDispose` 已是默认，**全仓零 `.autoDispose`** 写法。
- `dispose()` 里**不能** `ref.read`（Riverpod 3 约束）——迁移到新版本时注意。

### 8.2 渲染红线（真机踩过的坑，移植必须保住）

1. **相机视口的无界 Positioned**（`ui/reader/camera_viewport.dart:52-102`）。
   结构：`SizedBox(视口) → ClipRect → Stack(clipBehavior:none) → Positioned(left/top，故意不给 width/height) → Transform → 内容`。
   原因：视口给紧约束会沿代理链把"整卷高"压回视口高，命中测试被截在视口高度 → "滚动模式下只能写第一页上半屏"。只给 left/top 让子节点拿无界约束，内容盒保持整卷尺寸，命中链一路走到正确位置。裁剪交给外层 `ClipRect`（只裁显示不裁命中）。**回归测试 `test/camera_viewport_test.dart`。**

2. **页位图缓存的"独立句柄"契约**（`page_image_cache.dart:14-25,26-91`）。
   - 按**字节数** LRU 淘汰（`maxBytes=320MB`），不是按页数（1x 缓 16 页、4x 自动只剩 1 页，避免 OOM）。
   - **single-flight**：在途渲染 `_inflight` 存的是缓存原图，所有调用方等到后各自 `clone()`，**绝不返回同一个 `ui.Image` 实例**。
   - **clone 契约**：`obtain()` 返回独立句柄，调用方负责 `dispose()`；缓存始终持原图。破坏这条 → 旧实现里 `prefetch` 把原图当结果返回，`obtain` 撞上时拿到原图，PageLayer 离开可见集 `dispose()` 了它 → 缓存里留下"已销毁的图" → 翻回来显示不出来。**回归 `test/page_image_cache_test.dart`。**
   - **运动期间暂停淘汰**：`deferEviction` 滑动时不淘汰，停手再 trim，避免每帧纹理 churn（单帧 30ms 顿挫）。

3. **夜读 duotone 的 `ColorFilter.matrix` 单位陷阱**（`domain/reader/night_tint.dart:51-101`，**REQ-15 红线**）。
   - 输入通道与第 5 列偏移都是 **0..255 字节值**，不是 0..1 归一化。
   - `out_255 = m0·R255 + m1·G255 + m2·B255 + m4`，系数无量纲，但**偏移必须 ×255**（见 `_buildMatrix` 里 `_inkR*255` 等）。旧实现把归一化 ink≈0.91 当偏移 → 白纸算成约 −207 钳到 0 → 整页死黑。
   - **笔迹层是兄弟节点，永不吃这个滤镜**（`night_tint.dart:20`）：`ColorFilter` 只作用背景层，ink 层必须作为 sibling 而非其子节点，否则夜读下笔迹也被 duotone 化。

4. **`RepaintBoundary` 分层**（`page_layer.dart:334-336`）：`PaperEffect` + `RepaintBoundary(child: InkLayer(...))`。写字的每一帧只重画"正在写的那一笔"，不是整页。

5. **SIF 解码离主线程**：笔迹解码较重，建议在 Isolate 执行（避免大页卡顿）。

6. **`cacheWidth` 解码约束（已知风险）**：部分大图（书架/收藏列表）未约束 `cacheWidth`，仅 `profile_header.dart` 正确。跨平台需统一用 `cacheWidth` 限制解码内存，否则大图 OOM。

## 13. 平台移植改造清单（iOS / Desktop / Web）

> 按"改动量 / 风险"排序。凡标 ⚠️ 的是硬替换点。

### 13.1 Web —— 风险最高

| 改造项 | 现状（Android） | Web 替换方案 |
|---|---|---|
| ⚠️ PDF 渲染 | pdfrx（pdfium 原生） | `pdf.js`（WASM）或后端渲染成图；`ui.Image` 缓存体系整个重做（`PageImageCache` 直接依赖 `dart:ui`） |
| ⚠️ 手写识别 | ML Kit（GMS） | 服务端 OCR / 前端 WASM 识别；或先禁用"识别"功能，仅保留手写笔迹 |

| 改造项 | 替换方案 |
|---|---|
| ⚠️ 手写识别 | `PencilKit` / `Vision` / 自建模型；首次下载逻辑换成本地打包或 on-device |

| 改造项 | 替换方案 |
|---|---|
| ⚠️ 手写识别 | 桌面一般无触屏笔；可保留手写笔迹存储（SIF 复用），识别走"导入图片 OCR"或服务端 |

| 窗口/权限 | 无相册概念，导出落 `Downloads/` 即可 |

### 13.4 跨平台通用不改的（复用）

- `domain/` 全部纯 Dart：**SIF 编解码、切题/覆盖层、批改模型、夜读 duotone 数学、几何、记录统计**。

- 分层约束（`architecture_test.dart`）在任意平台都成立。

### 13.5 移植落地顺序建议

1. **先搬 `domain/` + `infra/db` + `infra/vault` 的纯 Dart 部分**：用 CI 跑通现有 `test/`（`architecture_test`、`sif`、`region_*`、`grading_*`、`records_*`、`favorite_*`），保证数据契约零回归。
2. **替换 `infra/pdf` + `infra/ocr` + `infra/ai` 的平台后端**：选 Web 则 pdf.js + 服务端 OCR/识别 + `fetch`；选 iOS/桌面则对应原生封装。
3. **重写 MethodChannel 5 方法**为新平台的落盘/重启/设备信息实现（参见 §10.1 表）。
4. **`ui/reader` 渲染层复核**：`camera_viewport` 无界 Positioned、`PageImageCache` 克隆/LRU/单飞、`ColorFilter.matrix ×255`、ink 与滤镜层 sibling 关系——逐条在目标平台真机/浏览器验证。

## 15. 关键经验与组件坑（移植易踩）

- **`ColorFilter.matrix` 偏移 ×255**（夜读死黑事故根源，§8.2 #3）。
- **CameraViewport 无界 Positioned**（滚动模式只能写第一页上半屏，§8.2 #1）。
- **PageImageCache 克隆/单飞**（缓存里留已销毁图 → 翻页不显，§8.2 #2）。
- **SIF 小端 + 0.1pt 定点**（读成 big-endian/整数 pt 会整页缩放错误，§6.1）。
- **切题只读自动结果 + 覆盖层**（直接改 `regions.v1.json` → 重切全丢，§6.2）。
- **灰虚线 = level 1 大题容器**；"加题"在 level 1 上走 `ConfirmQuestionCorrection`（只 level 1→2，题号/位置/id 全不变）；走 `AddQuestionCorrection`+`DeleteCorrection` 会让题号跳到末尾、违反意图（§6.2）。
- **`pending ≠ 错`**：判题三色点语义，UI/文案务必区分。
- **`dispose()` 内不可 `ref.read`**（Riverpod 3）。
- **`AnimatedSlide` 出屏仍在语义树** → 用 `ExcludeSemantics`。
- **M3 `inverseSurface` 暗色下是浅色**（SnackBar 变白条）等 Material 细节。
- **`showModalBottomSheet` 显式背景色 + 顶部圆角**；全屏弹层用不透明 `Scaffold`。
- **sqflite `insert(ignore)` 冲突仍返回旧 rowid** → 不能判断"是否新插入"（062 踩过）；Android 8 的 SQLite 3.19 无 `ON CONFLICT DO UPDATE`。
