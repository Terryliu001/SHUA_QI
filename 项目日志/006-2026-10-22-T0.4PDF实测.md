## 3. 三个必须做决定的技术发现

### 3.1 `PdfSource.renderPage` 返回 `Uint8List` 是错的

| 操作 | 耗时 |
|---|---|
| pdfium 渲染一页 | **3–12 ms** |
| 转成 PNG | **120–135 ms** |
| 合计（契约要求） | 120–138 ms |

**PNG 编码占了 97%。** 屏上显示根本不需要 PNG——需要的是 `ui.Image`（或 `RawImage` 直出）。
按现在的契约，每次翻页都要多付 100ms+ 与 400KB 内存，200ms 的翻页预算被凭空砍掉一半。

**建议**：把 `renderPage` 拆成两个：
- `Future<ui.Image> renderImage(int index, {required double maxEdgePx})` —— 屏显走这条
- `Future<Uint8List> renderPng(...)` —— 只给导出/OCR 裁图用

这属于改 §7 签名。按 00-总览 §8 的规矩，**要先改 `项目具体规划formachine.md`，再改代码**，我不能自己动。**需要你拍板。**

### 3.2 400% 缩放必须分块渲染

`maxEdgePx = 页长 × 4` 只等于 **4 像素/pt**，而这台机器 400% 观感需要 **4 × dpr = 10 像素/pt**。
按 10 px/pt 整页渲染：

```text
595.3 × 10 = 5953 px 宽
841.9 × 10 = 8419 px 高
≈ 5000 万像素 ≈ 191 MB 位图/页
```

**一页就能把 4GB 设备打爆。** 实测一块 200×120pt 只要 **4ms**、135KB，
所以正确做法是**按视口分块渲染 + 分块缓存**（tile），而不是"整页高分辨率位图"。
这条要在 T1.5 之前定下来，否则阅读器会写成 191MB 的炸弹。

### 3.3 pdfrx 不给字号，且片段粒度太碎

- `PdfPageTextFragment` 只有 `bounds`（`PdfRect`，**PDF 原生 y 向上**），**没有 `fontSize`**。
  目前 `TextRun.fontSize` 用**片段高度**近似——从高度分布看能分清晰地区分 5 档（10/11/12/13/29pt），
  近似是可用的，但它≠字号：多行片段的高度会偏大。
- 片段是**碎**的：真实卷里出现 `"1"`（6×15.2）与 `"."` 分开、空片段 `""`、
  `"Synthetic"`/`"Exam"`/`"Paper"` 各自成片段。**题号 `1.` 会被切成两段**，
  直接对单片段跑 `^\s*(\d{1,3})\s*[.、．]` 会漏检（实测 11/490 命中，纯属碰巧有合并好的）。

**结论**：§6.1 的 L1 必须改成两步——
1. **先按 y 聚合行**（同一 y 带内的片段按 x 排序拼接成"行文本"）；
2. **再在行文本上跑题号正则与高度统计**。
并且层级判定用「行内主字高跳变 ≥1.15x」替代「字号跳变」。

## 4. 传输通路的坑（写下来省下次的时间）

OPPO 这台机器上把文件送进应用内部目录，连着踩了三层：

1. `/sdcard/Android/data/<pkg>/files/` 用 `adb push` 能写，**但目录若是 shell 建的，应用读不了**
   （`PathAccessException ... errno = 13`）——scoped storage 按目录所有者判权限。
2. `run-as pkg sh -c 'cat > file'` **被 SELinux 拒**（`can't create ... Permission denied`），
   虽然目录是 `drwxrwx--x`、属主就是应用自己。
3. 可行写法：**写由子进程完成**，不用 sh 的重定向——
   ```bash
   base64 paper.pdf | adb shell -T "run-as com.shuaqi.shuaqi sh -c 'base64 -d | dd of=/data/user/0/com.shuaqi.shuaqi/files/paper.pdf 2>/dev/null'"
   ```
   取回反向用 `adb exec-out`（`adb shell` 会加 CR 把 base64 弄坏）：
   ```bash
   adb exec-out run-as com.shuaqi.shuaqi base64 /data/.../files/x.png | tr -d '\r' | base64 -d > x.png
   ```

> 这三条都只在"调试期手工塞文件"时需要。产品走 `path_provider` + 应用自己创建目录，不会遇到。
