## 1. 定位（先定清楚，再动手）

用户口径：**这里是"全部的答题情况看板"，不是个人主页**。
- 页首是个人空间（"我"），主体是统计（"练得怎么样"），出口是时间线（"哪几张卷、哪几道题"）。
- 与另外两个 tab 的分工必须清晰，否则三页会越长越像：
  | tab | 回答的问题 | 视觉主角 |
  |---|---|---|
  | 书架 | 我有哪些卷、怎么管 | 封面大图卡 |
  | 收藏夹 | 我挑出的题在哪、怎么组 | 题面缩略图卡 |
  | **记录** | **我最近怎么练的** | **日期轴 + 逐题判定色带 + 热力格子** |

## 2. 数据层（T9.1）：为什么必须新建事件表

先查了真机数据，三条"反推"全部不成立：
- `session` 每卷只有一条 draft（4 次打开仍 2 行），拿不到"哪天做了几题"；
- `grading.v1.json` 的 `at` 是**整批改卷**的时间戳（真机 16 题同一毫秒），当"作答时间"会凭空造出 16 道题；
- `answer_sheet.v1.json` 的 `updated_at` 只覆盖"调过框/识别过"的题。

于是 **v7 `answer_log`**（`infra/db/migrations.dart`）：

```sql
answer_log(id INTEGER PK AUTOINCREMENT, at INTEGER, day TEXT,   -- day = 本地 yyyy-MM-dd
           workbook_id, workbook_title, question_id, label, kind,
           page_index, source, verdict, hits)
UNIQUE(question_id, day)   -- 同一天同一题只有一行
INDEX(day) / INDEX(workbook_id)
```

四条设计口径：
1. **不设外键**：卷删了"我做过 5 道题"仍然成立；卷名/题号/题型在写入时抄一份快照，
   显示时活库优先（改名能同步），卷没了才回落快照并标「原卷已删」。
2. **`UNIQUE(question_id, day)`**：热力图数的是**题目数**，不是动作数；
   动作次数累加在 `hits`（本次 UI 不展示它，避免被读成"刷了两遍"）。
3. **`day` 用本地日期**：按 UTC 分桶会让晚上 8 点以后做的题掉到第二天。
4. 记录是**旁路**：`RecordService` 吞掉所有异常并 `debugPrint`，写不进去绝不影响落笔/判题。

## 3. 打点与回填

| 触发 | 落点 | source |
|---|---|---|
| 答题卡落笔/保存/切题/系统返回 | `InkEditController._scheduleSave`（每题每天只写一次库） | `ink` |
| 判出一个结论（三色手改/一键改卷/AI 判） | `GradingController.onGraded` 回调（6 个调用点收敛成 1 个） | `grade` |
| 收藏重刷页落笔 | 同上，`fav:` session 回表查来源卷/题 | `redo` |

回填（`app/records/record_backfill.dart`，口径版本 `kBackfillVersion='2'`）只认三类证据：
`answer_sheet.updated_at`、`sessions/*/answers/*.sif` 的 mtime、`grading` 里 `verdict != none` 的 `at`。
批量改卷写下的 `none` **不算**（否则一天会多出几十道题）。真机回填出 1 条（线性代数第 5 题，判错）。

> 版本号而不是布尔值：修完 bug 后要让已装机的库重跑一次（`seed` 幂等，只补更完整的结论）。

## 4. 三个坑（都值得记住）

1. **`insert(conflictAlgorithm: ignore)` 的返回值不能用来判断"是否新插入"**。
   sqflite 的 `insert` 返回 `last_insert_rowid()`，冲突被忽略时不清零，仍返回上一行 id。
   第一版据此 `if (inserted != 0) return;` 直接丢掉了所有"更新"分支——真机上表现为
   **回填的判题结论消失**（只有 `save`、`verdict` 还是 `none`）。改成"先查后写 + 唯一索引兜并发"。
2. **Android 8 的 SQLite 是 3.19，不支持 `ON CONFLICT DO UPDATE`**（要 3.24+）。minSdk 26，所以永远别写 upsert。
3. **`state/` 的任何文件都会把 pdfrx 拖进宿主测试链**（`ink_providers → app/bootstrap → import_workbook → pdfrx_source`）。
   所以"落笔即记录"的**判据**被抽到 `domain/records/answer_log.dart`（`answerQuestionIdOf` /
   `answerRecordKeyOf`）才测得动；`session id` 编解码也一并挪到 `domain/ink/ink_session_id.dart`
   （`state/ink_providers.dart` 只 `export`，老导入不用改）。

## 5. UI（T9.2–T9.4）

- **个人空间**（`ui/records/profile_header.dart`）：封面图（`cacheWidth` 上限 1600 解码，不重编码）
  + 由下往上暗渐变 + 78dp 圆形头像 + 昵称/格言；没有封面时跟随主题底色、文字用主题色。
  ⋯ 菜单：设置/更换头像、设置/更换背景、编辑昵称与格言、移除头像、恢复默认底色。
  图片原样收编进 `vault/profile/avatar.img|cover.img`（`ProfileStore`）。
- **热力图**（`records_heatmap.dart`）：26 周 × 7，右端对齐本周、周一起；一个 `CustomPainter`
  画 182 格（不是 182 个 widget），点击用坐标换算。档位 0 / 1–2 / 3–5 / 6–9 / 10–15 / 16+（`ShqHeat` 绿阶）。
- **词云**（`records_word_cloud.dart`）：按科目（文件夹）默认、可切题型；权重
  `题数×1 + 卷数×3`，字号按 `sqrt(weight/max)` 归一；阿基米德螺旋 + 固定步长、无随机；
  布局缓存按（尺寸/文字缩放/配色/词表）命中，旋转或改字号才重排。**只画不点**（点一个词跳哪都是猜的）。
- **数据看板**（`records_stats_board.dart`）：近 7/30 天可切；题数 / 卷数 / 正确率（只算已判题，
  没判过显示「—」而不是 0%）；判定分布条 + 连续打卡 + 累计；底部是时间线入口。
- **时间线**（`timeline_page.dart`）：左缘日期轴；**按试卷**=一天一张卷卡（逐题判定色带 + 题数 + 时间范围），
  **按题目**=卷名小标 + 逐题行；点卡精确回原卷（`ReaderRouteArgs.initialQuestionId`），
  原卷已删则置灰并提示；长按：卷卡=重命名/移动文件夹/去书架（复用书架那套），题目卡=在卷中定位/复制题号。

## 8. 已知限制

1. 「落笔即记录」的判据有单测，但**端到端没有真机写入证据**：`adb input` 注入的是触摸，
   答题卡把单指触摸判为"拖动查看"，不会落笔。等用户用笔在答题卡写一题即可确认（DB 里
   该题 `source=ink`）。
2. 长按题目卡的「收藏」未做（收藏要抓题面/作答/AI 快照，属于收藏夹的用例，不在记录页重复实现）。
3. 词云没有"按知识点"维度：`answer_log` 不含知识点，跨表 join 会漏掉未收藏的题，宁可先不给。
4. 封面不做裁剪框，直接 `BoxFit.cover`；长条形人物照可能被裁到脸。
5. `hits` 只入库不展示（语义容易被读成"做了几遍"）。
