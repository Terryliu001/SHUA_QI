## 1. 先量化，再动手（T2.5 的性能 HUD 顺带落地）

新增 `ui/reader/debug_hud.dart`：`SchedulerBinding.addTimingsCallback` 采集最近 60 帧的
**build / raster 中位耗时、超 60Hz 预算占比、最差帧**；同时显示当前页笔画/点数、
位图缓存占用与页数。设置页「开发」分组可开关（`kReleaseMode` 里连入口都没有）。

改动前实测（OPPO OPD2601，profile，100%，4 页卷）：

| 场景 | raster 中位 | 超预算帧 | 最差帧 | 位图缓存 |
|---|---|---|---|---|
| 打开后第一次滑动 | 4.5ms | 2% | **30.7ms** | **146MB / 3 页** |
| 写过 8 笔后再滑 | 2.5ms | 0% | 4.6ms | **194MB / 4 页**（≈200MB 上限） |

结论：帧率本身不差，**顿挫来自"边滑边淘汰纹理"**（一页 A4 在 3000px 宽下 51MB，
4 页就顶到 200MB 上限，于是每进一页都要 dispose 旧纹理 + 上传新纹理），
以及"打开文档到第一次滑动之间完全没有预热"。

## 2. 滚动跟手性：改了四处

| 改动 | 为什么 |
|---|---|
| `PageImageCache` 上限 200MB → 320MB | 工作集（视口 2 页 + 预热 1 页 + 刚离开 1 页）正好 204MB，卡在上限上就是**每次都churn** |
| 新增 `deferEviction`：手势/甩动期间**暂停淘汰**，停手后一帧 `trim()` | 滑动中淘汰 = 每页重新渲染 + 重新上传 51MB 纹理（30.7ms 的来源） |
| `build()` 里也预热下一页（原来只在手势回调里预热） | 打开卷后用户还没碰屏幕时就把下一页烘好，第一次滑动不再是"现渲染" |
| **笔优先门槛 800ms → 200ms + 新增 `_penDown`** | 原规则"笔最近 800ms 出现过就冻结单指滑动"的真实副作用是：**写完抬笔后 0.8 秒内滑页面毫无反应**，这大概率就是"不跟手"的主观来源。现在：笔压着屏幕时一律冻结（真正的手掌搭屏场景），笔抬起来 200ms 后立刻可滑；且手势"从手掌开始"的那一整段仍然冻结、不甩动 |

另外给墨迹层补了 `RepaintBoundary`（页面级 + 已提交/活动双层各一层）：
相机矩阵每帧变化时，`RenderTransform` 会把整棵非边界子树重新 paint，
**写满一页的页签在滚动时每帧都会重画所有笔画**（`getBounds()` 也要重算）。
滚动帧数的**同条件复测留到下次接平板**（改动前基线已记在 §1）。

## 3. 三个真 bug（都是排查过程中掉出来的，价值比功能大）

### 3.1 水平/竖直笔画根本画不出来（T2.2 起就存在的隐形 bug）

`InkRibbon.draw()` 用 `path.getBounds().isEmpty` 判断"这一档有没有内容"。
而**完美水平线**的包围盒高度是 0 → `Rect.isEmpty == true` → 整笔被跳过。
用户视角就是"横着画一条线没反应，斜着才行"（下划线、表格线全中招）。

修法：每档一个 `_levelUsed` 布尔（顺带省掉每帧对 24 条 Path 调 `getBounds()` 的
O(点数) 开销）。回归测试：三种笔刷各画一条水平线，必须至少有一个档位被使用。

### 3.2 荧光笔落笔先黑、抬笔才变荧光

根因是**两层各自拼一半参数**：已提交层知道荧光笔要 `multiply` + 荧光色，
而活动层（正在写的那一笔）只传了 `style` 和**墨色**，`blendMode` 用默认 `srcOver`。

修法不是补参数，而是**只留一条构造路径**：新增 `InkBrushSpec`
（样式 + 颜色 + 粗细 + 混合模式，一次算完），活动层与已提交层都从它取。
真机验证：慢速画荧光笔，中途抓帧与抬笔后抓帧的像素颜色**完全一致**（245,230,174）。

### 3.3 荧光笔在合成层里一个像素都画不出来（`multiply` 的坑）

给墨迹层加 `RepaintBoundary` 后，荧光笔整笔消失（日志显示 360 个点已提交、已绘制，
像素扫描 0 个黄色像素）。原因是 `multiply`/`screen` 这类**依赖目标像素**的混合模式，
在"透明背景的合成层"里算不出可见结果。

修法：荧光笔改为**半透明 + srcOver**——视觉上就是一道透光色带，下方文字仍清楚
（REQ-03 要的是"文字可读"，不是"必须乘算"），而且与合成层无关，亮纸/夜读纸表现一致。
夜读纸上实测：黄条清晰、纸下文字可读。

### 3.4（附带）重构时漏了 `paint.color`

`InkRibbon._paintFor` 重写后忘了 `..color = spec.color`，`Paint` 默认不透明纯黑，
于是**所有颜色都画成黑**。像素扫描发现笔画是 `(0,0,0)`（调色板的墨黑是 `#14161A`）。
现在有单测直接断言 `Paint` 上的颜色/混合（几何断言永远抓不到这类问题）。

## 4. 笔刷：颜色 + 粗细（数据契约变更，为 T2.4 一次写终版）

| 项 | 决定 |
|---|---|
| 颜色 | 语义 6 色（墨黑/蓝/红/绿/橙/紫）+ 荧光笔专用 4 色（黄/绿/粉/蓝） |
| 暗纸 | 每个索引都有"夜读版"（同色相提亮），切到夜读时旧笔迹**自动变亮**（缓存按纸重建一次） |
| 粗细 | 每支笔 3 档：钢笔 0.8–2.4 / 1.2–3.2 / 1.8–4.4；圆珠笔 1.6/2.4/3.2；荧光笔 12/18/24（规格值） |
| 入库 | `InkStroke` 增 `colorIndex` + `widthLevel` 两个字段 → SIF v1 的 stroke 头变成 `style|color|width|flags|nPoints|bbox|t0`（每笔 +2 字节，5000 笔 +10KB，可忽略） |
| 每支笔记住自己的色/粗 | 切钢笔↔荧光笔不会丢设置，落盘格式 `tool:color:width;…`（旧格式 `pen` 仍可读） |

> 这一项**必须在 T2.4 之前定**：SIF 一旦按旧格式写出去，以后加颜色就要写迁移。

## 5. 工具条形态：圆形浮钮 + 设置里可切顶栏（用户拍板）

- **默认（浮钮）**：右下角 56dp 圆钮，常态只有"当前笔图标 + 当前颜色小点"，
  点一下向上展开面板（工具 / 颜色 / 粗细），再点收起。阅读时几乎不占正文。
- **固定（顶栏）**：设置 →「书写」→ 工具条固定在顶栏，变成 AppBar 底部一条 52dp 工具带，
  三段并排、零展开（窄屏也放得下，标题不会被挤没）。
- **撤销/重做搬到 AppBar**：它们是文档动作、频率高，不该藏在工具栏两层里；
  按"当前页"取 `canUndo/canRedo`，没得撤时是灰的。

## 8. 已知限制

| 限制 | 说明 |
|---|---|
| 荧光笔不再与下方墨迹"乘算" | 见 §3.3：合成层里 `multiply` 不可用。现在是半透明覆盖，视觉接近，文字可读 |
| 每支笔的颜色/粗细是**全局**的（不分卷） | 与原有笔刷语义一致；规格里"每篇文档记住上次笔型"的那一条还没做（T2.2 尾项） |
| 换纸会重建整层笔迹缓存 | 一次性 O(笔画数)，用户手动动作，可接受 |
| 保存（SIF）还没做 | **T2.4，下一轮**；在那之前杀进程仍会丢笔 |
