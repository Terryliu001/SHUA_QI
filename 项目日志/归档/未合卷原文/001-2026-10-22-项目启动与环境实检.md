## 5. 未决问题（需要你拍板）

### Q-01 compileSdk 怎么定（**本轮最重要**）

你选的是「不补装，就用 35」。但实检发现一个硬事实：

> **本机 `platforms/` 里既没有 36，也没有 35，只有 37.0。**
> 所以「不补装」和「用 35」这两件事**不能同时成立** —— 把 `compileSdk` 钉到 35，同样需要 `platforms;android-35` 这个包。

三条可行路径：

| 方案 | 具体操作 | 下载 | 风险 | 倾向 |
|---|---|---|---|---|
| **A：装 36** | `sdkmanager "platforms;android-36"` | 数十 MB 量级（未实测） | 与 Flutter 3.47.6 模板默认值一致，插件兼容性风险最低 | ★ **推荐** |
| **B：装 35 + 钉 `compileSdk=35`** | 装 `platforms;android-35`，改 `main\android\app\build.gradle.kts` 的 `compileSdk` | 与 A 同一量级，**并没有省下载** | 低于 Flutter 测试基线；`pdfrx`（含原生）、ML Kit、`onnxruntime` 若声明 `compileSdk 35+` 需逐个确认 | 次选 |
| **C：不装，`compileSdk=37`** | 直接用现有 `android-37.0` | 0 | Flutter 3.47.6 未对 37 做测试，可能有插件 API 变更警告；**且 AGP 在许可已接受时可能构建期自动下载缺失平台**，所谓「不下」并不可控 | 不推荐，但可作为尝试 |

我的建议：**走 A**。理由是新装的 Android 包不影响运行期行为，只影响编译期头文件版本，而 A 是唯一与 Flutter 官方模板对齐的选择；B 省不下下载量却引入插件兼容不确定性，性价比最低。
若你坚持零下载，那就只能走 C，我会把它记为「显式偏离规格」，并在 `build.gradle.kts` 里写注释说明原因。

### Q-02 是否现在就 `git init`
规格 §10 有提交规范（`type(scope): 一句话`），但没有明确 `.git` 放在 `SHUAQI_project\` 还是 `SHUAQI_project\main\`。
倾向：**放在工作区根**（`SHUAQI_project\.git`），这样 `项目日志\` 和 `main\` 一起纳入版本管理，日志能和代码同一次提交。

### Q-03 `assets/models` / `demo_assets` 何时建
模型（引擎 B/C 的 ONNX）体积大、且 `T0.5` 才产出。倾向：`T0.1` 先建空目录并在 `.gitignore` 里排除 `*.onnx`（避免把几十 MB 二进制塞进仓库），等 T0.5 定了再决定是否用 Git LFS 或外部路径。

## 7. 协作规则（写给未来每一次会话）

1. **一次只做一个 `T-x.y`**，绝不整周打包做。
2. **先出改动计划**（文件清单 + 每个文件改什么 + 是否新增依赖 + 风险），确认后才写码。
3. **所有下载 / 联网 / 拉包 / 连设备，先请示**。包括：`sdkmanager`、`pub get`、首次 Gradle 构建、模型下载。
4. **文档目录只读**：`D:\SHUAQI_project_dev\` 不改、不在里面执行任何 flutter 命令。
5. 每个任务结束必给：`flutter analyze` 结果 + DoD 逐条复现 + **3 步手测方法**。
6. **不新增白名单外依赖**（白名单：`flutter_riverpod`、`pdfrx`、`sqflite`、`path_provider`、`path`、`file_picker`、`google_mlkit_digital_ink_recognition`、`onnxruntime`、`flutter_math_fork`、`flutter_markdown`、`flutter_secure_storage`、`http`、`archive`、`crypto`、`share_plus`、`device_info_plus`）。
7. **不确定就说不确定**：编造 API / 编造包名是红线。
8. 性能数字一律标注设备与模式；**debug 模式的帧率/延迟数据不得作为验收依据**。

## 8. 规格要点速记（防走偏，7 条公理压成一行一条）

| 公理 | 一句话 | 最容易违规的地方 |
|---|---|---|
| INV-01 | 落笔路径只允许坐标变换、点追加、脏区标记、增量绘制 | `onPointerMove` 里 `await` / `setState` / 每次落盘 |
| INV-02 | 识别永远异步，可失败、可丢弃、可重试 | 阻塞式「正在识别」弹窗；回写不校验 `revision` |
| INV-03 | 归属靠纯几何，同输入两次结果逐条一致 | 把归属丢给模型或随机启发式 |
| INV-04 | 离线下导入/书写/识别/判题/导出全部可用 | 把 BYOK 做成启动前置 |
| INV-05 | `conf<0.65 → unclear`；无答案 `→ ungraded`；解答题不判分 | 出现「错误/不得分/扣分/你错了」 |
| INV-06 | 每个判题结果带 `reason`+`evidence`；手工编辑不被覆盖 | 「系统判错但看不到依据」的路径 |
| INV-07 | 公式必产出 `formula_item` 或退裁图；**未闭合 `$…$` 绝不交给渲染器** | 渲染失败显示空白；把公式发在线服务 |

**三条红线**（发布前手测）：笔迹不丢 · 书写不卡 · 数据可导出。
