## 1. AI 归纳进「点亮知识点」

`多选 → 点亮知识点` 弹窗底部新增 **「AI 归纳这些题…」**：
- 关掉标签选择弹窗，直接对**当前选中的题**跑归纳；
- 走同一套「确认清单 → AI 请求 → 结果确认 → 写库」，成功后自动退出多选；
- 与标签条上的「AI 归纳」共用 `_runAiTag` / `_reviewAiTags`，没有第二套逻辑。

真机：选 1 题 → 点亮知识点 → AI 归纳这些题 → 结果确认（1 题）（截图 `06`）。

## 2. 看题页编辑知识点

- 元信息卡里的标签后面常驻 **「＋ 添加知识点」/「编辑」** chip，点开标签多选编辑器（已有标签 + 新建 + 清空=未归纳）；
- 右上角 **实心星** 点开菜单：**编辑知识点**（带当前标签摘要）/ **取消收藏**（只删快照，写明不影响原卷）；
- 保存后立即刷新本页 + 收藏夹，并更新 `favorite.last_tag_at`（算一次归纳）。

真机：看题页 → 添加知识点 → 选已有标签 → 保存；再清空 → 保存为未归纳（DB 核对通过）。

## 3. AI 归纳结果先确认

新弹窗「AI 归纳结果」：
- 每题一行：勾选框 + `第 X 题 · 卷名` + 标签 `InputChip`（可删）+「＋ 标签」；
- 顶部说明「可以删改标签，或取消勾选整题不采用」；
- 底部「写入 N 题」随勾选/删标签实时变；取消 = 不写任何标签；
- 只对确认后的、仍非空的题写库；写成功才更新归纳时钟。

真机：5 题归纳 → 取消勾选 4 题 → 「写入 1 题」→ DB 仅该题得到标签；随后在看题页清空（截图 `05/08`）。

## 4. 「未返回可用标签」排查与修复

用户自接接口时最可能踩的四个坑，本轮都做了兼容/收敛：

| 可能原因 | 本轮处理 |
|---|---|
| 模型没按 `{"tags":{id:[...]}}` 返回：包了 `results`/`data`/`items`，或直接返回数组 | `parseKnowledgeTagResponse` 支持这些包装与顶层数组；`extractJsonArray` 新增 |
| 模型把 26 位 ULID 抄错/改大小写/换成题号 | 提示词改为**短键 `q1..qN`**（仍附真实 id）；解析后 `resolveKnowledgeTagKeys` 按 qN / 原 id / 「第 3 题」/ 纯数字题号映射回收藏 id |
| 完全不是 JSON（分行写「q1：极限、函数」） | 新增 `parseKnowledgeTagLines` 兜底 |
| 题太多导致 JSON 被 max_tokens 截断 | 每批最多 **20 题**分批请求、`max_tokens` 提到 **2048**；仍解析失败时错误信息带**原始返回开头 120 字** |
| 推理模型把内容放 `reasoning_content` | content 为空时再用 reasoning 解析一次 |
| 模型把结构倒过来（标签当键、题号当值） | `resolveKnowledgeTagKeys` 支持 `{"极限":["q1"]}` 反向结构 |

仍然失败时，新的提示会显示「原始返回开头：…」，可据此判断是模型能力（换 JSON 稳定的模型）还是网关（返回了 HTML/错误 JSON）。

> 注意：本轮只在假 SSE 与本机解析单测上验证；**用户的具体端点/模型没有复测**。若仍报错，把那句「原始返回开头」发来即可定位。

## 5. 收藏按钮反馈 + 看题页星标

- 题目面板单题动作：`收藏`（空心星）↔ `已收藏`（实心星、tertiary 色），`AnimatedSwitcher` 缩放过渡；再点即取消；
- 多选批量条：选中的题**全部已收藏**时显示实心星「已收藏」；
- 面板通过 `favoriteQuestionIds`（阅读器 watch `favoritesProvider`）拿状态，收藏/取消后立刻刷新；
- 看题页右上角由「取消收藏图标」改为**实心星 + 菜单**（见 §2）。

真机：面板选中未收藏题 → 收藏 → 立即「已收藏」实心星；再点 → 恢复「收藏」空心星（截图 `07`）。
