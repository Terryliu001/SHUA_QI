## 1. 这轮为什么这么改

上一轮把 AI 对话/补答案/判题接进来了，但真用起来有六个明显不顺：

1. 附件图在会话最顶上，用户输入时看不到自己「这次要发哪几张」；
2. 面板能拖宽，AI 气泡却仍按 320dp 的窄宽度排版，右边一大片空白；
3. 判题只能一题一题点，卷子有 10+ 题时不可用；
4. 推理模型（DeepSeek reasoner 等）的 `reasoning_content` 被丢掉，用户只看到最终答案；
5. 公式渲染有了，但编程/代码输出没有代码块，`$` 还会被当公式；
6. 答案卡上的「AI 补答案」和问 AI 面板的「先做一遍」重复，且容易误导成「AI 答案已确认」。

用户还追加了一条：把 token 统计放进设置，能看使用记录。于是这轮把这七件事一起收掉。

## 5. 批量 AI 判题

### 5.1 入口

- 题目面板工具行第三颗按钮 `AI 判`，和「多选」「改卷」同排；
- 进行中显示 `AI done/total`，并禁用「改卷」避免并发改同一份 grading；
- 只在有 `onGradeAi` 回调时出现（测试/预览页不接就不显示）。

### 5.2 流程（`reader_page._gradeAllWithAi`）

1. 先跑一遍本地规则 `_judgeOne`，`applyAuto` 立即落能判的题；
2. 收集待判：
   - `pending`（本地拿不准）；
   - `none` 但**有作答**（没有参考答案的主观题，也交给模型）；
3. 若没有待判：提示「没有待判的题：对 X · 错 Y · 未判 Z」；
4. 若 AI 未配置：提示「本地能判的已判完；还有 N 道待判，配置 AI 后可自动判」；
5. 否则逐题串行：
   - 取 `_aiAttachmentsOf`（题面 + 作答图）；
   - 没有作答文本/作答图 → 跳过，不浪费 token；
   - `AiService.grade` → `GradingController.applyAi`（**不覆盖 manual**）；
   - 每题完成 `_aiGradeDone++`；
6. 最后提示：对 / 待判 / 错 / 未判 + 跳过数。

### 5.3 口径

- **不静默扣 token**：必须用户点「AI 判」；
- **不覆盖手改**：`applyAi` 只写非 manual；
- **逐题串行**：避免 429 和成本失控，进度可见；
- **失败不中断整批**：单题异常算 skip；
- **只判有作答的题**：空白作答不发给模型。

真机（假 SSE）：工具行点「AI 判」→ 模型返回 correct → 状态栏从 `对0 未判14` 变 `对1 未判13`，用量页新增一条「判题」。

## 6. Token 用量

### 6.1 为什么进表

用量是**跨卷**的 app 级数据，且要按时间查最近记录；放 `setting` 里塞 JSON 会越来越难查。
新增 DB **v5**：

```sql
CREATE TABLE llm_usage(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  at INTEGER NOT NULL,
  model TEXT NOT NULL DEFAULT '',
  task TEXT NOT NULL DEFAULT '',
  tokens_in INTEGER NOT NULL DEFAULT 0,
  tokens_out INTEGER NOT NULL DEFAULT 0,
  estimated INTEGER NOT NULL DEFAULT 0,
  ok INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX idx_llm_usage_at ON llm_usage(at);
```

只追加迁移，不改旧表；真机从 v4 原地升级成功，旧卷/旧设置都在。

### 6.2 怎么拿到 token

- 非流式：`LlmResult.tokensIn/Out`（已有）。
- 流式：
  - 请求带 `stream_options.include_usage = true`（`LlmRequest.includeUsage`）；
  - 末尾 `choices:[]` + `usage` 也能解析；
  - 兼容端点返回 400 且提到 `stream_options` / `include_usage` / `unknown field` 时，**自动去掉该字段重试一次**；
  - 端点完全不回 usage → 按字符估算：
    - CJK 每字约 1 token；
    - ASCII 每 4 字符约 1 token；
    - 每张图约 600 token（粗估，只用于占位）。
- `estimated=1` 的记录在 UI 统一加 `≈`，不把估算伪装成真实。
- 记账覆盖：`chat` / `solve` / `grade` / `test`；失败也记一行 `ok=0`，便于看失败调用。

### 6.3 设置页

- 「AI 分析」区新增「AI 用量」行：
  - 未配置/无记录：`还没有调用记录`；
  - 有记录：`累计 N 次 · 输入 X · 输出 Y · 含估算`。
- 点开 `AiUsageSheet`：
  - 三张指标卡：调用次数 / 输入 tokens / 输出 tokens；
  - 合计 + 估算次数 + 失败次数说明；
  - 最近 20 条：时间、任务（对话/先做一遍/判题/连接测试）、模型、`≈`、in/out、失败红边；
  - 刷新 + 清空（二次确认；只删统计，不删对话/答案/判题）。
- `AiUsageService` 记完一笔通过 `onRecorded` 失效 `aiUsageProvider`；设置页常驻 `IndexedStack` 也能立刻更新。

真机：4 次调用（连接测试、2 次对话、1 次判题），2.2k 输入 / 237 输出；对话 321/87 为**真实 usage**，判题/测试带 `≈`；清空后归零。

## 10. 已知限制 / 遗留

1. **真实厂商未联调**：仍只有假 SSE；DeepSeek reasoner、Kimi、混元、智谱的真实 reasoning/usage 字段可能不同。
2. **Kimi/混元模型名是示例**：厂商会改；设置页可手改，但日志不保证长期有效。
3. **图片 token 是粗估**：每张 600；真实视觉 token 因分辨率/厂商差异很大。
4. **`stream_options` 降级靠关键词**：有的网关返回泛化 400（不含字段名），不会自动重试；这时对话会失败，但不会静默错记。
5. **批量 AI 判是串行**：没有取消按钮；卷子大时耗时/费用可见但不低。
6. **批量判只收有作答的题**：没有作答文本/答题卡笔迹的题跳过；页内书写只有当前页能便宜统计，其他页可能漏（可先开答题情况）。
7. **AI 判题不会因作答变化自动失效**：改了作答后旧 AI 结论仍在，需要重跑「AI 判」或手改。
8. **用户相册附图仍未持久化**：只随本次会话发送，重开只恢复文字。
9. **Key 仍存 `setting`**：还没换 `flutter_secure_storage`（需联网拉包，等用户确认）。
10. **代码复制没有 toast**：按钮变对勾 1.4s；系统剪贴板在部分 Android 版本会有隐私提示，不是 bug。

## 12. 补记（2026-10-25）：推理内容不显示

### 现象与证据

用户在真机上用自己的 DeepSeek Key 试了 `deepseek-chat`：

- 用量表留下 5 条真实记录：2 次连接测试失败、1 次测试成功（5/8 tokens）、2 次对话成功（444/391、884/542）；
- 回答正文正常，但**没有出现推理内容**；
- 因此这不是"客户端完全没收到响应"，而是"模型/请求/展示三者之一没把 reasoning 给出来"。

同时发现代码里三个具体问题：

1. 最终回答里的「思考过程」默认折叠，用户不点就看不到；
2. `parseSseData` / `parseChatCompletion` 只读 `delta` / `message` 里的 reasoning，部分中转把 `reasoning` 放在 choice 或顶层会丢；
3. `ChatTurn.listFromJson` 只按 `text` 非空保留，推理-only 的轮次重开后被丢掉。

另外，`deepseek-chat` 本身不是推理模型；DeepSeek 当前（2026-10）的推理模型是 `deepseek-flash` / `deepseek-v4-pro`，并支持 `thinking` / `reasoning_effort` 参数（[官方 Chat API](https://api-docs.deepseek.com/api/create-chat-completion)）。

### 修法

- **默认展开**：最终助手气泡有 reasoning/开了深度思考时，`_ThinkingBlock` 默认展开；用户可手动收起。
- **解析面加宽**：
  - `delta.reasoning_content` / `reasoning` / `thinking` / `reasoning_details`；
  - `message` 同名字段；
  - choice 层与顶层兜底；
  - reasoning 为 token 数组时读 `text` / `token` / `content`；
  - thinking-only 轮次可落盘、可恢复。
- **真的请求推理**：
  - `LlmThinkingMode`（default/enabled/disabled）；
  - 仅对 DeepSeek 端点/模型发 `thinking: {type: enabled|disabled}`；开启时加 `reasoning_effort: high`；
  - 400 且提到 `thinking` / `reasoning_effort` 时，自动去掉这两个字段重试一次；
  - 深度思考时 `max_tokens` 从 1400 提到 4096，避免推理把额度吃光。
- **引导**：
  - DeepSeek 预设模型改为 `deepseek-flash`，模型输入框加提示；
  - 没返回 reasoning 的折叠块明确写「DeepSeek 请用 deepseek-flash / deepseek-v4-pro；deepseek-chat 不是推理模型」。
