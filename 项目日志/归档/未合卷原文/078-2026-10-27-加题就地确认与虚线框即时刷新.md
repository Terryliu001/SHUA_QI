---

## 1. 现象

切题拿不准的块会画成**灰色虚线框**（可能是大题容器，也可能就是一道题）。
用户在题目面板里点这条的「加题」：

- 期望：**这一块就是这道题** → 去掉虚线、认作题目；题号不变、面板位置不变；
- 实际：面板里**新增**了一道题（题号 = 现有最大号 +1、排在列表末尾），原来的虚线容器被删掉。
  效果上"题号被改了、位置也跑了"。

另外，即使把语义改对，确认后画布上的框**不会立刻**由虚线变实线，要关一次题目面板再打开才刷新。

---

## 2. 根因（两层，缺一不可）

### 2.1 语义层：`addQuestion` 走了"新增 + 删除"

`reader_page._applyAction` 对 `RegionAction.addQuestion` 统一走
`AddQuestionCorrection`（题号 = `_nextQuestionLabel` = 最大数字 +1，追加到列表末尾），
再对 `level == 1` 补一条 `DeleteCorrection` 删掉原容器。

于是用户看到的是：**一道新题**（新题号、列表末尾）而不是"原来那道被确认"。

### 2.2 显示层：重绘判定漏了 `level`

`region_overlay.dart` 的 `_RegionPainter.shouldRepaint` 用 `_sameMarks` 比较新旧框，
但只比了 `key / rect / grade / label / locked / isAnswer / userAdded`，**没有比 `level`**。

确认操作恰恰只改 `level`（1 → 2，虚线 → 实线）：key 不变、矩形不变、题号不变；
如果这一题的置信度本来就落在"绿"档，`grade` 也不变 —— 于是判定"没变"、不重绘。
**关面板再打开**会重建绘制层，所以看起来"过一会儿才生效"。

---

## 3. 修法

### 3.1 新增 `ConfirmQuestionCorrection`（domain）

`domain/region/correction.dart`：

```dart
class ConfirmQuestionCorrection extends RegionCorrection {
  // 只改两件事：level 1 → 2（虚线 → 实线）、confidence → 1（已确认）
  // key / ordinal / label / slices 全部保留
}
```

- JSON 记为 `{ "t": "confirm" }`，`RegionCorrection.fromJson` 能读回（撤销/重开卷都靠它）；
- 不设 `userAdded`（这不是手画，否则面板会显示"手画"）；
- `questionDeltaOf(log)` **不计**（确认不是"加一道题"）。

### 3.2 把"加题走哪条 correction"抽成纯函数

`ui/region/add_question_action.dart`：

```dart
RegionCorrection addQuestionFor({
  required QuestionBundle bundle,
  required RegionSet set,
  required String id,
  required String key,
}) {
  if (bundle.question.level <= 1) {
    return ConfirmQuestionCorrection(id: id, key: key); // 虚线框：就地确认
  }
  return AddQuestionCorrection(...);                     // 实线题：新增一道（原语义）
}
```

`_nextQuestionLabel` 一并移到这里。`reader_page._applyAction` 只负责调用 + 在
`op is ConfirmQuestionCorrection` 时给一句提示。

**为什么抽成纯函数**：这个分支以前就是反的；语义放进一个可单测的函数里，
以后重构页面时不会又被写回 `Add + Delete`。

### 3.3 重绘判定补上 `level`

`region_overlay.dart` 的 `_sameMarks` 改成公开的 `regionMarksEqual`，
把**所有影响绘制的字段**都比一遍：

```dart
a[i].level != b[i].level || a[i].confidence != b[i].confidence || ...
```

`level` 决定虚线/实线，`confidence` / `grade` 决定颜色与分级 —— 漏一个就会
"改了但屏幕不动"。

---

## 4. 为什么"就地确认"更对

| 维度 | 旧（新增 + 删除） | 新（就地确认） |
|---|---|---|
| 题号 | 变成最大号 +1 | **不变** |
| 面板位置 | 跳到列表末尾 | **不变** |
| 题目 id | 新 id（判题/收藏/记录会对不上） | **复用原 anchor key → 原 id** |
| 题目数 | +1（删掉一个容器、新增一个） | **净增 0**（level 1 → 2） |
| 画布 | 新框叠在原虚线框上 | 原框直接变实线 |

> 复用 id 的依据：`RegionBuilder` 用 `matchExistingQuestionIds(oldIdByKey, newKeys)`
> 按 anchor key 复用题目 id；确认不换 key，所以 id 不变。

## 6. 不要改坏的约定

1. **虚线框（level ≤ 1）上的「加题」必须是 `ConfirmQuestionCorrection`**：
   不改题号、不改 ordinal、不改 key / slices；不要改回 `Add + Delete`。
2. **重绘比较必须包含 `level`**（以及 confidence 等影响绘制的字段）：
   漏一个就会出现"数据改了、屏幕不动"。
3. **实线题上的「加题」仍保留"新增一道"**（题号接最大号 +1）——
   这是"切题把两道并成一条时从中间加一道"的入口，不要一起改掉。
4. `confirm` 的 JSON 类型是 `t: 'confirm'`；改格式要同时改 `fromJson`，否则撤销/重开会丢这一步。
5. 确认**不设** `userAdded`，也**不**计入 `questionDeltaOf`。
