## 1. 做了什么

`Rpage/` 共 5 个代码/文档文件 + 5 张 webp 截图 + 1 个 APK，**无 npm / 无打包 / 无外部字体**：

| 文件 | 行数 | 作用 |
|---|---|---|
| `index.html` | 640 | 结构与全部文案 |
| `assets/css/site.css` | 2786 | 设计令牌 + 全部样式 |
| `assets/js/site.js` | 707 | 滚动动效、三个演示、画布、热力图、色系 |
| `site.config.js` | 9 | 部署前唯一要改的文件（`apkUrl` / `github`） |
| `README.md` | 161 | 预览、部署、换图、口径、下一步 |

页面结构：首屏 → 生态位对照（三条"它到不了的地方"+ 刷起那一行）→ 01 切题 → 02 判题（深色段）
→ 03 二刷 → 截图画廊 → 04 试写（可写画布）→ 05 记录（深色段）→ 06 归属 → 07 问答 → 下载（深色段）→ 页脚。

### 三个"活"的演示（这页的重点）

1. **切题**：卷面用真实 DOM 文字排版，SVG `rect` 由 `getBoundingClientRect()` 反推位置，
   逐题用 `pathLength=1 + dashoffset` 描出来，末尾浮出"已切出 4 道题"。改字号/改文案后框仍贴合，`ResizeObserver` 自动重算。
2. **判题**：六行题目逐行点灯（对/待判/错）+ 数字滚动 + 最后浮出"第 4 题识别置信度不够"的说明，
   点「改卷」可重播；刻意保留"待判 ≠ 错"这一条。
3. **二刷**：三张错题卡 → 打勾 → 收成"组卷"卡 → 空白答题卡（笔迹是 SVG 路径画出来的）→ "已保存"提示 + 纸叠。

### 一个真的能玩的功能

「试写」画布：Canvas 2D + Pointer Events，**手写笔压感**、荧光笔、**局部橡皮（把一笔切成两段）**、
撤销、清空、6 种纸色（原纸/暖白/象牙/浅灰/浅绿/夜读，夜读自动换暖白墨）。
这不是装饰——产品最容易被误解的就是"能不能真写"，所以直接让人写。

### 五套色系

导航右上角 5 个色点 = App 的 `ShqAccent`（靛蓝/青瓷/紫藤/赭陶/石墨），切换会改整站 `--accent`，
并存 `localStorage`。这是把 App 的一个设置项做成了网页彩蛋。

## 2. 关键决定与理由

| 决定 | 理由 |
|---|---|
| **不做构建、不用框架** | 静态站直接丢 Nginx / Pages 就能跑；49 MB 的包与页面互不牵连；以后换配色不用装 node |
| **系统字体栈** | 不引 Google Fonts（国内会卡），中文走 HarmonyOS/PingFang/雅黑；页面零外部请求 |
| **暖纸底 + 深墨字 + 一个强调色** | 对齐 App 的"纸感 + 冷灰骨架"；深色只给判题、记录、下载三段，让截图与三态灯有地方发光 |
| **"密封线内不要答题"** | 中国卷子的强识别符号；只做两条（试写区左边、切题纸左边），不铺满 |
| **截图只用数学卷** | 书架截图里有一份政治课试卷（课程名+卷面），不适合公开物料；只取阅读器/收藏夹/答题卡/二刷/记录 5 张 |
| **下载区单独列"这一版还没有"** | 075 的口径是"不夸大"；没有交卷总分、公式只给图、没有 iOS —— 写在下载按钮旁边比藏在 FAQ 里更诚实 |
| **APK 用现成的 release 包** | `app-release.apk` 49 MB / SHA-256 已实测写进页面；只发 arm64 的 37 MB 包等正式签名一起做 |

## 5. 不要改坏的地方

- **`[data-reveal]` 的兜底**：JS 或 `prefers-reduced-motion` 缺失时必须可见（`<noscript>` 已兜一层）。
- **切题框不吃死尺寸**：位置必须由 DOM 量出来，不能在 CSS 里写死坐标。
- **下载区的数字**：改 APK 必须同步版本号 / 体积 / SHA-256 三处，否则页面在撒谎。
- **文案口径**：不写"交卷总分""公式识别""提分/押题"；AI 一律"自带 Key、可选"。
- **截图**：不出现真实姓名、手机号、出版社卷面、政治课试卷。

## 8. 第四轮（同日 12:00）：release 包启动即崩（R8 吃掉 ML Kit 反射构造器）

### 8.1 现象

用户从 GitHub Release 下载 `shuaqi-0.1.0.apk`、卸载旧包后安装（安装成功，`firstInstallTime` 有值），
**点图标闪退**；profile 包一直正常。

### 8.2 根因（logcat 直接指出）

```
FATAL EXCEPTION: main
java.lang.RuntimeException: Unable to get provider androidx.startup.InitializationProvider:
    Failed to create an instance of androidx.work.impl.WorkDatabase
Caused by: java.lang.NoSuchMethodException:
    com.google.mlkit.vision.digitalink.recognition.internal.DigitalInkRecognitionRegistrar.<init> []
    com.google.mlkit.common.internal.CommonComponentRegistrar.<init> []
    com.google.mlkit.vision.common.internal.VisionCommonRegistrar.<init> []
```

`flutter build apk --release` 会开 R8（`build/app/outputs/mapping/release/mapping.txt` 16MB 可证），
ML Kit 的组件注册器是**按类名反射 newInstance()** 的，无参构造被裁掉 → 启动时
`androidx.startup` 初始化失败 → 进程直接崩。**profile 不跑 R8，所以之前一直没暴露。**

### 8.3 修法

- 新增 `main/android/app/proguard-rules.pro`：整包 keep `com.google.mlkit.**`、
  `com.google.android.gms.internal.mlkit_*`、实现 `ComponentRegistrar` 的类及其 `<init>()`、
  `androidx.startup.**`、`androidx.work.**`。
- `android/app/build.gradle.kts` 的 `release` 显式声明
  `isMinifyEnabled = true` + `proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")`
  （之前没有引用任何自定义规则）。

### 8.4 验证

- 重新 `--split-per-abi` 构建：arm64 包 **36.6 MB / 38,378,383 字节**
  SHA-256 `467B346CCBD06E343EEFE1A3F3FED126246A9F56D931157532235E28DB64907A`；
- `adb install -r` 覆盖安装后 `am start -W` → `Status: ok`，书架正常渲染（空态），
  `logcat` 无 FATAL；
- 新包已用 API 删旧资产、上传新资产到 `v0.1.0`（digest 与本地一致），
  站点体积/SHA 同步改（36.6 MB / 38,378,383 / `467B346C…DB64907A`）。

### 8.5 教训

- **profile 通过 ≠ release 通过**：本项目第一次真正装 release 包才发现，以后每个版本至少装一次 release 冒烟。
- R8 不是"开着就行"：任何靠反射/按名加载的三方库（ML Kit 这类）都必须显式 keep。

### 8.6 顺带修的线上问题

## 9. 第五轮（同日 12:30）：卷面作答也进记录 + 记录页实时刷新

### 9.1 用户反馈

> 「直接在卷子上写的题目只要有痕迹（在对应大题框内）也要统计」；「记录页没做到实时随作答信息更新」。

第一条是真遗漏：v7 的打点只认答题卡会话（`ans:`），**直接写在 PDF 卷面上的字不归属任何题**。

### 9.2 卷面作答归属（`state/ink_providers.dart`）

在 `_recordAnsweredInner` 的兜底分支里加 `_recordPageInkIfAny()`：

- 只处理**普通页会话**（不是 `ans:`、不是收藏重刷），且 `workbookId` 非空、有笔迹；
- 读 `regionSetProvider(workbookId)`（与题目面板同源，切题后面板失效，这里跟着失效，不会用旧框）；
- 归属口径：
  - 只认**当前页**的框（跨页题按页切片）；
  - 卷里有小题（`parentId != null`）时**只数小题**，避免"大题容器 + 小题"重复记两道；
  - 判定用**落点**（`RegionRect.contains(point)`），不是笔迹外接框相交——长笔斜穿不会误伤别的题；
- 命中后复用现有的去重键 `answerRecordKeyOf(qid, now)` 与 `RecordService.touch`，同一天同一题只落一条。

### 9.3 实时刷新（同一轮）

原来的刷新只有两处：`records_page` 监听 `shellTabProvider` 切 tab、下拉刷新。
如果记录页本来就停在「记录」tab（IndexedStack 保活），写完不会重算。

改成**写完就失效**：

- `ink_providers`：答题卡 / 卷面 / 收藏重刷三条 `touch` 之后都 `.whenComplete(_invalidateRecordPages)`（invalidate `recordsOverviewProvider` + `recordsTimelineProvider`）；
- `grading_providers`：判题 `syncVerdict` 之后同样失效（正确率也会变）。

### 9.4 验证

- `flutter analyze` 0 issue；
- 真机（OPPO OPD2601，release/arm64 包）：打开《数据结构》→ 在 Q4 的框内划一笔 → 返回记录页，
  「作答概览」从 2 题变 3 题、热力图/连续打卡/时间线同步更新（截图 `_verify/demo/96-final.png`）；
- 包：38,378,383 字节，SHA-256 `252F15207B140979BD2B5358AE8F1EC28B34EF14AF49C94367389C6FFB4B3E7B`；

### 9.5 边界（本轮没做）

- **只有墨迹落点落在框里才算**；写在框外的边角（比如题目之间的空白）不计——按用户口径这是对的；
- 一笔同时压在两题的框上会**两题都记**（落点各自命中），暂未做"取重叠面积最大"的消歧；
- 已判过的题不会因为卷面再写而改判定（判定仍由「对答案/改卷/AI 判」写）。
