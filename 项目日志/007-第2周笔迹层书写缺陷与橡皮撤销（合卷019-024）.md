## 1. 三层画布与输入管线（T2.1）

### 1.1 结构

```text
PageLayer
 ├─ PaperEffect(背景位图)        ← 墨迹层是它的兄弟节点（滤镜不染墨迹）
 └─ InkLayer
     ├─ ClipRect                ← 墨迹不越页界（裁显示，不裁数据）
     ├─ CustomPaint(committed)  ← 档位共享 Path，只在新笔时重绘
     ├─ CustomPaint(active)     ← 当前笔逐段变宽，ValueNotifier 驱动
     └─ Listener(translucent)   ← 只收 stylus；touch 穿透给父层
```

三层各司其职：**active 层**每帧只重绘当前笔，承载压感细节；**committed 层**按档位维护共享 Path，整层重绘只需 3+1 次 `drawPath`（荧光笔单独一条，`BlendMode.multiply`）；**背景层**是既有 PDF 位图与纸感/夜读。

### 1.2 stylus 分流（规格 §6.9.1「笔写、指滚」）

| 模式 | stylus | touch |
|---|---|---|
| 滚动 | 墨迹层消费（写） | 父级 `GestureDetector` 平移/缩放（`supportedDevices: {touch}`） |
| 分页 | 墨迹层消费（写） | `InteractiveViewer` 缩放/平移 + 双击 |

- 滚动模式的缩放手势必须显式限定 touch：**不加这一条，stylus 拖动会被当成平移，边写边跑画面**。
- `HitTestBehavior.translucent` 是自己收笔、触头穿透的关键；同一时刻只受理一个指针（`_activePointer`），手掌或第二根手指落上来不会插进当前这笔（T0.2「缝合线」事故的产品化解）。
- 双击必须用 `input motionevent DOWN/UP` 连发（两次 `input tap` 间隔太长，识别不了 double-tap）。

### 1.3 点压缩与坐标

流式最小间距过滤 **0.35pt**（T0.2 实测无可见变化）；`finish()` 按 1/4 阈值**强制补回末点**，否则「写到一半停住」的笔尾会短一截；单点笔画保留为一个点（打钩打点是合法输入）。

坐标一律存**页面坐标 pt**：落笔 `local × pageWidthPt / displayWidth`，绘制 `canvas.scale(displayWidth / pageWidthPt)`。滚动模式的缩放矩阵在墨迹层之外，墨迹天然跟着页一起缩放——这条是后面 023 命中区问题的伏笔。

### 1.4 状态与存储（SIF 前身）

- `inkDocProvider`（family，键 `InkPageKey(sessionId, pageIndex)`）：`Notifier<InkDoc>`，`build()` 先返回 empty、异步入库后静默替换；
- `commit()` 先改内存（UI 立即出墨）再异步 `InkStore.save`，落盘返回的 revision 按代次回填（W4 识别调度要拿它做版本校验，INV-02）；
- 存储实现是 **`MemoryInkStore`（内存，杀进程即丢）**：T2.1 刻意先兑现「UI 一开始就依赖契约」，T2.4 换 SIF + ink-io isolate 时上层零改动。

### 1.5 本卷唯一有意取舍（后被推翻）

分页模式放大中（`_zoomed`）曾禁用书写，理由「1x 书写是主路径，放大书写是罕见组合」。**该取舍被用户推翻**，见 §2.5。

## 2. 书写手感与暗色/滚动缺陷（020–022）

### 2.1 暗色下 PDF 一片死黑 —— 矩阵单位错

**现象**：一进深色主题，整页纯黑，白纸黑字全没了。

**根因**：`ColorFilter.matrix` 的输入通道与第 5 列偏移是 **0..255 字节值**，不是 0..1。`NightTint._buildMatrix` 把归一化 ink 色（≈0.91）当偏移填进去：白纸 `(-0.816)·255 + 0.91 ≈ -207 → 钳到 0`。旧单测按归一化口径（r∈0..1）算，**数学上自洽，只是单位错了**，所以宿主机全绿也拦不住。

**修法**：偏移列 ×255；单测改字节口径（`NightTint.applyByte`），断言「白纸→纸色≠0、黑字→亮墨>200」。

**验证**：真机截图夜读为暖黑纸 + 暖白墨，不再死黑；新增 3 例字节口径用例。

### 2.2 滚动 100% 不流畅、多次捏合后卡顿+显示异常 —— 三个根因

| # | 根因 | 量级 | 修法 |
|---|---|---|---|
| 1 | `RenderTransform` 没走合成层，`needsCompositing == false` 时矩阵只压进 canvas | 可见页位图+噪点+阴影每帧重新光栅化，2 页 A4 ≈ **12.8MP/帧** | 每页包 `RepaintBoundary`，Transform 推出真正的 TransformLayer，纯平移变成合成器搬贴图；写字也不再带动 PDF 位图 |
| 2 | 捏合后位图内存暴涨触发淘汰与 GC | 4096px 上限时 A4 一页 **95MB**，三页 **285MB** > 200MB 缓存 | 收敛到 3200px：一页 52MB、三页 156MB；代价是 200%+ 放大略软（真无损等 T1.5.1 分块渲染） |
| 3 | 位图落在半个像素上 | 1 倍时位图与屏 1:1，但位移是浮点 → 每帧一次双线性重采样 | `_publishCamera` 把位移取整到设备像素（2.5dppx 下台阶 0.4dp，不可见） |

顺带修掉 T2.1 引入的布局缺陷：`PageLayer` 返回的 `Stack` **只有 Positioned 子节点** → 撑满父级约束；分页模式父级是 `Center`（松散约束=整个视口），页面被拉成视口比例。外面钉 `SizedBox(页宽×页高)`。

### 2.3 抬笔瞬间粗细跳变 —— 两个来源，一并根除

**现象**：落笔一瞬偏粗/偏细，抬笔瞬间整笔换宽度。

| 来源 | 机理 | 修法 |
|---|---|---|
| 压力读数不可信 | Android DOWN/UP 常报 0 或 1.0，直接映射就是发丝或最粗；旧收尾点硬编码 0.5、t=0 | `_pressureOf`：`<=0.02` 沿用上一有效压力（落笔基线重置为中性 0.5），`>=0.999` 视为无压感取 0.5；收尾点用真实最后压力 |
| 活笔/死笔两套几何 | 活笔逐段 `drawLine`（压感连续），死笔按平均压感归 3 档（1.6/2.6/4.2）重画 → 抬笔整笔换宽 | 新 `InkRibbon`：宽度量化 **24 档（0.148pt/档，400dpi 下不可见）**，每档一条 Path；活笔流式 append、死笔整笔重放，**同一份代码同一份几何** |

配套：压感 EMA 平滑（0.45，约 3 个采样点 ≈13ms）；`ink_ribbon_test.dart` 用「流式 vs 整笔逐档包围盒相等」把承诺钉进测试。

### 2.4 荧光笔把字染黑 + 起笔圆斑

**荧光笔**：原来最后画，`multiply` 会把已写的字再乘一次色。修法：**荧光笔垫底先画**（每笔刷一条 ribbon，钢笔/圆珠笔 `srcOver`，荧光笔 `multiply`）。代价是已提交层重绘从 3 条 Path 变最多 72 条，仍远低于逐段绘制。

**起笔圆斑**：每个笔画起点一个明显圆点。根因是 DOWN 事件压力读数系统性偏高（T0.2 实测区间 0.0–0.877），旧实现照它画了全宽起点圆。修法：起笔**不画点**，从 `raw × 0.55`（`InkWidth.taperIn`）起笔，EMA 约 13ms 收敛；单点仍在 `endStroke` 补一个完整圆点。

### 2.5 「放大后写不上」—— 两次误判后定位（旧取舍被推翻）

**分页模式，两个根因**：

1. `inkEnabled: index == _current && !_zoomed` 让放大时墨迹层整个卸载，已写笔迹跟着消失。修法：去掉 `!_zoomed`——墨迹层在 IV 的变换子树里，指针事件 `localPosition` 会被 IV 矩阵自动逆变换到页面局部坐标，**放大后写哪儿落在哪儿**。
2. 放大状态下笔的拖动被 `InteractiveViewer` 当成平移 →「一落笔页面就跑」。修法：`StylusGestureGuard` 自定义 `OneSequenceGestureRecognizer`，在 `addAllowedPointer` 里**立刻 `resolve(accepted)`**。要点：竞技场在 DOWN 派发结束时 sweep，未决时判给**第一个**成员（恰好是 IV），所以必须抢在 DOWN 派发期间接受；touch 不在允许列表，指头缩放/平移/双击不受影响。

**滚动模式**：实测 200% 下书写位置精确，**「滚动放大写不了」的旧结论是错的**，真凶是手掌。T2.1 有一条没实现的规格——「笔优先：收到 stylus 事件后 800ms 内忽略所有 touch（双指缩放除外）」。修法：translucent `Listener` 只记录「笔最近出现」时间戳，缩放手势回调开头 `笔 800ms 内出现过 && pointerCount < 2 → return`；被挡的手势在 End 里也不甩动。

### 2.6 滚动放大专项：一次「假靶子」与 5 处真修复

对照实验（`input stylus` 注入）：100% 连写 10 笔 10/10、200% 连写 10 笔 10/10；200% 下九宫格前 6 笔成功后 3 笔丢失，但**紧接着同位置竖排 8 笔 8/8**——说明丢事件是 adb 注入在连续命令下的缺陷，不是 App 侧 bug（逐笔日志 down→commit→state 递增，没有一笔「收到事件却没写进去」）。

结论：单指路径（菜单 `setScale`）是好的，差异点必在**双指捏合路径**。五处修复：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| ① | 捏合放大失灵/卡在半途 | `ScaleStartDetails.pointerCount` **恒为 1**（第一根手指落下时还没有第二根），笔刚离屏 800ms 内捏合从第一帧就被判「单指+笔活跃」而冻住 | 双指判定只在 `_onScaleUpdate` 做；`_onScaleStart` 不再因笔阻塞；**双指永远放行**，单指平移仍冻结 |
| ② | 字画在「还在飘的纸」上 | 惯性滚动未停，落笔那刻算的页面坐标与松手后的纸已错开 | `onPenDown` → `PageLayer` → `_stopMotion()`（停 ticker + 清速度） |
| ③ | 这一页**永久**写不了，且无任何提示 | UP 丢失后 `_activePointer` 被占死，后续笔全被当手掌拒掉 | 记录当前笔最近事件时刻，**超过 1.2s 无事件**判僵死并复位接管 |
| ④ | 被冻结的手势仍然甩动 | 手指在动页面没动，按手指速度甩出去会突然窜一段 | 冻结标记 → `_onScaleEnd` 不甩动 |
| ⑤ | 「按了没反应」无从解释 | 无从区分「没落在纸上」 | 新增 `onPenMissed`：视口看见的落笔次数 ≠ 纸面接住次数 → 浮出「这一笔没落在纸上」；依赖「深的先派发」，已验证不误报 |

**验证**：100%/200% 各 10 连写全成功、位置精确；甩动中落笔笔迹正确且页面立即停；正常书写不误报。捏合路径无法自动注入（§5），靠代码审查 + 用户复验。

## 3. 命中区与纸色解耦（023，重点）

### 3.1 「看得到、写不上」—— 内容画对了，命中区被压扁

前两轮已「验证滚动 100%/200% 能写」，因此先假设**不是所有位置都能写**，用一次性 widget 探针（`zz_probe_test.dart`，验完即删）把怀疑变成数字：

| 结构 | 内容盒实际尺寸（期望 800×5000） | 内容坐标 y=2300 落笔命中 |
|---|---|---|
| 旧：`SizedBox(视口) > ClipRect > Transform > SizedBox(整卷)` | **800×600**（=视口高，被压扁） | **0 次** |
| 新：`SizedBox(视口) > ClipRect > Stack > Positioned > Transform > SizedBox(整卷)` | 800×5000 | **1 次** |

**机制链**：① 视口必须撑满父级（015 立的规矩）→ ② `SizedBox(视口)` 给下游**紧约束**，沿代理链一路传下去 → ③ `SizedBox(整卷高)` 被 `BoxConstraints.enforce` **压回视口高度** → ④ 绘制不受影响（`Stack` 的 `clipBehavior: Clip.none` 照样按 `Positioned.top` 画），但 `RenderBox.hitTest` 第一件事是 `size.contains(position)`，**内容坐标 y > 视口高的落笔全部被丢弃** → ⑤ 848×1050 的视口里只有「整卷最上面那一屏」能写：第 1 页上半页正常，第 2 页往后、以及滚下去的任何位置都写不上。

**为什么前两轮没测出**：`input stylus` 注入点都落在文档顶部（内容坐标 y < 视口高），恰好是唯一能写的区域——**「测在能写的地方」造成的假通过**。

**修法**：新增 `ui/reader/camera_viewport.dart`：

```text
SizedBox(视口) > ClipRect > Stack(clipBehavior: none)
                                └─ Positioned(left:0, top:0)   ← 故意不给 width/height
                                     └─ ValueListenableBuilder<Camera> > Transform > 整卷
```

`Positioned` 只给 `left/top` 时子节点拿到**无界约束**，`Transform` 因此是整卷尺寸，命中链能走到内容坐标系的正确位置；`Stack` 自己是视口尺寸，裁剪交给外层 `ClipRect`（只裁显示，不裁命中范围）。相机状态从私有 `_Camera` 提升为值对象 `Camera`。

**验证**：`camera_viewport_test.dart` 5 例（内容盒尺寸、1 倍/2 倍命中、纸外不命中、相机变化不重建内容子树）；真机连甩到第 3/4 页写两笔均落在第 3 页。

### 3.2 深色主题不该把 PDF 也变黑

**现象**：深色界面下没法看白底黑字的卷子；浅色界面下又选不到夜读。

**根因**：旧规则「App 一进深色 → 所有卷面强制 duotone 夜读」把**界面配色**与**纸面配色**绑成一件事。

**修法**（用户拍板：黑底白字只是一种风格选项，白底黑字必须随时可用）：

| 关注点 | 谁决定 | 管什么 |
|---|---|---|
| App 主题 | `themeModeProvider` | 书架、AppBar、浮层、抽屉等**骨架** |
| 纸样式 `PaperStyle` | `reader.*` 偏好（全局默认 + 每卷覆盖） | **卷面**配色：原图/暖白/象牙/浅灰/护眼/**夜读** |

- `PaperStyle.night` 是一种纸样式，浅色界面下也能选；
- 新增 `PaperStyle.isDarkPaper` 作为「暗纸亮墨」的**唯一判定**——UI 层不许再写 `style == PaperStyle.night`，更不许看 `Theme.brightness`；
- 废止 `ReaderPrefs.forSurfaceBrightness`；
- 墨色跟**纸**走（`inkColorFor`）：夜读纸→暖白墨，其余→深墨；已画的笔**自动换色**；
- 页面底色/发丝边/投影也跟纸走，且**画在滤镜之外**——放滤镜里会被 duotone 再反一次（黑投影变成一圈脏光）。

**验证**：深色主题 +「原图」→ 纯白纸黑字；深色 +「夜读」→ 暖黑纸暖白字、旧笔迹自动变暖白墨；显示浮层六个色块在深色下全部可点。

## 4. 橡皮与撤销重做（024，重点）

### 4.1 笔画级橡皮

12pt 阈值；`bounds` 预筛 → 点到折线距离 → **段到段距离**（「划过即删」必须算线段相交，只看采样点会漏）。笔尾橡皮：`invertedStylus` 直接当橡皮。撤销按**页**：滚到第 3 页按撤销，撤的是第 3 页的笔。

### 4.2 命令栈：深度 50，一次擦除 = 一步

三个命令 `AddStroke` / `RemoveStrokes` / `ClearPage`，深度 **50**；一次擦除拖动合成**一步**撤销，因此把规格里的单数 `RemoveStroke` 扩成复数带索引。

**被单测抓住的真 bug**：擦除是「边划边删」，删完一次 doc 下标全变；若第二次擦除按**当前** doc 取索引，撤销会把 `[a,b,c]` 复原成 `[b,a,c]`。修法：一次拖动只在**第一次**擦除时取基线 doc，之后所有索引相对它（`_eraseBaseline`）。

### 4.3 三个不许改回去的设计决定

| 决定 | 理由 |
|---|---|
| 工具 ≠ `InkStrokeStyle`（橡皮不入 SIF） | `InkStrokeStyle` 是数据契约（SIF v1 的 style 占 1 字节：0/1/2），橡皮**不产生笔画**；新增 UI 概念 `InkTool`，落笔时取 `tool.strokeStyle` |
| 命令必须带「原索引」 | 删除要可逆到**原 z 序**；删除发生那一刻就把 `(index, stroke)` 记进命令。`ClearPage` 因此必须带「清空前那一页的笔画」 |
| 撤销栈不持有 doc | 栈只记历史、`InkEditController` 持有 doc；「落盘 revision 回填」不搅乱历史 |

### 4.4 异步加载覆盖新笔（T2.4 前必修）

**现象**：用户 `_load()` 返回之前就落笔，刚写的笔**凭空消失**。

**根因**：旧实现无条件 `state = loaded`，异步结果把内存里已有的编辑整个盖掉。

**修法**：守卫——内存里已有编辑（`canUndo || strokeCount > 0`）就不接受磁盘内容。

**风险标注**：T2.4 换真实文件 IO 后，这个窗口会从「一个微任务」变成「十几毫秒」，不挡就一定会丢笔。

### 4.5 有意偏离规格（代码里都注明了理由）

| 规格写法 | 实际 | 为什么 |
|---|---|---|
| `ClearPage` 无字段 | `ClearPage(removed)` | 不可逆的清空命令没法进撤销栈 |
| `UndoStack.undo/redo()` 自带 doc | 栈不自持 doc，由 controller 执行 | 落盘回填 revision 时不搅乱历史 |
| 只有 `RemoveStroke` | `RemoveStrokes`（复数，含索引） | 一次擦除拖动要算一步 |
| 橡皮藏在 `InkStrokeStyle` | 独立 `InkTool` | 不许污染 SIF 的 style 字节 |

### 4.6 真机验证

| 操作 | 结果 |
|---|---|
| 连写 3 笔（y=700/900/1100） | 三笔都在；撤销从灰变亮、重做仍灰 |
| 切橡皮横划穿过中间笔 | 只有中间那笔消失，上下两笔完好（12pt 不误伤 200px 外邻居） |
| 撤销 → 重做 | 中间那笔回来；重做后又消失，截图与擦除后**逐字节相同** |
| 连按 4 次撤销 | 三笔+擦除全部退回，撤销变灰、重做变亮 |
| 切回钢笔续写 | 正常出墨；重做立刻变灰（新编辑作废旧分支） |

### 4.7 后记：局部擦除（026 返工，非 024 内容）

**024 的「整笔删除」被用户要求推翻**：橡皮要能只擦掉碰到的部分，并且可选大小。

```text
原笔 ────────────────      一条长横（一笔，uid=H）
擦         ●●              橡皮（半径 12pt）划过中间
结果 ──────      ──────      变成两笔（uid 是新的），缺口近似 = 橡皮直径
```

**算法（`eraser.dart` 重写）**：

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 橡皮路径 → 圆盘 | 按步长 `min(radius, 4pt)` 采样成一串圆盘 | 圆盘与线段交集有**精确解**（二次方程） |
| 线段 ∩ 圆盘 | 解 `At² + Bt + C ≤ 0`，与 [0,1] 求交 | 精确、无采样误差（单测断言缺口=直径，误差<0.01pt） |
| 多圆盘区间 | 排序后合并成「被覆盖的 t 区间」 | 一笔可能被多个圆盘覆盖 |
| 切分 | 区间外保留、区间内丢弃，**断口用 `lerp` 插值** | 碎片首尾正好贴着擦除边界 |
| 预筛 | `mayTouch()` 只比包围盒 | 一页 5000 笔，每个 move 事件全量求交会直接卡死 |

**碎片继承样式**：碎片继承原笔的样式/颜色/粗细，**uid 换新**；单点笔画要么整体擦掉要么不动；一次拖动的所有切分抬笔时合成一步撤销。

**命令层**：新增 `ErasePatch = ({index, original, fragments})`、`EraseStrokes`（就地替换，保 z 序）、`EraseBatch`（一次拖动合成一条）。`apply` **从后往前**替换避免下标被列表长度带偏；`revert` 先摘碎片 uid 再按原下标**从大到小**插回；`EraseBatch.revert` 按**相反顺序**还原。

**绘制层 `epoch`**：`CommittedInkCache` 原是「只追加」，而局部擦除会让一笔变两笔——长度可能刚好对得上，只比 `strokeCount` 会漏判，结果是「数据改了、画面没改」。修法：`InkEditState.epoch` 只在**非追加**改动时 +1，绘制层 `sync(doc, epoch)` 见 epoch 变就整体重建。

**三档大小**：小 6pt / 中 12pt（默认，规格值）/ 大 22pt；复用 `InkBrush.widthLevel` 当大小档；橡皮不显示颜色/粗细，改成一排**空心圆**。

**像素测量验证**（长横画在 y=900，`#14161A`，实测 21854 像素）：

| 操作 | 测量 |
|---|---|
| 中号，横划 100px（1400→1500） | 断成 `297→1344` 与 `1557→2504`，缺口 **213px ≈ 42pt** |
| 撤销 | 恢复成单段 `297→2504`，与擦前完全一致 |
| 重做 | 缺口精确回到 `1344→1557` |
| 小号点擦（700 附近） | 缺口 **63px ≈ 12pt** |
| 大号点擦（2100 附近） | 缺口 **225px ≈ 44pt** |

## 5. 验证手段与能力边界

### 5.1 `input stylus` 注入法

`adb shell input stylus swipe x1 y1 x2 y2 [ms]` 会产生 `PointerDeviceKind.stylus` 事件，App 端照常出墨——**笔交互从此可在真机自动化验证**。`input motionevent DOWN/UP x y` 连发两次可触发双击。

| 能力 | 结论 |
|---|---|
| 单指 stylus 书写 / 位置校验 | ✅ 可注入，可逐点比对 |
| 双击 | ✅ `motionevent` 连发 |
| 双指捏合 | ❌ `input` 是**单指针**，无法注入 |
| `sendevent /dev/input/event2` | ❌ 权限被拒（`crw-rw---- root:input`） |
| 笔尾橡皮 `invertedStylus` | ❌ 注入不了 |

设备上确实存在两支输入设备：`OPPO Pencil 2`（`/dev/input/event12`）与 `touchpanel`（`/dev/input/event2`，Type B 多指）。**「捏合后书写」这条路径只能靠代码审查 + 用户复验**。

### 5.2 帧数与性能的测量口径

`dumpsys gfxinfo` 对 Flutter（SurfaceView 直绘）**计 0 帧**，`SurfaceFlinger --latency` 在该 ROM 也只回刷新周期——**fps 数字采不到**。后来改用自建 HUD 同口径对照：

| 场景 | raster 中位 | 超 60Hz 预算 | 最差帧 | 位图缓存 |
|---|---|---|---|---|
| 优化前：打开后第一次滑动 | 4.5ms | 2% | **30.7ms** | 146MB / 3 页 |
| 优化后：打开后第一次滑动 | **2.4ms** | **0%** | **5.0ms** | 97MB / 2 页 |
| 优化后：连甩到末页 | 2.1ms | 0% | 3.0ms | 146MB / 3 页 |

## 6. 结论与遗留

### 6.1 已被推翻 / 已证伪的结论（不要再沿用）

| 旧结论 | 现状 |
|---|---|
| 分页模式放大中禁用书写 | **被用户推翻**：放大必须可写，靠 IV 逆变换 + `StylusGestureGuard` 实现 |
| 深色主题 → 所有卷面强制 duotone 夜读 | **推翻**：纸样式与主题正交，夜读只是六种纸之一 |
| 「滚动放大后写不了」 | **证伪**：200% 位置精确，真凶是手掌拖页 + `pointerCount` 恒 1 冻住捏合 |
| 「滚动 100%/200% 已验证能写」 | **假通过**：注入点全在文档顶部；实为内容盒被压成 800×600，y>视口高全部丢弃 |
| 橡皮 = 整笔删除 | **被用户推翻**（026）：改为局部擦除，碎片继承样式 |
| 抬笔跳宽是「压力读数抖动」单一原因 | 不完整：另一半是活笔/死笔两套几何，必须同源 |
| 荧光笔最后画没问题 | 错：最后画会把已写的字再乘一次色 |

### 6.2 遗留（按优先级）

| 遗留 | 归属 |
|---|---|
| 杀进程丢墨迹（当时为 `MemoryInkStore`） | **已由 031（T2.4）补齐**：SIF 编解码 + isolate + 冷启动恢复（单页 5000 笔 ≤400KB） |
| 撤销按「当前主可见页」作用，两页交界处写在下一页时可能指向上一页 | 已记录；精确到「最后一笔落在哪页」与 INV-01 冲突，留待实际痛点 |
| 每访问一页留一个 `InkEditController`（含历史，非 autoDispose） | T2.4/T2.5 上 HUD 时评估 |
| 200%+ 清晰度受 3200px 位图上限约束 | T1.5.1 分块渲染 |
| 无双指捏合/笔尾橡皮的自动化回归 | 能力边界（§5.1），需 root 或用户实笔 |
| 12pt/6/22pt 阈值与 `taperIn 0.55` 仅为工程值 | 需用户实笔手感复验 |
| 几何平滑仍为折线 + 压感 EMA、笔尖悬停预览未做 | T2.2 尾项 |
| 夜读强度滑条不参与 | 已置灰并说明，不装假功能 |
| 缩略图抽屉始终显示原图 | 有意：缩略图是「内容索引」 |
