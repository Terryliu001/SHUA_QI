## 1. 体积（有实测数据，收益最大的一块）

### 1.1 两个包的实测构成

| 包 | 大小 | 说明 |
|---|---|---|
| `app-profile.apk`（现装机） | **143MB** | 3 个 ABI + `libvmservice_snapshot` + 未 R8 |
| `app-release.apk`（`--target-platform android-arm64`） | **49.0MB**（解压 50.7MB） | 已 R8（dex 只剩 1.98MB） |

release 包逐条（解压后）：

| 条目 | 大小 | 归谁 |
|---|---|---|
| `lib/arm64-v8a/libflutter.so` | 11.20 MB | Flutter 引擎 |
| `lib/arm64-v8a/libapp.so` | 10.13 MB | 我们的 Dart AOT 代码 |
| `lib/arm64-v8a/libdigitalink.so` | 6.57 MB | ML Kit 手写识别 |
| `lib/arm64-v8a/libpdfium.so` | 6.09 MB | PDF 渲染 |
| **`lib/x86_64/libdigitalink.so`** | **8.37 MB** | **无用的 ABI** |
| **`lib/armeabi-v7a/libdigitalink.so`** | **4.26 MB** | **无用的 ABI** |
| `classes.dex` | 1.98 MB | Java/Kotlin（R8 后，健康） |
| `assets/*` | 1.30 MB | KaTeX 字体 ~0.35 / paper_noise 0.10 / manifest.json 0.32 / NOTICES 0.10 |
| `resources.arsc` + `res/` | 0.32 MB | 资源 |

### 1.2 白给的 12.6MB（最大单项收益）

`--target-platform android-arm64` 已经剔掉了**非 arm64 的 Flutter 库**（x86_64/v7a 里没有
`libflutter.so` / `libapp.so`），但 **ML Kit 的 `libdigitalink.so` 仍然按 3 个 ABI 全打进包**：

```
lib/x86_64/libdigitalink.so       8.37 MB   ← 平板上永远不会被加载
lib/armeabi-v7a/libdigitalink.so  4.26 MB   ← 同上
```

原因：它是 AAR 里带进来的 JNI 库，不受 Flutter 那套 `-Ptarget-platform` 约束。
**49.0MB → 约 37MB（-25%）**，功能与效果零影响。

三种做法，任选其一：

| 做法 | 命令/改动 | 结果 |
|---|---|---|
| A. 按 ABI 拆包（**最稳，推荐先试**） | `flutter build apk --release --split-per-abi` | 产出 3 个 APK，只发 `app-arm64-v8a-release.apk`（~37MB） |
| B. 锁 ABI（要复测） | `android/app/build.gradle.kts` 的 `defaultConfig` 加 `ndk { abiFilters += listOf("arm64-v8a") }` | 单包 ~37MB。⚠️ 该文件里现在写着"abiFilters 实测无效"，那是指 Flutter 自己的库会被 `-Ptarget-platform` 覆盖；对 AAR 的 JNI 是否生效**必须重新验一次** |
| C. 上架 Play 用 AAB | `flutter build appbundle --release` | 商店按设备下发，天然只有一份 ABI |

### 1.3 还能再挤 0.5–1MB

- `--obfuscate --split-debug-info=build/symbols`：缩短 Dart 符号名，`libapp.so` 通常小几百 KB（**符号表必须留存**，否则崩溃栈不可读）。
- profile 包里的 `libvmservice_snapshot`（1.5–1.8MB ×3）在 release 里本来就没有 —— 所以**演示/自测也尽量用 release 包**，143MB 的 profile 包不代表真实体积。

### 1.4 不建议动的部分（动了就是砍功能）

`libflutter.so` 11.2MB、`libapp.so` 10.1MB、`libpdfium.so` 6.1MB、`libdigitalink.so` 6.6MB
都是功能本身；KaTeX 字体 0.35MB 是公式渲染的必需项；`paper_noise.png` 0.10MB 是纸感。

> **关键认知**：Dart 的**死代码不进包**（AOT 前 tree-shaking）。所以"删掉没用的 Dart 代码
> 能减小体积"是错的 —— 体积只对 **native 库 / ABI / 字体 / 资源** 敏感。
> 下文 §4 的"拆文件"是为了可维护性，不是为了体积。

## 2. 性能

### 2.1 【P1】面板拖动 → 阅读器整页每帧重建

`lib/ui/reader/reader_page.dart:3736`（在 `build()` 内）：

```dart
// 面板宽度是全局偏好：watch 一次，拖动/落盘后整棵树重建
ref.watch(panelWidthProvider);
```

`PanelWidthController.preview()` 在拖动**每一帧**都写这个 provider（`panel_width_provider.dart`），
于是 `ReaderPage.build()`（4446 行，含顶栏 10 个动作、笔工具条、页层、面板、`_marksByPage` 切题框换算）
每帧跑一遍。拖动时"能跟手"是因为它真的每帧重建。

**改法**（不动手感，只缩小重建面）：把 `ref.watch(panelWidthProvider)` 从页面 `build` 里删掉，
改成只包住"面板 + 阅读区右侧留白"的 `Consumer`（或 `Builder` + `ref.watch`）。
重建范围从"整页"降到"面板壳"，其余子树（页层/工具条）保持不动。

### 2.2 【P1】三处 `Image.file` 全分辨率解码

| 位置 | 现状 |
|---|---|
| `ui/favorites/favorite_card.dart:241` | `Image.file(..., fit: contain)`，**无 `cacheWidth`** |
| `ui/favorites/favorites_page.dart:2085` | 同上 |
| `ui/favorites/favorite_set_page.dart:501` | 同上 |

题面快照按 2.8×pt 渲染（一道题常见 1000×800 px），解码后 3–4MB/张；卡片墙一次 8–10 张
≈ 30MB 位图 + 每次进页面重新解码。`records/profile_header.dart` 已经示范了正确写法
（`cacheWidth: 320`），把同样的做法补上即可：

```dart
cacheWidth: (cardWidth * MediaQuery.devicePixelRatioOf(context)).round(), // 或固定 720
```

看题页/全屏看图那一处**不要**加（那里就是要清晰）。

### 2.3 【P2】收藏夹分组在 `build` 里重算

`ui/favorites/favorites_page.dart:290 / 311`：`groupByWorkbook(favorites)`、
`groupByKnowledge(filterByTag(...))` 都在 `build` 内。每次 `setState`（包括**每勾选一张卡**）
都把整份收藏重新过滤 + 排序 + 分桶。500 条量级约几毫秒，1000+ 会开始掉帧。

**改法**：用 `late List<FavoriteGroup>? _cache` + `(favorites, view, tag)` 三元组做键，
不匹配才重算。20 行以内，零行为变化。

### 2.4 【P2】family provider 没有 `autoDispose` → 访问过的数据常驻

全项目 `autoDispose` 只出现 **1 次**，但 family provider 有 12 个，其中三个是真会吃内存的：

| provider | 常驻内容 |
|---|---|
| `inkEditProvider(pageKey)`（`state/ink_providers.dart:193`） | 每一页的 `InkDoc`（全部笔画）+ 最多 50 步撤销历史 |
| `workbookThumbnailProvider(id)` | 每本卷的缩略图字节 |
| `answerSheetControllerProvider(id)` | 每本卷的答题卡控制器 |

翻过 100 页写满的卷子，这些 doc 就都留在内存里。

**改法**：给上述三个加 `.autoDispose`。落盘安全性没问题 —— `InkWriter` 是另一个
（非 autoDispose）provider，`schedule()` 时已持有 doc 引用，且 `ref.onDispose` 里会
`flushAll()`。**但**这是行为敏感改动，必须回归：翻页往返笔迹在、500ms 内退出不丢最后一笔。

### 2.5 【P3】冷启动要等两件事才 `runApp`

`lib/main.dart`：`await pdfrxFlutterInitialize()` → `await bootstrap()`（开库 + 清孤儿目录）
→ 才 `runApp`。这期间是系统 splash。代码里已有 TODO。

**轻量改法**（不动架构）：把 `bootstrap` 里"清孤儿目录"这类**非阻塞**动作挪到首帧之后
（`WidgetsBinding.instance.addPostFrameCallback`）。真要更短就得换"先 runApp 再注入依赖"的
启动状态机 —— 那是中等改造，建议发布后再做。

### 2.6 【P3】SQLite 没开 WAL

`infra/db/app_database.dart:63` 的 `_configure` 只有 `PRAGMA foreign_keys = ON`。
这个 App 的写频率不低（落笔元数据、作答记录、收藏、设置），默认 `journal_mode=DELETE`
意味着每次提交都要 fsync + 删日志文件。

```dart
await db.execute('PRAGMA journal_mode=WAL');
await db.execute('PRAGMA synchronous=NORMAL');
```

⚠️ 连带两件事：① 备份 zip 要么把 `-wal`/`-shm` 一起打，要么导出前先
`PRAGMA wal_checkpoint(TRUNCATE)`；② 恢复时要先删掉旧的 `-wal`，否则会拿到旧页。
改完必须跑一遍"备份 → 恢复 → 重启"。

### 2.7 【P3】PDF 导出整份在内存里拼

`app/export/pdf_writer.dart:75` 的 `build()` 用 `BytesBuilder` 攒完整份 PDF 再返回
`Uint8List`。20 页 2400px 大约 40–60MB 峰值（页级 RGB 已释放，这点做得对）。
真要压，就改成"逐对象写 `IOSink`"，代价是要重写 xref 偏移的记录方式；**建议等实测超预算再动**。

### 2.8 【P3】320MB 位图缓存没有内存压力响应

`PageImageCache` 的 320MB 上限是实测调出来的（合理），但它对系统"内存紧张"毫无反应。
加 12 行就够：

```dart
// PageImageCache 使用者（PageLayer 或 reader_page）实现 WidgetsBindingObserver
@override
void didHaveMemoryPressure() => _cache.trim();   // 立刻收敛到上限，必要时把上限减半
```

这是把"4GB 机型 + 后台存活"的 OOM 概率降下来最便宜的一招。

| 编号 | 问题 | 证据 | 建议 |

| R1 | **release 下错误只 `debugPrint`**，用户侧完全不可见 | `ui/errors/error_handling.dart:17,25` | 加一个环形日志（`vault/logs/err.log`，保留最近 200 条 / 256KB），反馈表单可勾选附上。成本 ~80 行 |

## 4. 轻量化 / 可维护性（不影响体积，影响"改坏的概率"）

| 文件 | 行数 | 说明 |
|---|---|---|
| `ui/reader/reader_page.dart` | 4446 | 顶栏 + 工具条 + 页层 + 面板 + 覆盖层 + 导入/导出入口全在一个 State |
| `ui/bookshelf/bookshelf_page.dart` | 3175 | 4 种视图 + 多选 + 文件夹树 + 拖拽 |
| `ui/favorites/favorites_page.dart` | 2657 | 4 视图 + 多选 + 知识点 |
| `ui/panel/region_panel.dart` | 1969 | 面板 + 批量条 + 预览 |

拆分成 `*_actions.dart` / `*_views.dart` 这类同目录文件（本项目已有先例：
`reader_top_actions.dart`、`workbook_menu_sheet.dart`），**不改任何行为**，
但能让后续每次改动只 diff 一两百行。优先级排在 §2 之后。

**真正的"轻量化"清单（按性价比）**：
1. §1.2 只发 arm64 → -12.6MB（-25%）
2. §1.3 obfuscate + split-debug-info → -0.5~1MB
3. §2.8 内存压力 trim → 不省安装包，省"被杀"的概率
4. 其余都是代码整洁度，不影响包体

## 6. 已经做得很好、不要"优化"的地方（避免好心改坏）

- `ui/reader/page_image_cache.dart`：按字节 LRU + 单飞 + 独立 clone 契约，注释里写清了
  回归测试锁在哪。**任何"改成按页数缓存"的想法都是倒退。**
- `page_layer.dart` 的 `RepaintBoundary` 分层（纸 / 墨迹各一层）：这是滚动丝滑的根本，
  删任何一层都会退化成"每帧重光栅化整页"。
- SIF 编解码走 `Isolate.run`：落笔不阻塞 UI 的关键。
- `RegionOverlay` 内部已有 `RepaintBoundary`：切题框不会在滚动时逐帧重画。
- `sha1OfFile` 流式哈希、`Vault` 的 `.tmp + rename` 原子写、`backup` 用 `ZipFileEncoder`
  流式打包：都是对的，别改回 `readAsBytes` / 全内存 zip。
- `record_providers` 把统计放在 `FutureProvider`（不在 build 里算）：正确。
