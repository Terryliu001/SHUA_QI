## 1. 标签书签（用户第 7 条）

### 1.1 只有"不占布局"才能不改卡面

用户的原话是"不能因为加入标签导致卡片样式不统一"。所以书签**不进 Card 的子节点**，
而是挂在卡片外层 `Stack` 上：

```dart
Stack(clipBehavior: Clip.none, children: [
  Pressable(child: Card(...)),                       // 卡面一个像素都不动
  if (!selecting && tags.isNotEmpty)
    Positioned(top: 0, right: ShqSpace.md, child: _TagBookmarks(...)),
])
```

两个坑：
- `Stack` 默认 `clipBehavior: hardEdge` → 书签会**被裁掉**，必须显式 `Clip.none`；
- 列表卡右上角原来是 `more_horiz`（长按菜单入口），书签要占这块 → 按钮**下移到元信息行**末位，
  而不是把书签挤到别处（右上角是用户指定的位置）。

### 1.2 形状与颜色

- 形状：矩形 + 底部居中 V 形缺口（`_BookmarkClipper`，缺口 5dp）——这是"书签"的唯一语义来源；
- 颜色：`domain/model/tag_color.dart`，`kTagPalette` 8 色 + `defaultTagHex(tag)`。
  用**码位求和**而不是 `String.hashCode`：后者不保证跨版本/跨平台稳定，
  一变整批标签就换色，"按色彩分类"就废了；
- 用户可改：长按书签 → 单个标签配色；卡片菜单「标签颜色」→ 该卷全部标签配色。
  存 `tag` 表（name → color），空串 = 回到自动分配的默认色。

### 1.3 卡片上不再画标签 chip

标签的名字已经在书签上了；再画一排 chip 会跟书签重复，也挤掉文件夹 chip。
列表卡最多 3 枚、大图卡最多 2 枚（宽度不够就截断，形状不变形）。

## 2. 嵌套文件夹（用户第 8 条）

### 2.1 为什么必须换表

旧实现把文件夹名存在 `workbook.folder`（字符串）+ setting 里的空文件夹名列表。
名字字符串只能表达**一层**，而且改名要批量 UPDATE。v4 加表：

```sql
CREATE TABLE folder(id, name, parent_id, color, sort);
ALTER TABLE workbook ADD COLUMN folder_id TEXT NOT NULL DEFAULT '';
CREATE INDEX idx_folder_parent ON folder(parent_id);
```

`workbook.folder` 旧列保留不删（迁移只追加），`FolderDao.migrateLegacyNames()`
在书架首帧把旧名字一次性搬成 folder 行并回填 `folder_id`（幂等）。

### 2.2 UI

- 文件夹条按"在最里面的位置"排：`‹ 上一层` → `全部` → `未分类` → 当前层子文件夹 → `新建`；
- 有子文件夹的 chip 末尾加 `›`（传 `foldersWithChildren` id 集合，不传整棵树）；
- 文件夹有颜色（8 色板，与标签共用）→ chip、卡片上的归属 chip、树里的图标都跟着变色；
- 新建：文件夹条上的「新建」建在**当前层**；长按文件夹 →「在里面新建文件夹」可直接建子级；
- 删除：删整棵子树，里面的卷变成**未分类**（不是"回到上一层"，文案已按实际行为改写）。

## 3. Obsidian 式树视图（用户第 9 条）

### 3.1 位置与形态

切换入口按用户要求放在**主页上部工具栏**的「视图」菜单：列表 / 大图 / **树形** / 卡片大小。
树形是单栏纯文本树（`ui/bookshelf/shelf_tree.dart`，公开 `ShelfTree` 便于单测）：

- 文件夹行：展开箭头 + 带色文件夹图标 + 名字 + 子树卷数 + 「在列表里查看」；
- **末端只到文件夹**，PDF 只占一行文件名（点一下直接打开，长按出菜单）；
- 未分类是一个虚拟节点（id 为空串），只在真有散卷时出现；
- 树里的「新建文件夹」是自带入口 —— 树视图不显示横向的文件夹条，否则用户没法归类；
- 展开状态存 `bookshelf.expanded`，视图选择存 `bookshelf.tree`（跨会话保留）。

### 3.2 两条实现口径

- **先自己的卷、再子文件夹**：点开一个文件夹，它的卷就在名字下面，
  不会被一条很长的子树推到屏幕外；
- **搜索时剪枝**：只保留"含有匹配卷"的那条链（`folderPath` 求祖先集合），
  否则几十个空文件夹会淹没结果；搜索时自动展开命中的层级。

### 3.3 真机踩到的坑

`IconButton` 默认 `tapTargetSize: padded` 会给 48×48 的点击区，
放在 30dp 宽的位置里被裁成**半个图标**（2120×3000 上第一版就是这样）。
解法：`IconButton.styleFrom(tapTargetSize: MaterialTapTargetSize.shrinkWrap)`。

## 6. 已知限制（不是 bug，是取舍）

1. **书签最多 3 枚**（大图卡 2 枚）：宽度有限，多了会糊成一条彩带；超出的标签仍可从卡片菜单看到。
2. **树视图不支持卡片大小/双指缩放**：树里没有卡片，缩放没有意义。
3. **树视图里「全选」仍按列表口径**（当前文件夹），因为树的可见集合与 `_visibleOf` 不同口径；
   实际使用中树视图一般停在"全部"，影响可忽略。
4. **文件夹没有"拖动改父级"**：移动文件夹要重新建 + 移卷。拖动改父级需要一整套拖放命中判定，
   这一轮的收益不值这个复杂度。
