## 1. 用户报的"翻看几次后页面刷新但无法显示"

### 1.1 先把它变成可复现的失败测试

现象只有一句，但足够指向一条链路：滚动模式会 `prefetch` 下一页，`PageLayer` 会
`obtain` 当前页；两者**同时要同一页同一宽度**时会发生什么？

写了 `test/page_image_cache_test.dart`，模拟：

1. `prefetch(3, 240)` 发起在途渲染；
2. 30ms 内 `obtain(3, 240)` 加入同一个在途请求；
3. `PageLayer` 离开可见集，`dispose()` 自己那份；
4. 再 `obtain(3, 240)`。

旧实现直接失败，异常原文：

```text
Bad state: Cannot clone a disposed image.
  dart:ui                                               Image.clone
  package:shuaqi/ui/reader/page_image_cache.dart 58:48  PageImageCache.obtain
```

### 1.2 根因：在途请求把"缓存原图"交给了调用方

旧 `PageImageCache` 的 `_inflight` future 有两条出口：

| 路径 | 旧行为 |
|---|---|
| `prefetch` | 渲染完 → `_store` → **返回缓存原图本身**（只给缓存加热，不 clone） |
| `obtain` 撞上在途请求 | 加入同一个 future → **拿到的也是缓存原图本身** |

于是 `PageLayer` 把缓存原图当成自己的句柄，在离开可见集时 `dispose()` 掉；
缓存 `_entries` 里留下一张**已销毁的图**。下一次命中时 `hit.image.clone()` 直接抛异常
（或让 RawImage 画不出来）——**这一页从此"刷新了也显示不出来"**。这与用户描述的
"翻看几次之后"完全吻合：只有"预热与取图撞在同一页"时才种下这颗雷。

### 1.3 修法：契约写死，任何调用方都只拿 clone

`PageImageCache` 现在只有一条交付约定：

```text
缓存自己持有原图；
obtain() 的每一个调用方都拿到独立的 clone；
prefetch() 不向任何人交出句柄；
调用方 dispose 自己那份，不影响缓存、不影响别人。
```

具体加固：

- `_inflight` future 的结果明确是**缓存原图**，`obtain` 等到后统一 `clone` 再返回；
- 命中缓存 → 取出、移到队尾、clone；clone 失败（历史遗留的脏条目）→ 丢弃并重新渲染；
- 在途结果刚进缓存就被别的页挤掉 → 自动重取一次（不会长循环，`trim` 至少保留 1 条）；
- `_store` 遇到同键旧值先释放，避免"只加不减"；
- `dispose()` 置 `_disposed`，在途渲染返回时自行销毁，不再往已关闭的缓存里塞图；
- 所有清理路径 `_disposeQuietly`，不让一张图的重复销毁把整页搞崩。

### 1.4 顺带修掉三个同链路隐患

| 隐患 | 后果 | 修法 |
|---|---|---|
| `deferEviction` 在"笔优先冻结"的手势分支直接 return | 缓存永久停止淘汰，越滚越吃内存 | 该分支补 `_endMotionSoon()` |
| 运动中退出阅读器 / 换卷，`deferEviction` 没复位 | 缓存被下一卷复用后永不 trim | `dispose` 与 `didUpdateWidget` 复位并 trim |
| 重排后在 `build` 里回调父级页码 | 祖先 `setState during build`，转屏后可能整页空白 | 改到 `addPostFrameCallback` |

### 1.5 页面层兜底：不能永远转圈

`PageLayer` 以前取图失败就停在菊花上，用户只能干等。现在：

- 失败先自动重试一次（450ms）；
- 仍失败 → 显示"这一页没显示出来 + 重试"（缩略图小格子只放刷新钮）；
- 重试成功自动恢复，`debugPrint` 留下页码 / 宽度 / 错误，真机排查不用猜。

## 3. UI 设计 v3：把"系统与骨架"补成一套能落地的皮肤

### 3.1 设计令牌与主题

- **字阶补齐 15 级**：之前只定义了 9 级，`titleSmall` / `labelMedium` 落到 Material
  默认值，中英混排明显"不是一套字"。现在每级写死字号/字重/行高/字距，
  `leadingDistribution: even`，并给中文/英文分别配 fallback（Noto Sans CJK SC /
  PingFang SC / Microsoft YaHei）。
- **浅色表面改为手调中性偏暖灰白**（`ShqLight`）：seed 派生的表面带冷紫，与"暖白纸感"
  相冲。主色仍由 seed 派生，只负责"可点/选中"。
- **组件主题一次收口**：输入框、对话框、底部浮层、菜单、列表行、chip、分段按钮、
  滑块、Switch、FAB、进度、滚动条、Tooltip、SnackBar、按钮全部在 `ThemeData` 定一次；
  页面只写布局，不写皮肤。
- 暗色层级按新表面阶梯复核（卡片 / 浮层 / 菜单 / 对话框分别高一档，靠发丝线分层）。

### 3.2 设置页

- 每行**图标 + 标题 + 说明**；行间发丝线缩进 64dp，与文字左缘对齐；
- 主题 / 默认模式改为**整宽分段选择器**（图标 + 文字，适合平板触控）；
- 纸感增加**真实预览块**（纸色 + 标题 + 题干 + Aa），选色/拖强度时即时反映；
- 「关于」改成品牌块（"刷"字徽标 + 名称 + 版本）；
- AI / 存储仍置灰 + 标注路线图位置（T6.1 / T7.5），不做假入口。

### 3.3 书架

- 卡片重排：64×88 缩略图（发丝边 + 极浅投影）、标题、带图标的"页数 / 最近"、文件夹与标签 chip；
- 修掉一个**假入口**：原先右上角 `more_vert` 图标没有点击处理，现在就是长按菜单入口；
- 文件夹 chip 支持**长按改名**（补上 027 遗留的 `renameFolder` UI 入口）；
- 搜索框：有内容才出现清除钮、胶囊形焦点描边；
- 筛选为空时给"清除筛选"动作（动作图标不再固定成书本）；错误态换成软圆底 + 重试。

### 3.4 记录 / 错题本

两页从"只有一句暂无"改成**诚实的路线图预览页**：品牌软圆图标 + "规划中"标签
+ 三条"将来会有什么"（作答时间线 / 三态判题 / 回看原卷；待复核题 / 原卷笔迹 / 二刷）。
没有任何可点的假数据，唯一动作"去书架"是真的。

### 3.5 阅读器

- 顶栏分组：撤销/重做｜缩放胶囊｜显示｜更多；"切模式 / 缩略图"收进更多菜单，
  窄屏不再把标题挤没（<600dp 时缩放只显示图标）；
- 底部页码改成胶囊 + 网格图标 + 淡入淡出的页码（等宽数字，快速翻页不跳）；
- 缩略图抽屉重做：标题 + 总数 + 关闭、当前页主色描边、每张缩略图右下角页码；
- 固定工具带在窄屏改为**横向滚动**，右侧"改为浮窗"始终可见（消除 RenderFlex overflow）。

### 3.6 应用外壳与空态

- 侧边 rail 顶部换成"刷"字徽标；rail 与内容之间用发丝线；底部导航加顶部分界线；
- `EmptyState` 的动作图标改为可传参（"清除筛选"不再显示书本图标）。

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 手机 360dp 顶栏仍偏紧 | 缩放已缩成图标；再窄需要把撤销/重做也收进菜单，当前不做（主战场是平板） |
| UI v3 仍不是"重画一套插画" | 没有引入图片资源，靠软底图标/发丝线/字阶；记录/错题仍是路线图预览，等 T7 真数据 |
| 取图失败只自动重试一次 | 真实 OOM 下会停在"点按重试"，这是有意的（避免反复点火） |
| 50 页压力测试卷是合成内容 | 只验证显示链路与滚动，不代表真实排版/识别 |
| 缓存契约是红线 | 以后改 `PageImageCache` 必须保留"每个调用方独立 clone"，否则同款空白会复发 |
