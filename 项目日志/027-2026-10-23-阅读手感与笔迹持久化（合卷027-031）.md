## 1. 滚动：可缩放卷轴的定版口径

**结论**：1.0 仍是 fit-width（页宽 = 视口宽），但默认与最小值都下移到 1.0 以下。

| 量 | 旧 | 现有（`scroll_view.dart:144`） |
|---|---|---|
| 默认 | 1.0，贴满屏 | **0.86**（页宽占 86%，两侧留白，与翻页模式观感一致） |
| 最小 | 1.0，不能缩小 | **0.45**（整页浏览；横向自动居中，走 `ScrollMath.clampOffset`） |
| 最大 | 4.0 | 4.0 |
| 档位菜单 | 100/125/150/200% | **60/86/100/150/200/300%**（`reader_top_actions.dart:329` `_steps`，原写在 `reader_page.dart`，v3 顶栏分组时抽出） |

旧规则"最小 = fit-width"有两个必然后果：横向被 `clampOffset` 夹死（内容宽 == 视口宽，任何横移都被吃掉）、页面永远贴边（1px 抖动都看得见）。下移最小值后，"内容窄于视口 → 居中"的分支才真正生效。

### 1.1 跟手三处（现象 → 根因 → 修法）

| 现象 | 根因 | 修法 |
|---|---|---|
| 起手有死区、之后永远落后手指 18dp | `GestureDetector` 默认 `DragStartBehavior.start`，`onScaleStart` 焦点取"越过触摸阈值那一刻"，前面那段位移被永久丢掉 | `dragStartBehavior: DragStartBehavior.down`（`scroll_view.dart:1033`），基准取按下点，越阈值时一次补上，之后 1:1 |
| 拖动中整页重建 | `_updateCurrentPage` → `onPageChanged` → 父级 `setState`（顶栏/工具条/两个视图全重建）发生在拖动过程中 | 手势/甩动期间只更新内部 `_pendingPage`，抬手后 `_flushPendingPage` 补发一次（`:812/:841`） |
| 跨页频繁重建页面列表 | 构建范围 == 可见集，贴着视口边界时会来回跨页 | 构建范围左右各多一页（`:971`），跨页重建从"每页几次"降到"每页最多一次"，代价是离屏多一张位图 |

**证据**：慢速拖动 80px（2 秒）用"页间缝隙的 y 坐标"量实际位移 —— 修复前 ≈16–20px，修复后 **80px**（1:1，无死区）。帧耗时 raster 中位 2.1–3.3ms、超 60Hz 预算 0–2%、最差帧 5.0ms（HUD，与 026 同口径）。

### 1.2 边界：橡皮筋 + 欠阻尼弹簧

不再是硬夹紧 + `ticker.stop()`（手感是撞墙）。

- 拖动越界：`_rubberBand`（`:387`）`f(o) = (1 − 1/(|o|/c + 1))·c·sign(o)`，**c = 0.35·该方向视口尺寸**。o=0 处导数为 1（起手跟手），越拉越钝，极限 ≈1/3 屏；
- 松手时已越界：立刻回弹不甩动，初速度 = 释放速度 ×0.6；
- 甩动中撞边界：不再 `stop()`，余速交给弹簧（先越出一点再弹回）；
- 弹簧 `a = −260·位移 − 26·速度`（`_bounceStiffness/_bounceDamping`），ζ = 26/(2√260) ≈ 0.81，轻微过冲一次。

**证据**：顶部边界慢速下拉 3000ms（手指拉了约 1000px），拖动中顶边 y = **492**（越界 242px ≈ 24%，与曲线吻合）；松手 1.2s 后 y = **250**（精确回到边界，无残留）。

### 1.3 斜向滑动：按可滚方向决定轴（029 结论已被推翻）

029 的"竖轴偏好 0.7 + 6dp 判定阈值 + 起手即锁竖轴"**已废弃**。现在按"哪个方向真有可滚余量"决定，两轴都能滚时**自由斜滑**。

```text
DragAxisLock.decide(allowHorizontal, allowVertical)   // domain/reader/scroll_math.dart:121
  两轴都可滚          → DragAxis.free      （两轴都收，斜向 1:1）
  只有横能滚          → DragAxis.horizontal
  只有竖能滚 / 都不能滚 → DragAxis.vertical
project(dx, dy, axis) → vertical:(0,dy) / horizontal:(dx,0) / free:(dx,dy)
```

- 余量由调用方算：`contentSize * scale > viewport + 0.5`（`scroll_view.dart:599`）；
- 为什么不再用角度猜：角度猜测只在"两轴都能滚"时有意义，而那正是要自由斜滑的场景。旧口径下放大到 200% 后竖滑被锁竖轴，满足不了"上下左右都要能滑，也要能斜着滑"；
- 单轴模式仍投影 —— 那一轴的另一分量会被夹紧或橡皮筋吃掉，不投就是"滑了很长距离页面只走一点"；
- 橡皮筋只在锁定轴生效（`overscrollVertical/Horizontal` 按轴开关，`:656`）；甩动速度同样投影，斜着甩不会横着飘；
- 自由模式用**增量**累加而非"起点 + 总位移"（down→越阈值那一段不会一次性补进来）；单轴模式仍用绝对投影，避免累计误差把锁定轴带偏；
- 双指捏合期间不做轴处理（捏合本来就是两轴同时变）。

**证据**：`test/drag_axis_lock_test.dart` 7 例钉住判定与投影。真机暗纸卷 45° 斜拖 1000×1000、3 秒：拖动中左右留白对称（≈105 / 1435 预览像素），与静止时一致 → 零横向漂移；同一手势内内容从第 17/18 题滚到第 13/14 题 → 竖向位移完整生效。
> 测量方法上的坑：本想用像素测"横向位移 = 0"，但暗纸下纸面与背景只差 ~10 灰阶，边缘检测噪声大于信号（实测 2421/2509/2365 波动），改用"留白是否对称"这种目视可判指标 + 单测钉数学。

**涉及文件**：`domain/reader/scroll_math.dart`、`ui/reader/scroll_view.dart`

## 2. 位图缓存契约与"翻几次后页面空白"

### 2.1 根因（030 的核心）

**现象**：滚动模式"翻几次后页面刷新了却显示不出来"。

**根因**：`PageImageCache` 的 `_inflight` future 有两条出口 —— `prefetch` 与撞上在途请求的 `obtain` **都拿到缓存原图本身**。于是 `PageLayer` 把原图当自己的句柄，离开可见集时 `dispose()` 掉，缓存 `_entries` 里留下一张**已销毁的图**；下次命中 `hit.image.clone()` 直接抛：

```text
Bad state: Cannot clone a disposed image.
  dart:ui                                               Image.clone
  package:shuaqi/ui/reader/page_image_cache.dart 58:48  PageImageCache.obtain
```

只有"预热与取图撞在同一页同一宽度"时才种下这颗雷，所以症状是**翻几次之后**才出现。

**修法**：契约写死（`ui/reader/page_image_cache.dart`）：

```text
缓存自己持有原图；
obtain() 的每个调用方都拿到独立 clone，各自 dispose 自己的那份；
prefetch() 不向任何人交出句柄（只加热）；
在途 future 的结果是缓存原图，obtain 等到后统一 clone 再返回。
```

配套：命中 → 移到队尾 → clone，clone 失败（历史脏条目）→ 丢弃重渲染；在途结果刚进缓存就被挤掉 → 自动重取一次（不会长循环，`_trim` 至少保留 1 条）；`_store` 同键旧值先释放；`dispose()` 置 `_disposed` 守卫；所有清理走 `_cloneQuietly`/`_disposeQuietly`。

> **红线**：以后改 `PageImageCache` 必须保留"每个调用方独立 clone"，否则同款空白复发。回归用例 `test/page_image_cache_test.dart` 3 例（含旧实现必失败的事故复现）。

### 2.2 顺带修掉的三处同链路隐患

| 隐患 | 后果 | 修法 |
|---|---|---|
| `deferEviction` 在"笔优先冻结"的手势分支直接 return | 缓存永久停止淘汰，越滚越吃内存 | 该分支补 `_endMotionSoon()`（`:489`） |
| 运动中退出阅读器 / 换卷，`deferEviction` 没复位 | 缓存被下一卷复用后永不 trim | `dispose` 与换卷分支复位并 `trim()`（`:252/:285`） |
| 重排后在 `build` 里回调父级页码 | 祖先 `setState during build`，转屏后可能整页空白 | 改到 `addPostFrameCallback`（`:956`） |

### 2.3 清晰档与缓存容量

| 量 | 值 | 说明 |
|---|---|---|
| 位图宽上限 | **3200px** | 3200 而非 4096：A4 在 3200 宽时一页 ≈52MB，视口 ±1 三页 ≈156MB。代价：200% 以上放大清晰度从 1:1 降到 0.75:1，真无损要等分块渲染 |
| 清晰档 | 0.45 / 0.6 / 0.75 / 0.86 / 1 / 1.25 / 1.5 / 2 / 2.5 / 3 / 3.5 / 4 | 相邻档比值 ≤1.25，肉眼看不出差别；向下扩展是为缩小后按实际像素出图，0.45 档 1350px 宽 ≈11MB |
| 停手升档 | **220ms**（`_qualityDelay`） | 捏合过程中不升级，避免位图风暴；停手后取 `>= scale` 的最小档 |
| 缓存上限 | **320MB** | 200→320MB（实测）：一页 A4 在 3000px 宽下 51MB，"视口 2 页 + 预热 1 页 + 刚离开还没丢的 1 页"正好 204MB，卡在 200MB 上就是每帧淘汰 + 上传纹理，HUD 抓到单帧 30ms 顿挫 |
| 运动期间 | `deferEviction = true` | 边进边淘汰会造成纹理 churn；运动中不淘汰，停手后 `_endMotionSoon` 在**下一帧**（停手那帧往往还有纹理在上传）统一收敛 |
| 淘汰 | 按字节 LRU，至少保留 1 条 | 不按页数定容量：1x 缓 16 页合理，4x 时同样 6 页直接 OOM |
| 预热 | `prefetch` 前后页 | 翻到新页才渲染会有 12ms 渲染 + 解码 + 首帧的顿挫 |

- 位图宽 = `(baseWidth × dpr × bucket).round().clamp(1, 3200)`；缓存键 `'$pageIndex@$widthPx'`（用像素不用比例，避免浮点误差导致同页反复渲染）；
- 位移对齐到物理像素再发给矩阵层（`_publishCamera`）：半像素偏移会触发双线性重采样，既糊又慢、滑动时能看见细小抖动；取整后在 400dpi 屏上每 0.4dp 一格，看不出台阶。

### 2.4 页面层兜底

`ui/reader/page_layer.dart`：取图失败先自动重试一次（**450ms**），仍失败 → 显示"这一页没显示出来 + 重试"（缩略图小格子只放刷新钮），成功则自动恢复，并 `debugPrint` 留下页码/宽度/错误。**有意只自动重试一次**：真实 OOM 下停在"点按重试"，避免反复点火。

### 2.5 证据

- 宿主机：analyze 0；148 测试通过（+7：`page_image_cache_test` 3、`page_layer_test` 1、`ui_widgets_test` 3）。
- 真机 50 页压力卷（`synthetic_50p.pdf`）：连续 40 次快速上滑（1 → 35/50）无空白、无"取图失败"日志；继续 25 次到 50/50 再反向 70 次回 1/50，第 1 页正常显示（事故点回归通过）；4 页数学卷在 60%/86%/200% 三档来回、切模式、开缩略图跳页后再翻均正常。
- 截图：`main/demo_assets/verify/2026-10-23-ui-v3/`（11 张）。测试卷已从设备删除，书架回到原来的 2 卷。
- 已知：50 页卷是合成内容，只验证显示链路与滚动，不代表真实排版/识别。

**涉及文件**：`ui/reader/page_image_cache.dart`、`ui/reader/page_layer.dart`、`ui/reader/scroll_view.dart`、`infra/pdf/pdf_source.dart`（`PageBitmapSource`：`pageCount` + `renderUiImage(index, {widthPx})`）、`infra/pdf/pdfrx_source.dart`

## 3. 笔刷：粗细 0..100 与笔尖大小参考圈

### 3.1 粗细口径

`InkStroke.widthLevel(0..2)` → **`brushWidth` 0..100**（`domain/ink/ink_doc.dart`）。选 0..100 是因为整数正好 1 字节，SIF 里与三档枚举代价相同，数据契约不用再改。

| 笔 | 0 | 100 | 压感 |
|---|---|---|---|
| 钢笔 | 0.8pt | 5.2pt | ×(0.55 + 0.65·p)（轻 55%、重 120%） |
| 圆珠笔 | 1.0pt | 4.0pt | 等宽，不响应 |
| 荧光笔 | 6pt | 36pt | 等宽，不响应 |
| 橡皮 | 4pt 半径 | 28pt 半径 | 等宽 |

常量在 `domain/ink/ink_width.dart`（`baseOf/rangeOf/levelOf/widthOfLevel/clampBrushWidth`）与 `domain/ink/eraser.dart`（`radiusOfWidth`；旧三档默认 12pt ≈ 33% 档 = A4 页宽的 2%）。

**绘制口径**：Canvas 一条 Path 只能有一个 strokeWidth。活笔与已提交笔统一走"量化成有限档，每档一条 Path"（`InkWidth.levels = 24`，按这一笔的实际区间归一，不是全局固定步长）且共用 `InkRibbon`，修掉了早先"逐段 drawLine 画活笔 / 量化档画死笔"导致的**抬笔瞬间粗细突变**。

### 3.2 坑：旧持久化值被当成新语义

粗细从三档变 0..100 后，`setting` 里旧的 `pen:2:2` 被解析成 **2%**，真机笔迹直接细成发丝（截图对比确认）。

**修法**：持久化串加格式版本前缀（`domain/ink/ink_brush.dart:88`）：

```text
新：v2:pen:0:50;v2:highlighter:2:85        （版本:tool:color:width）
旧：pen:0:2  → 无 v2: 前缀，按 0/1/2 映射到 15/50/85（legacyWidthMap）
```

解析失败一律跳过该条，全部失败由调用方用默认值兜底，绝不抛。工具条形态三处入口（顶栏「改为浮窗」、浮窗面板「固定到顶栏」、设置页开关）共用一份状态 `inkToolbarPinnedProvider`，落盘键 `ink.toolbar_pinned`。

### 3.3 大小参考圈（笔尖提示）

027 的"一个按真实大小画的圈，最小 14dp"**已被 028 推翻**。改成两个元素（`_HaloLayer`，`ui/reader/ink_layer.dart:724`）：

| 元素 | 尺寸 | 作用 |
|---|---|---|
| 实心点 | `real = (radiusPt × 2 × scale).clamp(3.0, 480.0)` dp = 真实笔尖/橡皮直径 | "这一笔有多粗"——参考的语义 |
| 定位环 | `max(real, 26.0)` dp，1.4dp 描边 + 6% 填充 | 把视线钉在最后落笔位置（细笔也看得见） |

根因：钢笔在 0.86 倍下最细档是 `0.8pt × 1.42 × 2 ≈ 2.3dp`（8 个物理像素），等于没提示；荧光笔/橡皮 12–28pt 圈很大 —— 所以旧版"只有大笔刷看得见"。

**动画**（027 是 `ValueNotifier<Offset?>` 硬切，用户反馈"不自然、隐退没做好"）：位置 `_halo` 与进度 `_haloAnim` 分成两个 notifier ——

- 进：**160ms** 淡入 + 缩放 88%→100%（`easeOutCubic`），像"浮起来"；停留 **1100ms**（`_haloHold` Timer）；出：**260ms**（`reverseDuration`）淡出 + 轻微收缩，**淡出结束才置 `_halo = null` 拆位置**（避免"消失瞬间还能看到一点"）；
- 连续改粗细从当前进度续播，不闪；整层 `IgnorePointer`，绝不挡落笔。

**证据**：四种笔都验过 —— 细笔是小点在环里，荧光笔/橡皮的环跟着真实尺寸变大；切荧光笔 60%（≈24pt）时笔画末端浮出 ≈34dp 的淡圈。

**涉及文件**：`domain/ink/ink_width.dart`、`domain/ink/ink_doc.dart`、`domain/ink/ink_brush.dart`、`domain/ink/eraser.dart`、`ui/reader/ink_layer.dart`、`ui/reader/ink_toolbar.dart`、`ui/reader/ink_ribbon.dart`

## 5. 设计系统 v1 → v3

方向：**灵动现代简约**（更圆的外形、发丝线分层、极浅阴影、短促按压反馈）。参考 ColorOS 的圆角与呼吸感、iOS 的入场慢出场快、M3 的表面色分层、微软的信息密度优先。

### 5.1 令牌（`ui/theme/tokens.dart`；纪律：颜色/字号/间距/圆角/时长只从 tokens 取）

| 类 | 值 |
|---|---|

## 6. T2.4：SIF v1 落盘

### 6.1 文件格式（已核到 `domain/ink/sif_codec.dart`）

```text
zlib( Header 16B | Stroke × n | Footer 4B )
Header: 'SIF1' | flags u8 | pageW u16 | pageH u16 | nStrokes u32 | reserved 3B
        pageW/pageH 单位 = 0.1pt（841.89 → 8419；u16 可到 6553.5pt）
Stroke: style u8 | color u8 | width u8 | flags u8 | nPoints u16
        | bbox 4×u16 | t0 u32
        | points(dx,dy zigzag varint) | pressure(4bit × n，两点一字节，低半字节 = 前一点)
Footer: crc32(Header + Strokes) u32     // CRC-32 IEEE 802.3，多项式 0xEDB88320
```

与规格 03-第2周 §T2.4 的**三处有意差异**：① stroke 头加 `color`/`width` 各 1 字节（T2.2 起颜色与粗细写进 `InkStroke`，不存则重启后旧笔变黑/变中粗）；② 每点压力 4bit（`pressureLevels = 15`，规格只写了坐标，但钢笔线宽靠压力，丢了就是"重启后笔迹变一种样子"）；③ 页尺寸用 **0.1pt 定点**存 u16（存整数 pt 会让 841.89→842，在长边上累积约 0.2pt 误差）。

其他约定：

- 坐标量化 `q = round(v / pageSize × 16383)`（`quantMax = 16383`，**不是 16384**），往返误差 ≤ pageSize/(2×16383)，A4 高 842pt 时约 0.026pt；
- 单笔 >4096 点（`maxPointsPerStroke`）拆成多笔同款式碎片，z 序不变、点数不丢；
- **UID 不进文件**（它是会话内身份），解码时用 `Ulid.next()` 重新生成；
- 只存每笔 `t0`，解码时第 i 点 `t = t0 + i`；逐点时间戳不参与屏显/识别，要做速度特征再加 flags 位（v2，不破坏老文件）；
- **bbox 只做结构占位**（合法性校验），解码后用点重算，避免 bbox 与点不一致时相信错的一方；
- **`style u8` 写的是 `InkStrokeStyle.index`：枚举只能追加，不能重排**；
- 解码 `maxOutputSize: 64MB`（防 zip bomb），文件级另有 `SifInkStore.maxSifBytes = 16MB`，超过按损坏处理。

### 6.2 写入链路

```text
save:  查页尺寸 → Isolate.run(encode) → 删旧 .tmp → 旧 .sif rename 成 .bak
       → 写 .sif.tmp + flush → rename 成 .sif → ink_state upsert
load:  查 ink_state.sif_path → 解码主文件；失败读 .bak；两者都失败 → 空页 + InkLoadIssue.corrupt
```

- **防抖与生命周期**：`infra/ink/ink_writer.dart`，500ms 防抖、同页只留最后一次、同页写串行、失败保留快照（等下一次编辑/flush，不无限重试）、`flushAll`。`ReaderPage` 在 paused/detached、退出时 `flushAll`，切页/切模式 flush 当前页。
- **save 不在抬笔路径 `await`**：整页 zlib 编码 + 写盘是 IO，抬笔只改内存 + `schedule`；防抖 500ms 兼作写放大保护，生命周期是最后一道保险。
- **不直接覆盖写**：断电/被杀在 write 中途会留下半个文件。顺序固定为 `旧 .sif → .bak` → 新 `.tmp` → rename 成 `.sif`，任一步失败都把旧版还回主文件。主文件损坏时**先恢复备份、再把备份写回主文件** —— 否则下一次 save 会把损坏主文件 rename 成 `.bak`，覆盖掉唯一的好备份。
- **isolate 兜底**：`Isolate.run` 起不来时退回主 isolate 同步执行（宁可主 isolate 多花几毫秒，也不能让这一笔没写出去）。
- **表状态**：`infra/db/dao/ink_state_dao.dart`，`INSERT ... ON CONFLICT(page_id) DO UPDATE` 维护 `revision / stroke_count / byte_size / sif_path / dirty`。不删旧行再插（删除会触发外键/索引动作，且事务外有"两次操作之间被杀"的窗口）。`dirty` 恒 1（等第 4 周识别）。

### 6.3 损坏兜底与 UI 提示

`InkLoadIssue` + `InkIssueReporter`（不改 `InkStore` 签名）。`ui/reader/ink_layer.dart` 的 `_LoadIssueBanner`：

| 状态 | 提示 |
|---|---|
| 主文件坏、`.bak` 好 | 紫条（`tertiaryContainer`）「已从备份恢复这一页」，并把备份写回主文件 |
| 主/备都坏 | 红条（`errorContainer`）「笔迹文件损坏，已跳过（原文件保留）」，页面为空，不崩 |
| 正常 | 不显示。整条 `IgnorePointer`，不挡笔 |
