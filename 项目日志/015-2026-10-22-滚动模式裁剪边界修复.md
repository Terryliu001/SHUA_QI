## 1. 用户报障

1. 滚动模式**显示不完整**（页面右侧内容被切掉）；
2. 双指缩放后**出现黑边框**，不是自然的整页放大缩小。

## 2. 根因（第三版的结构性错误）

第三版的链路是 `ClipRect → Transform → SizedBox(内容宽)`，问题在于
**`ClipRect` 与 `Transform` 的尺寸都只有"内容宽"**：

```dart
final double baseWidth = math.min(constraints.maxWidth - ShqSpace.sm * 2,
                                  ShqLayout.maxReadingWidth);   // 1200-16 → 880
...
return GestureDetector(child: ClipRect(child: Transform(child: SizedBox(width: baseWidth, ...))));
```

`ClipRect` 的尺寸 = 子节点尺寸 = 880，而外层 `Column` 又按默认
`crossAxisAlignment.center` 把它居中了一次（左边界 160）。于是：

```text
视口 1200 宽
├─ 布局盒 880 宽（Column 居中 → 左边距 160）
│    ├─ 内容坐标再按 _clampOffset((1200-880)/2 = 160) 右移 → 纸面从 320 开始
│    └─ ClipRect 只认 880 宽 → 纸面在 320+880=1200? 不，裁剪盒本身只到 160+880=1040
```

**实测数据（截图像素量测，物理像素 / dpr 2.5）**

| 项 | 修复前 | 修复后 |
|---|---|---|
| 纸面横向范围 | x 800..2598（320.0..1039.2 逻辑） | x 0..2998（0..1199.2 逻辑） |
| 左/右边距 | 320 / 161（**不对称**，且右侧被硬切） | 0 / 0（铺满） |
| 页面内容 | 每行右侧 160pt 被裁掉（"则（D"、"同阶但非等价无穷"） | 完整 |

所以两个报障是**同一个 bug 的两种表现**：100% 时被裁掉右侧（显示不完整），
放大后整个画面被锁在这个 880 宽的窗口里、窗口外露出底色（黑边框）。

### 顺带推翻 014 的一个错误结论

014 的侧记写"第 2 页右侧文字被切是原卷 PDF 排版溢出页框"。**这个判断是错的**：
同一页在分页模式下文字完整（`s14_paged.png` 量测纸面 x 874..2124 居中，内容齐全），
滚动模式下才缺字。就是上面这个裁剪 bug。

## 3. 第四版：三条硬规则

1. **自身撑满视口**：`SizedBox(width: viewport.width, height: viewport.height)` 包住整条链，
   裁剪边界 = 视口边界（不是内容边界）；
2. **1 倍 = fit-width**：`_baseWidth = 视口宽`，任何倍率下都不会出现左右黑边；
3. **缩放只改矩阵不改布局**（第三版这条是对的，保留）：页在 `_baseWidth` 下排一次版，
   屏幕位置只由 `Matrix4(translate × scale)` 决定。

配套修正：

| 改动 | 原因 |
|---|---|
| `reader_page` 的 Column 加 `crossAxisAlignment.stretch` | 双保险：不允许阅读视图被"按自身宽度居中" |
| 重排时保留"当前页 + 页内比例" | 转屏/换窗口尺寸不跳页，实测竖屏切换后仍停在第 3 页 |
| 主可见页改为"重叠高度最大" | 原 `offset / 页高` 算法在 A4/A3 混排时会错（规格 §6.9.2） |
| 位图清晰度改**档位制**（1/1.25/1.5/2/2.5/3/3.5/4） | 捏合中冻结、停手 220ms 升一档，避免"每帧一张新位图" |
| 预热只做下一页 | 整页位图 3000×4243 ≈ 51MB，预热两页会挤爆 200MB 缓存 |

### 焦点缩放的定量验证（这是"捏合是否指哪放大哪"的核心）

adb 注入不了多指，所以用**同一条数学路径**（`setScale`，焦点 = 视口中心）做像素比对：

```text
A(100%) 中 (1060,1264) 处的纹理 patch
  → 按焦点缩放预测：B(200%) 中应在 (620,1404)
  → 实测最佳匹配偏移 (1,-1) px = (0.4,-0.4) 逻辑像素
  → 平均像素差 7.1（对照组故意错位 40px 处为 67.6，差 10 倍）
```

结论：`focalContent = (focalScreen - offset)/scale` 与 `localFocalPoint` 的坐标系是一致的，
中心焦点缩放的落点是准的。**双指捏合用的公式、坐标系与这条路径完全相同**，
剩下的只是"手指捏合"这一层输入分发（`GestureDetector.onScale*`），需手指复验。
