## 0. 怎么检查的

- **一手证据**：`main/lib` 目录结构、`grep` 契约符号（`markSubmitted` / `text_block` / `onnx` / `submission` / `zip` / `斜纹` …）、`pubspec.yaml`、`android/app/build.gradle*`、`git tag`。
- **二手证据**：`项目日志/` 25+2 篇（README §5.4 的真机清单、各轮结论）。
- **判定口径**：✅ 有代码且有日志/真机证据；◐ 有代码但证据不全或只覆盖一部分；✗ 规格要求、代码里没有；⏸ 规格自己标注为"置灰/规划中"。

## 1. 一句话结论

**刷题主链路（导入 → 阅读 → 手写 → 切题 → 逐题作答 → 判题 → AI → 收藏 → 记录 → 导出）已经全通，真机可用。**
但上游规格定义的 MVP 有 **6 项关键能力没有落地**，其中 2 项是规格明写的 P0/核心：**公式识别（P0）**与**交卷结果页**；另有 5 项工程收尾（release 签名、tag、双机、彩排、文档）未做。

## 10. 下一步建议（按优先级）

1. **公式识别（引擎 C）**：唯一被规格列为 P0 却完全空缺的能力。契约已留好（`FormulaEngine`），缺模型转换 + `onnxruntime` 依赖 + 预处理 + 后处理。若确认本期不做，应在 README §5.6 与产品文案里**明确降级声明**（"公式只显示原图"），别留着 P0 的空头支票。
2. **交卷结果页（T5.5 最小版）**：不必做全套快照/对比，先做「一键交卷 → 结果页（对/待判/未判 + 逐题依据 + 再交一次」。这一项同时解锁 T7.1 二刷、T7.2 未归属、边界用例 12，**性价比最高**。
3. **归属引擎（T5.1 纯函数版）**：规则规格写得很死（起笔点 → 重心 → 24pt 最近 → 不强行分配 + 时间修正），100 行纯 Dart + 15 条单测即可交付，直接决定"页内手写"能不能被统计。
4. **识别调度器（T4.3 精简版）**：只做 T1（停笔 800ms）+ T3（擦除）+「800ms 内有笔事件不启动」三条，就能把"停笔出字"立起来；引擎 B 可继续延后。
5. **备份/导出补齐**：zip 备份恢复（`VACUUM INTO` + manifest）+ md 导出，是"数据带得走"的最后一块；存储归档可以继续占位。
6. **工程收尾四项**：release 签名 + tag、产品图标与启动页、README/关于页三条限制、双机验证与彩排。

## 11. 本轮检查的方法论备注（给下一次）

- 判「有没有」最可靠的是 grep 契约符号：`markSubmitted`（交卷）、`text_block`（修订链）、`onnx`（公式）、`domain/assignment`（归属）、`斜纹`（重叠提示）。空命中比读注释可靠。
- 判「做没做完」要看设置页里的 `locked: true` 占位——本项目用"诚实置灰"代替假按钮，所以**置灰项就是缺口项**，一处不漏。
