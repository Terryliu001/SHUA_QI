## 1. 分层与 §7 契约（骨架）

### 1.1 为什么先做骨架

规格要求阶段 0 完成后再进第 1 周，但阶段 0 剩下的全是**必须真机取数**的项（T0.2 性能、T0.3 准确率、T0.4/T0.5 计时）。骨架与契约不依赖任何设备决策——画布方案与 PDF 库的选择只影响 reader 内部，不影响 `ui → state → domain` 的分层、不影响 §7 的接口签名。**等平板期间做它，不视为跳阶段。**

### 1.2 分层落地

依赖方向单向：`ui → state → domain`，`infra` 实现 `domain` 里的契约，`domain` 不依赖任何一方。

| 层 | 代表文件 | 职责 | 不允许 |
|---|---|---|---|
| ui | `ui/app.dart`（唯一 `MaterialApp`）、`ui/router.dart`、`ui/theme/tokens.dart`、`ui/theme/app_theme.dart`（唯一 `ThemeData` 构造点）、`ui/errors/error_handling.dart` | 展示、路由、主题、错误兜底 | 直接读 DB / 文件 |
| state | `state/app_providers.dart`、`state/reader_providers.dart` | 纯状态与用例入口、依赖装配 | import `ui/` |
| domain | `domain/ink/*`、`domain/reader/reader_prefs.dart`、`domain/model/*`、`domain/util/ulid.dart` | 值对象、接口契约、纯函数 | 出现 `flutter/*`、`dart:io`、`dart:ui` |
| infra | `infra/db/*`、`infra/pdf/*`、`infra/vault/*`、`infra/ocr/*`、`infra/formula/*`、`infra/ai/*` | 实现契约、真 I/O | 被 `domain` 反向 import |

分层规则写成 4 条 `test/architecture_test.dart` 用例：domain 无平台依赖、ui 不被下层反向 import、主题单点（全项目只有 `app_theme.dart` 造 `ThemeData`）、`MaterialApp` 唯一。

**验证测试本身有效**：在 `domain/ink/ink_doc.dart` 顶部故意加 `import 'package:flutter/material.dart';`，`flutter test test/architecture_test.dart` 立刻报「domain 层出现了平台依赖」；删掉即绿。口头约定会被违反，测试会在 CI 与本地同时生效。

### 1.3 §7 七个契约（签名原样保留，一律 `abstract interface class`，不写空实现）

| 接口 | 位置 | 实现任务 | 实现方必须记住的最后一条 |
|---|---|---|---|
| `InkStore` | `domain/ink` | T2.4 | 原子写（临时文件 + rename），并发调用要排队 |
| `PdfSource` | `infra/pdf` | T0.4 / T1.5 | 出本层前坐标翻成左上原点、单位 pt；`maxEdgePx` 由调用方乘过 dpr |
| `PaperRenderer` | `infra/pdf` | T1.6 | 按 `(page, style, intensity)` 缓存；`original` 走零处理分支 |
| `OcrEngine` | `infra/ocr` | T4.1 / T4.2 | 失败/取消返回 `OcrOutput.empty`，**不抛异常** |
| `FormulaEngine` | `infra/formula` | T4.5 | 未就绪返回 `false` → 调用方静默退裁图，不许弹窗 |
| `MathView` | `ui/widgets/math` | T6.7 | 渲染失败必须返回 fallback，绝不返回空白 |

2. `InkDoc` 不可变，`append()` 返回新实例并 `revision + 1`——异步回写的版本校验（INV-02）才有依据。
3. `ReaderPrefs.fromJson` **任何非法值都回落默认、绝不抛**。

## 2. 数据库与迁移（T1.2）

### 2.1 目标与结果

手写 SQL、不用 codegen；时间一律 UTC 毫秒；`onConfigure` 开 `foreign_keys`；旧库升级后原数据仍在。六表 DDL 逐字照抄 §5.2，不改列名。

### 2.2 六张表 + v2 的 setting

| 表 | 主键 | 关键约束 / 列 | 用途 |
|---|---|---|---|
| `workbook` | `id` TEXT | `sha1 UNIQUE`、`page_count`、`page_size`、`source_path`、`layout_status DEFAULT 'none'` | 一份卷；sha1 做导入去重 |
| `wb_page` | `id` TEXT | `workbook_id` FK CASCADE、列名 `idx`、`w/h`、`UNIQUE(workbook_id, idx)` | 页与页尺寸 |
| `session` | `id` TEXT | `workbook_id` FK、`seq`、`state DEFAULT 'draft'`、`last_page DEFAULT 0`、`UNIQUE(workbook_id, seq)` | 一次作答；进度落在 `last_page` |
| `question` | `id` TEXT | `ordinal`、`level DEFAULT 2`、`parent_id`、`kind`、`confidence`、`source DEFAULT 'rule'` | 题号树 |
| `question_region` | `id` TEXT | `question_id` / `page_id` 双 FK CASCADE、`x/y/w/h`、`role`、`locked` | 题目→页上矩形 |
| `ink_state` | `page_id`（一页一行） | `revision`、`stroke_count`、`dirty`、`sif_path`、`dirty_since` | 墨迹元数据（正文在文件） |
| `setting` | `k` TEXT | `v` TEXT | **v2 新增**：`reader.*` 键值 |

**为什么 setting 单独放 v2**：T1.2 要求"本周只建 6 张表"，但本周就要写 `reader.default_mode`。与其硬塞进 v1，不如让 v1 严格等于规格的 6 张，v2 加 `setting`——顺带让迁移机制有了第一个真实用例。

### 2.3 迁移机制

`lib/infra/db/migrations.dart` 只有一份 `kMigrations`（`version` + `statements` + `note`），三条规则写在文件头：**① 只追加，不修改历史版本**；② 每个 Migration 只做一件事；③ 迁移里不写业务数据，默认值用列上的 `DEFAULT`。

- `kDatabaseVersion` = 最后一版的 `version`，不另设常量；
- `statementsBetween(from, to)` 按版本升序摊平成语句列表，`open(targetVersion)` 执行；
- 事务入口 `tx`，关闭 `close`。

`Session` 的推进用 `WHERE state = ?` 兜底：`markSubmitted` 只对 `draft` 生效，返回 0 表示状态不对。

### 2.4 DAO

| DAO | 方法 |
|---|---|
| `workbook_dao` | `insert` / `listByRecent` / `bySha1` / `byId` / `touchOpened` / `rename` / `delete` |
| `page_dao` | `insertMany` / `pagesOf` / `byIndex` / `countOf` |
| `session_dao` | `createDraft`（自动 `seq`）/ `latestForWorkbook` / `updateLastPage` / `markSubmitted` / `archive` |

ULID 自己实现（`domain/util/ulid.dart`，Crockford Base32、128 位、不引包、含 `timestampOf` 回读），6 个宿主机用例覆盖。

### 2.5 架构事故：测试金字塔被环境逼着改

加入 `pdfrx` 后 `flutter test` 直接挂：

```text
pdfrx_pdfium_gate.c(17): fatal error C1083: 无法打开包括文件: "windows.h"
Building native assets failed.
```

**根因链**：`pdfrx → pdfium_dart` 是 native assets 包 → `flutter test` 在宿主机 Windows 上也要编译它的 gate 库 → 编译需要 Windows SDK 头文件 → `native_toolchain_c` 通过**查注册表**（`reg.exe`）定位 SDK → **本机沙箱禁止 `reg.exe` 启动** → INCLUDE 里没有 Kits 路径。

两条死路都试过：`flutter config --no-enable-native-assets` 被 `flutter test` 直接拒绝；手动补 `INCLUDE` 无效（hook 进程的 INCLUDE 由 `native_toolchain_c` 自己重建）。`sqflite_common_ffi` 同理。

**解法两条**：

1. **pdfrx 暂时移出 `dependencies`**；spike 归档到 `spikes/_archive/pdf_spike/` 并在 `analysis_options.yaml` 里 exclude；T1.5 加回来时同时重跑 `tool/patch_pdfium_mirror.py`。
2. **DB 测试搬到 `integration_test/`**，跑真机 sqflite：`flutter test integration_test/db_test.dart -d <设备>`。比桌面 ffi 更真，代价是必须有设备。

顺带一个坑：`flutter test -d <设备>` 同样会被 `http_proxy` 打断（`WebSocketException: ... was not upgraded`），必须清代理变量再跑。

## 3. Vault 与导入管线（T1.3）

### 3.1 目标

把"用户选的 PDF"变成"书架上一张卡"：路径约定单一入口、原子写、按内容去重、崩溃不留半截、缩略图可重建。

### 3.2 分层与关键文件

| 文件 | 职责 |
|---|---|
| `infra/vault/paths.dart` | `VaultPaths`：所有相对路径的**唯一**拼装入口 + `workbookIdOf()` |
| `infra/vault/vault.dart` | `open`/`file`/`ensureDir`/`writeAtomically`/`adoptFile`/`deleteWorkbook`/`workbookIdsOnDisk` |
| `infra/vault/file_hash.dart` | `sha1OfFile`：流式算指纹，禁止 `readAsBytes` |
| `infra/pdf/pdfrx_source.dart` | `PdfrxSource implements PdfSource`（+ `renderRaw` / `renderThumb` / `encodePng`） |
| `app/bootstrap.dart` | `AppDependencies` + `bootstrap()`：DB + Vault + 启动清孤儿 |
| `app/import/import_workbook.dart` | `WorkbookImporter` / `ImportOutcome` / `sweepOrphans` |
| `ui/bookshelf/bookshelf_page.dart` | 真列表（缩略图 + 标题 + 页数 + 相对时间）+ 导入按钮 + 空态/错误态 |

依赖变化：**加回 `pdfrx 2.9.0`**，新增 `file_picker 13.1.0`、`crypto 3.0.7`（全在白名单内）。

### 3.3 管线步骤与每一步的失败处置

| 步骤 | 动作 | 失败时 |
|---|---|---|
| 1 选取 | `FilePicker.pickFiles(...)` 拿 `PlatformFile` | 取消 → 返回空，不落任何目录 |
| 2 落地 | 先复制到 cache 再用 | 国产 ROM 的 content URI 不能 `File(uri.path)` 直读 |
| 3 指纹 | `sha1OfFile` **流式**（不许一次读 20MB 进内存） | 抛异常 → 删除 cache 副本 |
| 4 去重 | `workbookDao.bySha1` 命中 → `touchOpened` 并返回既有 id | 不新建目录（幂等的核心） |
| 5 建目录 | `ensureDir(workbooks/<ULID>)` | 失败直接抛 |
| 6 原子写 | 写 `source.pdf.tmp` → `rename` 成 `source.pdf` | 中途崩溃只留临时文件/孤儿目录 |
| 7 事务落库 | `tx` 内写 `workbook` + `wb_page` 全部页 | 异常回滚 → 再删整个目录，**不留半截记录** |
| 8 缩略图 | 前 3 页 + 末页 + 之后每 10 页一张，宽 240px | 失败只影响显示，卡片仍可点 |
| 9 孤儿清理 | 启动时 `sweepOrphans` 比对磁盘目录与 `workbook` 表 | 清掉第 6/7 步崩溃残留 |

顺序是刻意的：**建目录 → 写文件（.tmp + rename）→ 事务落库**。库是最后一步，所以"库里有记录但文件没写完"不可能出现；反方向的孤儿由启动清理兜底。

### 3.5 两个坑

**① `file_picker` 13 起 API 变了**：13.0 之后不再是 `FilePicker.platform.pickFiles()` → `FilePickerResult`，而是静态方法 `await FilePicker.pickFiles(...)` 返回 `List<PlatformFile>`；`FilePickerResult` / `FilePicker.platform` 都已不存在。按 12.x 的写法先写完再改，白花一次编译。

**② 每次验证要 10 分钟的根因**：不是网慢，而是 `flutter test integration_test -d 设备` **每次都要重新构建并安装整个 debug APK**，而这套 Flutter 的 debug APK 固定 ~144MB，其中 `kernel_blob.bin` 占 **118MB**。节奏改为：

| 场景 | 做法 | 耗时 |
|---|---|---|
| 日常看效果 | `flutter run --profile --target-platform android-arm64 -d <设备>` | 构建 ~60s + 安装 ~10s |
| 宿主机单测 | `bash tool/run_tests.sh` | 秒级 |
| DB / 导入等关键逻辑 | `flutter test integration_test/xxx.dart -d <设备>` | ~10 分钟，只在里程碑跑 |

附带发现：`build.gradle.kts` 里的 `ndk { abiFilters }` **无效**，Flutter 会注入 `-Ptarget-platform` 覆盖它。

### 3.6 缩略图格式：PNG 而不是 JPEG

规格写"JPEG q80"，但 **Flutter 引擎只能把 `ui.Image` 编成 PNG / raw RGBA，没有 JPEG 编码器**；要走 JPEG 得引 `image` 包，不在白名单。于是用 PNG，代价是单张 30–60KB（JPEG 约 10KB）。20 份卷 × 4 张 × 50KB ≈ 4MB，对整体存储无感，**换来零新增依赖**。

### 3.7 测试金字塔第三次调整

pdfrx 回到 `dependencies` 后，宿主机 `flutter test` **连纯 Dart 测试也跑不了**：不是编译失败，而是启动前就拒绝（`Package(s) ... require the dart assets feature`）。

最终形态：

| 测试 | 位置 | 怎么跑 | 现状 |
|---|---|---|---|
| 架构约束 / ULID / ReaderPrefs | `test/`（纯 Dart） | `bash tool/run_tests.sh`（跑前临时摘掉 pdfrx） | **16 passed** |
| Widget / DB / 导入 | `integration_test/` | `flutter test ... -d <设备>` | DB 10 + 导入 2 + Widget 3 |
| 一切改动 | — | `flutter analyze` | 零 issue |

`tool/run_tests.sh` 在跑测试期间把 `pdfrx` 那一行临时换成注释，跑完（含 Ctrl-C）自动恢复并 `pub get`。代价是每次多两次 `pub get`（3–5 秒），换来**秒级的 domain 测试反馈**。

## 4. 阅读器双模式（T1.5）

### 4.1 目标与产出

| 文件 | 职责 |
|---|---|
| `ui/reader/page_image_cache.dart` | 按**字节**做 LRU 的 `ui.Image` 缓存（当时 200MB 上限，单飞、`clone` 交付） |
| `ui/reader/page_layer.dart` | 单页图层（白纸 + 页位图；第 2 周墨迹层叠它上面） |
| `ui/reader/paged_view.dart` | 分页：`PageView` + 页内 `InteractiveViewer` + 15% 边缘点击翻页 |
| `ui/reader/scroll_view.dart` | 连续滚动：`CustomScrollView`，主可见页按"重叠面积最大"取 |
| `ui/reader/thumb_drawer.dart` | 缩略图抽屉：`GridView` 懒构建 + 当前页高亮 |

### 4.2 缓存按字节淘汰，不按页数

一页 A4 在 fit-width（约 1500px 宽）下是 1500×2100×4 ≈ **12MB**；400% 时是 6000×8400×4 ≈ **200MB**。所以"缓存 6 页"这类按页数的策略在 1x 浪费、在 4x 直接 OOM。改成按字节（当时上限 200MB）：1x 时能留十几页，4x 时自动只剩 1 页。

**交付的是 `image.clone()`**，调用方自己 `dispose()`。这样即使原图被淘汰释放，正在显示的 widget 手里那份仍然有效——避免"正在看的那页被自己挤掉"导致的崩溃。（2026-10-23 的 030 发现预热路径绕过 clone 会留下已销毁图，见 030。）

### 4.3 放大时的两个动作

`InteractiveViewer` 嵌在 `PageView` 里，双指平移会和翻页手势打架。做法：`_zoomed` 为真时把 `PageView.physics` 换成 `NeverScrollableScrollPhysics`，横向手势全让给平移。

同时按倍率档位（1/2/3/4）重渲染：显示尺寸不变，出图分辨率提高。T0.4 实测 4× 下一块 200×120pt 只要 **4ms**，所以放大后重渲染划算；整页 10px/pt 是 **191MB** 位图，因此高倍率必须按视口裁块渲染，缓存键 `(page, scaleBucket, tileX, tileY)`。

### 4.4 主可见页按重叠面积取

`offset / pageHeight` 在 A4/A3 混排时会错位。改成遍历页前缀偏移，取"与视口重叠长度最大"的那一页；300 页时每次滚动 300 次减法比较，可忽略。

### 4.5 进度记忆与一次误判的排查

进度落在 `session.last_page`，`_onPageChanged` 防抖写库。切模式用 `_current` 作锚点，所以"分页 ↔ 滚动"切换后仍在同一页。

**一次误判的完整排查**：手测发现页码"自己漂移"。先把 `shuaqi.db` 拉回本地用 sqlite 直接查，确认 `last_page` 是**连续操作叠加写进去的，不是代码 bug**——首次挂载时 `PageView` 会把 `initialPage` 回报成一次 `onPageChanged`，于是"只打开没翻页"也写库。顺手加防御：`_onPageChanged` 里页码没变就直接返回。复查：只打开不翻页，`last_page` 保持 `0`（查库确认）。
