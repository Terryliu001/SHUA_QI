## 1. 用户要求的五项

1. 「对答案 / 改卷」判题刷新：改框/补笔迹后展开「答题情况」自动重 OCR；「对答案」弹窗按钮改「判题」「交给 AI 判」；改卷逐题重核对、AI 原判保留、明显改动重判、手改保留；未作答单独计数。
2. 新装首次启动弹「用户须知」，内容与设置一致；确认后不再弹。
3. 设置二级页返回恢复原滚动位置。
4. 「关于 → 版本说明」顶部加版本检测/更新：GitHub Releases、后台检查、红点、手动更新、更新前自动备份、恢复指导。
5. 备份体系：导出备份可命名；「缓存统计与清除」改「存储占用」，内含备份文件查看/重命名/删除/恢复；更新确认弹窗内一键直达备份恢复。

## 2. 根因（为什么旧版不好用）

- `_checkAnswer` / `_gradeAll` 直接读 `entry.ocrText`，没有确认它是否对应当前笔迹/作答框。
- `AnswerSheetEntry.ocrStale` 只比较 `updatedAt > ocrAt`；新增/擦除笔迹不会改 `updatedAt`。
- `_autoRecognizeIfNeeded` 用 `_autoOcrTried` 一次性闸门，`_recognizingAnswer` 又是全局单标志；并发时后来的请求被丢掉。
- `QuestionGrade` 只存 verdict，不存“判题时用的 OCR / 参考答案”，改卷无法判断 AI 原判是否还成立。
- 设置页在 `_sub != null` 时直接返回另一个 `Scaffold`，设置 ListView 被销毁，返回即回到顶部。
- 没有更新代码；`AppInfo.version` 是唯一版本点。备份已有 zip 服务，但没有命名/管理 UI。

## 3. 落地口径

### 3.1 判题刷新
- `AnswerSheetEntry` 新增 `ink_sig`：作答框 + 答题卡每张纸 `revision/笔画/点数/包围盒` + 卷面框内笔迹的指纹。
- `QuestionGrade` 新增 `judged_text / judged_sig / judged_ref_hash`：判题依据快照。
- 展开「答题情况」：指纹不同 / 无文字 / `ocrStale` → 自动 OCR；同一题只跑一个，不同题排队，不再丢请求。
- 改框后 300ms 防抖自动重识别。
- 识别结果为空也写 `ocr_at + ink_sig`（避免每次展开都重跑）；识别失败不写，下次重试。
- 「对答案」：先刷新 OCR；手改永远保留；AI 无明显改动保留原判；明显改动才重判；本地低置信客观题点「判题」可强制落判并注明；主观/公式保持黄点。
- 「改卷」逐题：手改保留 → OCR 刷新 → 无答案/未作答分别计数 → AI 原判按快照判断 → 本地可信落判 → 不可信标黄并汇总问 AI；按钮显示 `改卷 n/N`。
- 未作答口径：卷面作答框笔迹 + 答题卡笔迹 + 识别文字 + 作答原图；改卷提示单列“未作答 d · 无答案 e”，一道都没判出来时额外弹汇总 +「去答题卡」。
- 明显改动：OCR 文本归一化相似度 < 80%，或空↔非空，或参考答案哈希变化。

### 3.2 首次须知
- `AppDependencies.isFreshInstall`：打开 DB 前看文件是否存在。
- 只对全新安装、且 `notice.accepted != 1` 弹；`kUserNotice` 共享给设置页与弹窗。
- 不勾选不能继续；「暂不使用」退出应用；确认后写 `notice.accepted=1`。
- 脚注说明以后可在 设置 → 关于 → 用户须知 查看。
- 须知正文顶部/设置同页都有「从备份恢复（可选）」：重装/换设备可先恢复数据再同意；恢复前二次确认并留底，完成后重启。

### 3.3 设置滚动
- 设置主体常驻（`Offstage`），二级页作为覆盖层；返回只移除覆盖层，滚动位置/状态不丢。
- `PopScope` 语义保持：有二级页先回设置，没有才退出。

### 3.4 版本更新
- 自研轻量实现（**原计划的 `flutter_autoupdate` 未拉取**：PC 直连 pub.dev/GitHub 不通，代理未开；按用户批准的 fallback 切自研）。
- `GitHubReleaseClient`：`releases/latest`，无 token；支持 `--dart-define=UPDATE_API_BASE=...` 本地假源。
- `AppVersion` 只比较 major.minor.patch；支持 `v` / `+build` / `-beta`。
- `UpdateService`：下载到私有 `update/`，进度每 256KB 刷新，校验大小与 GitHub asset `digest`（SHA-256）；取消删除半截文件。
- 安装：`REQUEST_INSTALL_PACKAGES` + `FileProvider` + `installApk`；安装前校验包名、versionCode、签名；未知来源未授权时给「去允许」。
- 更新前：先自动备份 zip 到「下载/SHUAQI」，命名 `SHUAQI_backup_before_v<目标版本>_yyyyMMdd-HHmm.zip`；失败中止。
- 更新确认弹窗内直接放「从备份恢复…」「管理备份文件」；更新页「数据安全与恢复」也有同样两个入口。
- 后台检查：启动 3s + 回前台距上次 >6h + 每 24h；红点在设置 tab 与版本说明行；打开版本说明即清。
- 更新后如果本机 `workbook=0` 且存在更新前备份 → 弹窗询问是否恢复（不自动覆盖）。

### 3.5 备份体系
- 导出：先弹窗显示统计（卷/收藏/记录），可命名，重名自动 `-2`，再打包；落「下载/SHUAQI」。
- 「存储占用」：缓存与备份两个区块；备份行支持恢复 / 重命名 / 删除，更新前备份置顶并打「更新前」标。
- 从备份恢复：先列「下载/SHUAQI」里本应用创建的备份；也可从文件选择；恢复前读 manifest 确认，恢复后重启。
- 已知边界：Android 10+ 的 MediaStore 只让应用看到/管理自己创建的 Downloads 条目；卸载重装后旧备份仍可用「从文件选择」恢复，但可能不出现在列表里。这一点写进了版本说明的限制。

## 7. 已知限制
- 备份列表只显示本应用当前安装创建的 Downloads 条目；卸载重装后用「从文件选择」。
- 更新检查只在应用运行时；不做常驻后台服务。
- 应用内更新必须允许「安装未知应用」；签名不一致只能先备份再卸载重装。
- 低置信度本地判题会落绿/红并注明“请自行核对”；公式/主观题仍建议 AI 或手改。
