## 1. 手势模式 / 书写模式：最终口径

**结论**：开关**只决定「手指算不算笔」**，不决定笔的行为——笔永远是笔。

| 状态 | 单指 | 笔 | 双指 |
|---|---|---|---|
| **书写模式**（`handTool == false`） | 写字 | 写字 | 平移 / 缩放 |
| **手势模式**（`handTool == true`，2026-10-24 起默认） | 平移 / 缩放 | **仍然写字** | 平移 / 缩放 |

039 的实现是「手形模式 = 手和笔都只浏览」，2026-10-24 用户拍板改成上表；中间形态已废弃。

**关键实现**（`ui/reader/page_layer.dart` 透传）：

```dart
inkInteractive = !regionEditing;                 // 笔永远能写，仅调框模式整层禁用
inkTouch       = !regionEditing && fingerWrites; // 只管「手指算不算笔」
```

- `InkLayer._accepts()`：`stylus || invertedStylus || (inkTouch && touch)`；笔尾橡皮（`invertedStylus`）直接当橡皮，不切工具。手势模式**不再隐藏**笔刷浮钮/工具带。
- **多指让位**：第二指落下 → `_cancelForMultiTouch()` 取消当前笔画（**不落库**）；正在擦除则 `abortErase()` 反向还原 pending（避免「想缩放却擦掉半页」）；手指全抬起前不再起笔。
- **滚动模式**（`scroll_view._observePointer`）：笔在任何非调框模式都冻结单指平移（手掌搭屏不推页面）；书写模式下 touch 也算「正在写」；冻过的手势标 `_gestureFrozen` 后**不甩动**。缩放识别器 `supportedDevices` **恒为 `{touch}`**（笔全交墨迹层；曾按模式放开 stylus，因语义变更废弃）。
- **分页模式**：`_TouchPanGate` 按 touch 数给 `InteractiveViewer.panEnabled`（1 根 → false 让墨迹层写，2 根 → true 让 IV 接管）；`StylusGestureGuard` 条件 `fingerWrites && !regionEditing`（039 曾改成只在书写模式启用——那会让手势模式下笔被 IV 抢走）；双击缩放**只在非书写模式**保留（单指点两下会先落两个墨点）。
- **调框模式**：`fingerWrites: !handTool && !panelOpen`，手指仍可平移看别的框，笔优先给框。

**坑（现象 → 根因 → 修法）**

| 现象 | 根因 | 修法 |
|---|---|---|
| 039：手形模式下笔完全不能滑页面 | 缩放手势 `supportedDevices` 只写 touch，`stylus` 被排除 | 按模式给设备集（**此修法已随语义变更废弃**） |
| 039：翻页模式笔调不了框 | 守卫在 `regionEditing` 时也启用，DOWN 阶段 accepted 把框的识别器挤出竞技场 | 条件改 `fingerWrites && !regionEditing` |
| 240/160dp 窄面板按钮溢出 | 三连动作 + 预览 + 答案卡挤在一起 | 答案卡 `mainAxisSize.min` + 非伸缩 Text；**不可用是灰掉而不是藏起来** |

## 2. 连续滚动：双向斜滑（按可滚方向决定轴）

**结论**：不再「一次手势锁一轴」，改成**按哪个方向真有可滚余量决定**：单轴有余量锁那一轴，横竖都能滚则自由斜滑。

`domain/reader/scroll_math.dart`（纯 Dart，位移返回 `(double, double)`，不许 import dart:ui）：

```dart
enum DragAxis { vertical, horizontal, free }
decide(): 横竖都有余量→free | 只有横能滚→horizontal | 否则→vertical（含"都不能滚"）
余量口径：contentSize × scale > viewport + 0.5
project(): vertical→(0,dy) | horizontal→(dx,0) | free→(dx,dy)
```

- 默认档内容窄于视口 → 走竖轴（不是被锁，是没余量）；放大后两轴都可滚 → 斜拖两分量都生效；橡皮筋 / 甩动速度同轴处理（free 两轴都保留，单轴收紧另一轴）。
- **位移合成**（039 二次修正）：`free` 用**增量** `focalPointDelta`（down 到越过 **18dp** 阈值那一段不会一次性补进来，斜拖连续）；单轴模式仍用**绝对投影**（`起点 + 总位移`），避免累计误差带偏锁定轴。

**坑**：029 的 `DragAxisLock` 是「一次手势锁一轴且偏竖轴」（为修竖滑迟钝），它解决的是**只有一个方向有余量**时的正确问题；放大后两轴都有余量，再锁轴就让斜拖只走一个方向。所以现在**按余量判断、不用角度猜方向**（角度猜测只在两轴都能滚时有意义，而那正是要自由斜滑的场景）。真机 150% 下 45° 斜拖：内容同时向上、向左移动。

## 3. 右侧面板：题干只给图 / 答案 / 收藏 · 对答案

### 3.1 公式 / 符号题：不做文字转写，只给题面

`domain/region/math_text.dart` → `formulaHeavyText(raw)`：PUA（`U+E000–F8FF`）、数学字母（`U+1D400–1D7FF`）、Greek、常见数学符号计入；**≥2 个数学字符 或 占比 > 6%** → true；纯中文里的一个 `x=1` 不误判。

整卷口径 `reader_page._showStemText`（现状，行 2048）：

```
有效题干 < 3 条 → 照常显示文字（样本太少比例不可信）
heavy / stems.length >= 0.30 → 面板不显示题干文字，只给 PDF 题面预览
```

阈值仍是 **0.30 / 6%**（已核实，与 039 一致）；个别「长中文 + 少量公式」的题会被整卷规则带走——有意的「宁可不显示」。面板加「公式题：以卷面为准，不做文字转写」；答案文本若为 formula-heavy，追加「答案含公式，文本可能错序；以卷面为准」。预览高度：039 当时 150dp → 公式卷 230dp（**未核实**当前 `RegionPreview` 值）；已核实 AI 面板预览 `maxHeight: 132`（`reader_page._aiPreviewOf`）。

### 3.2 答案抽取与 `answers.v1.json`

抽取（`domain/region/split.dart` + `answer.dart`）：

| 来源 | 规则 | 徽标 |
|---|---|---|
| 题内解析 | `解：`/`证明：`/`答：`/`解析：`/`【答案】` 后文字；题干在 marker 处截断 | 随题解析 |
| 文末答案区 | `参考答案/答案与解析/试题答案…` 后按题号逐题归并 | PDF 文本 |
| 压缩答案键 | `1.A 2.B 3.C` 一行多题 | PDF 文本 |

- **题内解析按 `ordinal` 精确挂**：同卷里填空题 `1.` 与选择题 `1.` 并存，只按 label 会串答案。文末答案键没有 ordinal，**只能按 label 兜底**（已知天花板）。
- 题号归一：`1.` / `1、` / `1` 同题；扫描件（`fromOcr`）无文本层 → 答案为空。
- 持久化：`VaultPaths.layoutAnswers(id)` → `layout/answers.v1.json`；`LayoutStore.readAnswers/writeAnswers`，`clearAuto` 一并清；`RegionBuilder` 切题成功后写，**无答案也写空文件**（清旧答案）；`kCutterVersion` **4 → 5**（`region_builder.dart:337`），旧卷按 `doc['cutter'] != kCutterVersion` 后台重切。
- 答案卡：来源徽标（PDF 文本 / 随题解析 / OCR / 手工 / AI）+ 文本（**最多 10 行**）+ 免责句「来自题内解析/文末答案区，供对答案；未做判题」；未匹配时显示「这道题没有匹配到答案」。

### 3.4 问 AI：右侧滑入面板

**为什么不是底部浮层**：要同时看见题目信息、题面图、预置 prompt、返回路径；底部浮层盖住题面，也没地方放「图片已附上」状态位。做成与「题目区域」同宽同位置的右侧面板。

`ui/panel/ai_chat_panel.dart`：头部（返回 / 收起 / `第 N 页 · 题号 X` +「题面图片是权威来源；机器文本只作辅助」）；消息区（附件卡 = `RegionPreview` 的 PDF 原页裁切 +「已附上」徽标、说明卡、双方气泡）；输入区预填 `QuestionAiPayload.prompt`，可改可「重置提问」。

**接线要点**：**`AiChatPanel.onSend` 是接模型的唯一入口** —— `Future<String?> Function(String, QuestionAiPayload)?`，为 `null` 时给明确的「预览版」回复（不假装有答案）；**当前 `reader_page` 构造面板时仍未传 `onSend`**（`infra/ai/llm_client.dart` 已存在，接线不在本卷范围）。`key: ValueKey(_aiBundle!.anchorKey)` 换题换 State，否则复用输入状态会让新题沿用上一题的提问。`_aiPayloadOf` 与题目区域复用同一套公式题判定，不会自相矛盾。

**载荷契约**（`domain/ai/question_payload.dart`，不要改短）：

```text
图片（PDF 原页裁切）= 权威来源；PDF 文本层 / OCR = 辅助，可能缺字、错序、公式碎片；
图片与文本冲突 → 以图片为准；看不清就说"题面不清晰"，不要猜。
```

字段 `question_id / label / page_index / rect / image_authoritative / text_provenance / extracted_text / declaration / prompt`；`TextProvenance { none, pdfTextLayer, ocr }` **必须随题面一起交**，否则模型会把文本碎片当事实。构造走 `buildQuestionAiPayload(...)`：`text == null` 时 provenance 自动降为 `none`——公式题只给图片就是这么实现的（`reader_page._aiPayloadOf`：`!formulaHeavyText(rawStem) ? rawStem : null`）。

### 3.5 PopScope 与语义树

顺序：**AI → 题目区域 → 退出阅读器**（`canPop: !_panelOpen` + `onPopInvokedWithResult` 里先关 `_aiOpen` 再 `_togglePanel`）。收起的面板用 `AnimatedSlide` 移出屏幕但仍在语义树里，`uiautomator` 能 dump 到 `[0,0][0,0]` 的「保存 / 问 AI / 返回题目区域」→ 两个面板分别 `ExcludeSemantics(excluding: !_panelOpen || _aiOpen)` 与 `excluding: !_aiOpen`（当前还多了 `IgnorePointer`）。

## 4. 顶栏「保存」

**落盘三样（缺一不可）**：

| 内容 | 函数 | 为什么是它 |
|---|---|---|
| **笔迹** | `_flushAllInk` | 落**所有**待写页，不只当前页（用户可能翻回前一页补一笔） |
| **阅读进度** | `handle.saveLastPage(_current)` | 500ms 防抖窗口里可能还没写 |
| **切题改动** | `_flushRegions` | 覆盖层同样有防抖 |

笔迹本来就有 **500ms 自动落盘 + 生命周期兜底**，按钮的价值是**给用户确定感**，不是救数据；落盘后给明确反馈「**已保存答题情况**」（原为「已保存：笔迹、进度与题目改动都已落盘」，042 改掉「落盘」「题目改动」这类开发词）。

**窄屏不是加一行代码**：`AppBar` actions 先按自身宽度排，标题是唯一可压缩的那个。实测 360dp：6 动作 + 缩放胶囊刚好不溢出，**加第 7 个动作溢出 33px**。处置是「保存永远在顶栏」+ 低频项让路：041 当时只收「显示设置」；**（049 起改为）** `< 600dp` 把手势/形态/显示都收进「更多」，题目区域/缩略图/答题卡改为常驻，图标宽 40dp（平板 48dp），见 `reader_top_actions.dart` 的 `kReaderCompactWidth = 600`。

顶栏抽成独立文件 `lib/ui/reader/reader_top_actions.dart` 不是洁癖：**这段逻辑必须能被单测锁住**，否则再加一个按钮就会在手机上炸黄黑条。

## 5. 暗色提示条为什么是白的

**根因（实测，不是猜的）**：`app_theme.dart` 的 `snackBarTheme` 用 `scheme.inverseSurface` + `onInverseSurface`。M3 的 `inverseSurface` 按定义是「surface 的反色」，所以它在**暗色**主题里（暗色 surface 的反面）是**浅色** → 暗色界面弹出一条白底横条，在暖黑纸面上格外刺眼（用户 2026-10-24 报「提示条都是白的」）。

| 主题 | 底色 | 字色 | 边框 |
|---|---|---|---|
| 浅色 | `inverseSurface`（深底） | `onInverseSurface`（浅字） | 无 |
| 暗色 | `surfaceContainerHighest`（#2B3941 深灰） | `onSurface`（#E3E9EE 浅字） | `outlineVariant` 发丝线 |

两套都统一成「**深底浅字**」；暗色补发丝线是因为深灰底与深灰界面边界弱（靠线显形而非阴影，符合项目设计哲学）。**同源问题**：`tooltipTheme` 用同一对颜色，暗色下工具提示也是浅色气泡，一并改成同套色 + 发丝线。

**证据**：`test/snackbar_dark_theme_test.dart` 用 **WCAG 相对亮度公式**断言（暗色底色亮度 < 0.2、字色 > 0.5），并**真渲染一条 SnackBar** 检查界面上的 Material 颜色——不是只断言主题字段。

### 6.1 大图最窄档溢出（widget 测试抓出来的）

**现象**：`A RenderFlex overflowed by 4.6 pixels on the right.`（`Row ← … ← _Chip ← Wrap`）。

**根因（两个原因叠加）**：① `SliverGridDelegateWithMaxCrossAxisExtent` 的 `maxCrossAxisExtent` 只是**上限**，实际宽度按列数**向下取整**：848dp 屏上传 `135` → 7 列 × **116dp**；② `_Chip` 标签上限取**卡片总宽**，而 chip 处在「卡片 − 左右 12dp」的内容区里 → 「文字上限 + 图标 + 内边距」必然比 Wrap 宽。

**修法**：网格下限 `135` → **150**（现状 `(180 * _cardScale).clamp(150, 280)`）；`< 150dp` 时 `LayoutBuilder` 切布局（标题 13px/1.3 行高仍两行、页数与时间合一行 `4 页 · 22 分钟前` 单行省略、标签只留 1 个且宽度按内容区算）；`_Chip` 上限再留 1.5dp 取整余量。**数字差异如实记**：代码注释写「最窄一档仍有 ~136dp」，040 真机实测约 **130dp**。

> 测试踩坑：`testWidgets` 在 FakeAsync 里跑，**真实文件 IO 必须 `tester.runAsync` 包一层**，直接 `await Directory.createTemp()` 会挂到超时。

### 6.2 卡片 5 级（替代 15 级滑杆）

`小 0.75 / 较小 0.95 / 标准 1.15 / 较大 1.35 / 大 1.55`，`divisions: 4` + 标签行五级高亮；拖动即 `setState`，书架在弹层上方实时变；弹层内另放样卡 `AnimatedContainer`（被遮住也能看到比例）；旧值（1.0/1.2/1.4）加载时吸附最近一级；**当前默认值 0.95**，clamp `0.75–1.55`。

### 6.3 文件夹与「选择文件」

**为什么不是「导入 PDF」**：导入会新建卷记录并出现在「全部」；建完文件夹后真正高频的是把**已导入（尤其未分类）**的卷收进来。混在一个入口会让人以为「加进文件夹」= 再导入一次，所以两入口职责不同、**不合并**（FAB 仍是导入 PDF）。

- 进入文件夹后筛选条下多一条 `📂 「数学」 · 3 卷 [＋ 选择文件]`；浮层列出**不在当前文件夹**的卷，**未分类排最前**，其余按最近使用；支持搜索、全选/取消全选；按钮写「加入 N 卷」；候选为空时说明「都已经在这个文件夹里了」并给「导入 PDF」作为下一步；空态主动作也改成「选择文件」。
- 纯函数 `addableToFolder(items, folder)`（`workbook_search.dart`）：过滤 + 未分类优先 + 最近优先 + 标题兜底，**不改原列表**。
- **本卷当时**：`workbook.folder` 只能推导「有卷子的文件夹」，空文件夹另存 setting `bookshelf.folders`；chip 长按可重命名（`WorkbookDao.renameFolder` 批量改归属）/ 删除（卷子回未分类，不删卷）。（**之后改 `folder` 表**：`ShelfFolder{id,name,parentId,color,sort}` + `workbook.folder_id`。）

### 6.4 多选与批量

顶栏「多选」进入选择态，点击/长按都切换选中；顶栏变「退出 / 已选 N / 全选 / 移动 / 标签 / 删除」；批量移动、批量标签、批量删除（二次确认，删库 + 删 Vault 目录）；返回键先退出多选（`PopScope`）；选中卡用 `primaryContainer` 淡底。

### 6.5 浮层必须显式给背景（真机坑）

主题把 `bottomSheetTheme` 设成透明（给自绘容器用），「选择文件」「卡片大小」没自绘背景 → 书架从后面透出来。**修法**：`showModalBottomSheet` 显式 `backgroundColor: surfaceContainerHigh` + 顶部圆角 `shape`；「选择文件」再按候选数量给高度 + `Flexible + shrinkWrap`（3 份卷时底栏紧贴列表，不再拉满 82% 屏高留一大片空白）。其他浮层若也透明，按同一方式补。

## 7. 多文件导入

**根因：不是插件不支持，是代码没用对**——`file_picker 13` 的 `FilePicker.pickFiles` 在 Android 端**本来就是多选**（`pickFile` 才是单选，`allowMultiple` 已从 API 移除），旧代码取 `picked.singleOrNull?.path`，**只用了第一个**，其余静默丢弃。

三个设计决定：

1. **串行不并行**：每份要算 sha1、复制、读页数、生成缩略图（pdfium 解码 + PNG 编码），并行让 CPU 与内存峰值翻几倍、几十页的卷容易 OOM；导入本来就是后台等待场景。
2. **一份失败不打断其余**：选 5 份里有 1 份加密 PDF，不该连另外 4 份一起废掉；失败明细记 `文件名：原因`。
3. **进度看份数不看阶段名**：多份时 FAB 显示「导入 N/M」；阶段名只在一份时才有意义。

**汇总文案**（`domain/model/import_batch.dart` 纯函数）：一次导入有**三种**结局，必须一起说清楚，否则用户选 5 份只看到一句「导入完成」，不知道另外几份去哪了。

```
导入 3 份。
导入 2 份 · 1 份已存在。      ← 重复不是错误，只是没新增
导入 1 份 · 2 份失败。
· 加密卷：文件已加密
· 另有 N 份失败              ← 超过 3 条只列前 3 条（kImportFailurePreview = 3）
```

`ImportBatchResult{imported, deduplicated, failures}`，全都没选 → 「没有导入任何文件」（兜底）。

## 8. 第 4 周基础：笔画行聚类（T4.1 纯函数）

`lib/domain/ocr/line_cluster.dart`：`clusterInkLines(Iterable<InkStroke>, {double? lineHeight}) → List<InkLine>{strokes, bounds, centerY}`。

规则（当前代码事实）：过滤空笔画与 `excludeFromOcr`（**荧光笔**）；行高 = 非零高度（> 0.5）笔画的**高度中位数 × 1.2**，`clamp(8, 96)`，全零 fallback **24**；按 y 重心升序（同重心按左边界），相邻重心差 `<= max(4, 行高 × 0.6)` 归同一行；组内用**滚动均值**做下一轮基准（一行里的上下标起伏不会把后续笔画越带越偏——038 原文只写「按 y 重心排序」，这是之后的修正）；行内按 **x 升序**；返回整行包围盒。纯 Dart、无随机、无时间依赖。

这是 T4.1「一行一张图喂 ML Kit」的前置：整块丢进去多行会被串成一行，准确率明显下降。**本卷只做这个纯函数**，OCR 引擎 / 调度器 / `text_block` 未开始。

## 9. 显示浮层：为什么「暗色和其他形式都设不了」

**现象**：阅读器里打开「显示」浮层报错、整块设置不可用；profile/release 下滑杆怎么拖都不动。

**根因**：`paper_style_sheet.dart` 的强度 `Slider` **只传 `value` 没传 `max`**。Flutter `Slider` 默认范围 `0..1`，而强度是 `0..100`（默认 **55**）→ `55 > 1` 违反 `value >= min && value <= max` 断言：debug 下浮层刚弹出就断言失败；release（assert 关闭）下滑杆刻度仍是 0..1，只能拖出 0/1，表现为「怎么拖都设不了」。**两种观感是同一条根因**，别当两个 bug。

**修法**：补齐 `min: 0 / max: 100 / divisions: 20 / label`（现状 `paper_style_sheet.dart:160`）；夜读/原图仍按既有规则置灰强度（没有纸色可染）。回归 `test/paper_style_sheet_test.dart`（min=0/max=100/value=55 无异常、「夜读」真的回调 `PaperStyle.night`、深色主题下也能打开）。

## 11. 工程坑：测试数量为什么会跳

**318/4 是假失败，330/0 才是真的**（042 实测）。差异来自沙箱：宿主机 `flutter test` 触发 pdfium native assets 构建 → `native_toolchain_c` 跑 `vcvars64.bat` → 靠查注册表定位 Windows SDK → **沙箱禁 `reg.exe`** → `WindowsSDKVersion` 为空 → cl.exe 找不到 `windows.h` → `fatal error C1083`。SDK 实际已装（Windows Kits 10.0.26100.0），只是**探测**这条路被封。

**试过两条路都失败、已回退，不要重走**：① 预置 `INCLUDE`/`LIB`——vcvars 对 INCLUDE 是**追加**不是覆盖，而 `native_toolchain_c` 只转发 vcvars 改动过的变量（INCLUDE 恰好是被改的那个），预置值被替换；用 `CL` 绕过也没进到 cl.exe 命令行。② 手写 hook 缓存 `output.json`——产物在 `.dart_tool/hooks_runner/shared/pdfium_dart/build/`，但缓存判定还要 `dependencies.dependencies_hash_file.json`（精确哈希），补齐成本高且脆弱；**手工造的 output.json 已删除**（留着会误导）。当前 `bash tool/run_tests.sh` 仍保留「临时摘 pdfrx」包装给无完整权限场景，但不再是唯一路径。

**`RegionSet` 从 `state/` 下沉到 `domain/`**：起因是 `test/region_panel_actions_test.dart` import `state/region_providers.dart`，顺链路拖进 pdfrx → native assets → 上面的失败。`RegionSet` 只是数据容器（题目列表 + 答案表），不碰 IO/provider，下沉到 `domain/model/region_set.dart`；数据来源 `regionSetProvider` **仍留在 state**（那是 IO）；`region_panel.dart` 与 `region_overlay.dart` 因此不再 import state。效果：301 passed/11 failed → **318 passed/4 failed**，顺手修好 **7 个**既有失败且无回归；042 复核保留（删掉会把 7 个测试重新弄挂）。

**测试数量轨迹**：`276`（038）→ `287`（039，+11）→ `314`（040，+16）→ `318`（041，+16 且修好 7 个既有）→ **`330` / 0 failed**（042，含 pdfrx 全量）。
