## 1. 做了什么

- **笔画级橡皮**：12pt 阈值；`bounds` 预筛 → 点到折线距离 → **段到段距离**（"划过即删"必须算线段相交，只看采样点会漏）。
- **撤销/重做**：命令栈（`AddStroke` / `RemoveStrokes` / `ClearPage`），深度 50；一次擦除拖动 = **一步**撤销。
- **笔尾橡皮**：`invertedStylus` 直接当橡皮，不用切工具、不改选中态。
- **工具栏**：钢笔 / 圆珠笔 / 荧光笔 / 橡皮 + 撤销 / 重做；没有可撤销内容时按钮是灰的（不装假功能）。
- **按页撤销**：滚动到第 3 页按撤销，撤的是第 3 页的笔，不动别的页。

## 2. 三个设计决定（都写进了代码注释，别改回去）

### 2.1 工具 ≠ `InkStrokeStyle`（橡皮不入 SIF）

`InkStrokeStyle` 是**数据契约**的一部分（SIF v1 的 style 占 1 字节：0/1/2，§5.4），
而橡皮**不产生笔画**。把橡皮塞进 `InkStrokeStyle` 会污染入库格式，还会诱导后人
"给橡皮也存一笔擦除痕迹"——那正是规格禁止的位图橡皮思路。所以新增 `InkTool`
（UI 概念：画什么笔、还是擦），落笔时取 `tool.strokeStyle`。

### 2.2 命令带"原索引"，否则撤销会把 z 序搞乱

删除必须可逆到**原来的 z 序**（荧光笔垫底、墨迹按落笔顺序叠）。所以删除发生的那一刻
就把 `(index, stroke)` 记进命令。`ClearPage` 因此必须带"清空前那一页的笔画"
（规格里它没字段，但不可逆的清空命令没法进撤销栈——有意偏离，见 §5）。

**这里踩到一个真 bug（单测抓住的）**：擦除是"边划边删"，删完一次 doc 下标全变。
若第二次擦除按**当前** doc 取索引，撤销会把 `[a,b,c]` 复原成 `[b,a,c]`。
修法：一次拖动只在**第一次**擦除时取基线 doc，之后所有索引都相对它
（`_eraseBaseline`）。`test/ink_edit_test.dart` 用"删 a,c 再删 b，撤销后必须是 a,b,c"钉住。

### 2.3 撤销栈不持有 doc

栈只记历史；`InkEditController` 持有 doc。这样"落盘返回 revision 回填"这类外部更新
不会搅乱历史，`undo()` 也只是 `doc = command.revert(doc)`。

## 3. 顺带修掉的一个竞态（T2.4 前必须修）

`_load()` 是异步的，用户可能在它返回之前就落了笔。旧实现无条件
`state = loaded`，会把刚写的笔**凭空抹掉**。现在加了守卫：
内存里已有编辑（`canUndo || strokeCount > 0`）就不接受磁盘内容。
T2.4 换成真实文件 IO 后，这个窗口会从"一个微任务"变成"十几毫秒"，不挡就一定会丢笔。
（单测 `异步加载晚于首次落笔时，不覆盖刚写的笔`）

## 5. 有意偏离规格的地方（都在代码里注明了理由）

| 规格写法 | 实际 | 为什么 |
|---|---|---|
| `ClearPage` 无字段 | `ClearPage(removed)` | 不可逆的清空命令没法进撤销栈 |
| `UndoStack.undo/redo()` 自带 doc | 栈不自持 doc，由 controller 执行 | 落盘回填 revision 时不搅乱历史 |
| 撤销栈里只有 `RemoveStroke` | 多了 `RemoveStrokes`（复数，含索引） | 一次擦除拖动要算一步撤销，不能按八次 |
| 橡皮藏在 `InkStrokeStyle` | 独立 `InkTool` | 橡皮不产生笔画，不许污染 SIF 的 style 字节 |

## 6. 真机验证（OPPO OPD2601 / Android 16 / profile APK，截图逐条确认）

| 操作 | 结果 |
|---|---|
| 连写 3 笔（y=700/900/1100） | ✅ 三笔都在；撤销按钮从灰变亮，重做仍灰 |
| 切「橡皮」→ 横划穿过中间那一笔 | ✅ 只有中间那笔消失，上下两笔完好（12pt 不误伤 200px 外的邻居） |
| 按「撤销」 | ✅ 中间那笔回来了；重做变亮 |
| 按「重做」 | ✅ 又消失（截图与擦除后那张**逐字节相同**，说明几何/顺序完全一致） |
| 连按 4 次「撤销」 | ✅ 三笔+擦除全部退回，撤销变灰、重做变亮 |
| 切回「钢笔」续写 | ✅ 正常出墨；重做立刻变灰（新编辑作废旧分支） |

未验（能力边界）：真笔的笔尾橡皮（`input stylus` 注入不了 `invertedStylus`）、
真笔手感下的 12pt 阈值是否合适（需用户实笔）。
