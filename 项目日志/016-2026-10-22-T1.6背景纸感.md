## 1. 设计决策（先讲清楚为什么，避免后人照抄错）

### 1.1 乘法染纸，而不是半透明叠色

规格 §6.9.3 原文写的是"叠色 + ColorFilter.matrix"。实现时改成**乘法**（`ColorFilter.matrix`
对角增益），理由是视觉效果的根本差异：

```text
叠色：out = src×(1-α) + paper×α   → 黑字也被纸色罩灰，对比度下降
乘法：out = src × gain(paper)      → 白→纸色、黑→黑，文字保持墨色
```

纸的本质就是"白底被染色、墨不变"，乘法才是纸该有的样子。增益公式：

```text
gain_c = 1 - (1 - paper_c/255) × t      t = intensity/100
```

- t=0 → 恒等（原图）；t=1 → 白底完全变成纸色；
- 默认 55 时白底约 (250,246,239)，肉眼是"淡暖纸"而不是"黄滤镜"。

### 1.2 滤镜是 GPU 合成，不是重新渲染位图

T0.4 的老结论再次救命：屏显走 `ui.Image` 贴图，`ColorFiltered` 与噪点都是 GPU 一次
pass，**没有 CPU 逐像素计算、没有 PNG 编码（那要 120ms/页）**。所以：

- 切换样式天然 ≤1 帧（规格要求 ≤100ms，实测无感）；
- **不需要**按 `(page,style,intensity)` 建位图缓存——缓存位图反而更慢更耗内存；
- `PaperRenderer` 契约（§7，返回 PNG 字节）**保持不动**，留给 T7 导出/缩略图用；
  本任务不实现它，避免写出无人调用的代码（与 OcrEngine / FormulaEngine 同等待遇）。

### 1.3 深色互斥（§6.9.3）照做，且把"为什么"告诉用户

深色下强制 `original` + 0.18 暗色遮罩（压刺眼白、保文字对比度）。浮层里整块置灰
并给一句说明："深色模式下已停用纸感，避免纸色与暗底叠成脏色"——
**能点但没反应是假功能，置灰 + 一句话才是真交互**。

### 1.4 噪点纹理

`assets/textures/paper_noise.png`（256×256 全对比噪点，本地脚本生成、随机种子固定），
widget 以 3% 不透明度平铺。噪点只在非 original 且浅色时叠加。

## 3. 真机验证（OPPO OPD2601）

| 场景 | 结果 |
|---|---|
| 浅色 + 原图 | 页面 (248,248,248) 中性白，零处理路径 |
| 浅色 + 暖白 55% | 页面白底变暖（重启后采样 (240,236,230)，R>B 差 10 与增益公式一致）；**文字仍是墨黑** |
| 切换样式 | 即时生效（GPU 合成），无可感延迟 |
| 强度滑条 | original 时置灰不可拖；选纸色后可用，拖动实时变化不卡 |
| 深色模式 | 纸感强制失效，页面叠 0.18 暗色遮罩（白底→约 210，夜读不刺眼）；浮层置灰 + 一句话说明 |
| 深色遮罩下翻页/缩放 | 无掉帧（遮罩是静态层） |
| **偏好持久化** | 杀进程重启：纸感暖白仍在（色值比对）；**阅读模式也持久化**（切滚动→重启→仍是滚动） |
| 分页/滚动两模式 | 纸感都生效（PageLayer 统一处理） |

宿主机：`flutter analyze` 零 issue；`bash tool/run_tests.sh` **21 passed**（新增 5 例）。

## 4. 有意偏离规格的地方（记录在案）

| 偏离 | 理由 |
|---|---|
| 叠色 → 乘法 | 视觉正确性（黑字不灰）；规格原文的"叠色"是手段不是目的 |
| 不建 `(page,style,intensity)` 位图缓存 | GPU 合成下无 CPU 成本，缓存反而多耗内存；"≤8ms/页"以 0ms 达成 |
| 默认纸感保持 `original`（规格 §6.9.3 表格写 warm 默认） | 与既有契约 `reader_prefs_test`（original/55）一致；且首开见原卷更可信，warm 一键可得。要改默认只需改 `ReaderPrefs.defaults` |
| `PaperRenderer` 契约本任务不实现 | 无调用方（导出在 T7）；不写没有调用者的代码 |
