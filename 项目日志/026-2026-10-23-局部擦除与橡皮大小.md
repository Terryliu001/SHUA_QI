## 1. 局部擦除：把"删整笔"改成"把笔画切开"

### 1.1 行为

```text
原笔 ────────────────      一条长横（一笔，uid=H）
擦         ●●              橡皮（半径 12pt）划过中间
结果 ──────      ──────      变成两笔（uid 是新的），缺口 = 橡皮直径
```

- 擦到哪删到哪；擦端头只剩一段；一划扫过整条则整笔消失；
- **碎片继承原笔的样式/颜色/粗细**（擦一半不该让另一半换色变粗），uid 换新；
- 单点笔画（点一下）要么整体擦掉，要么不动；
- 一次拖动里发生的所有切分，抬笔时合成**一步撤销**；撤销能精确回到拖动前的样子。

### 1.2 算法（`domain/ink/eraser.dart` 完全重写）

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 橡皮路径 → 圆盘 | 按步长 `min(radius, 4pt)` 采样成一串圆盘 | 圆盘与线段的交集有**精确解**（二次方程），比做"胶囊 ∩ 线段"简单且准 |
| 线段 ∩ 圆盘 | 解 `At² + Bt + C ≤ 0`，与 [0,1] 求交 | 精确，无采样误差（单测断言缺口 = 直径，误差 < 0.01pt） |
| 多圆盘区间 | 排序后合并成"被覆盖的 t 区间" | 一次可能被多个圆盘覆盖 |
| 切分 | 逐段走：区间外保留、区间内丢弃，断口用 `lerp` 生成插值点 | 碎片首尾正好贴着擦除边界 |
| 预筛 | `mayTouch()` 只比包围盒 | 一页 5000 笔，每个 move 事件都全量求交会直接卡死 |

### 1.3 命令层（`domain/ink/undo_stack.dart`）

新增两个命令，仍然是"命令而非快照"：

```dart
typedef ErasePatch = ({int index, InkStroke original, List<InkStroke> fragments});

class EraseStrokes extends InkCommand   // 把 idx 处的原笔替换成碎片（就地，保 z 序）
class EraseBatch extends InkCommand     // 一次拖动 = 多步替换，抬笔合成一条
```

- `apply`：**从后往前**替换，避免前面的下标被列表长度变化带偏；
- `revert`：先摘掉所有碎片 uid，再按原下标插回原笔（从大到小插）；
- `EraseBatch.revert` 按**相反顺序**还原（后发生的先撤），否则下标对不上。

### 1.4 绘制层的缓存失效（新加的 `epoch`）

`CommittedInkCache` 原来是"只追加"的增量缓存：抬笔只 append 一笔。
局部擦除会让**一笔变两笔**——长度可能刚好对得上，只比 `strokeCount` 会漏判，
结果就是"数据改了、画面没改"（看起来像橡皮没生效）。

修法：`InkEditState.epoch` 只在**非追加**改动（擦除 / 撤销 / 重做 / 清空 / 重载）时 +1；
绘制层 `sync(doc, epoch)` 看到 epoch 变了就整体重建。纯追加仍然走增量（抬笔不受影响）。

## 3. 真机验证（像素测量，不靠肉眼）

先把一条长横画在 y=900（`#14161A`，实测 21854 个像素），再逐项测：

| 操作 | 测量结果 |
|---|---|
| 中号橡皮，横划 100px（1400→1500） | 笔画断成 `297→1344` 与 `1557→2504`，**缺口 213px ≈ 42pt**（= 直径 24pt + 拖动 100px）✅ |
| 撤销 | 恢复成**单段 `297→2504`**，与擦之前完全一致 ✅ |
| 重做 | 缺口精确回到 `1344→1557`（同一个值，确定性）✅ |
| 小号橡皮，点擦（700 附近） | 缺口 **63px ≈ 12pt**（≈ 直径 12pt）✅ |
| 大号橡皮，点擦（2100 附近） | 缺口 **225px ≈ 44pt**（≈ 直径 44pt）✅ |

三档缺口宽度肉眼可分辨（63 / 213 / 225px），且都没有误伤相邻笔画。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 擦除按"折线"切分，不引入新的曲线拟合 | 断口是直线段，放大到 400% 看是平的；够用，做曲线会让碎片数暴涨 |
| 一次拖动擦很多次会产生较多碎片 | 碎片只保留在内存与后续 SIF 里；正常使用（一划）通常只切 1–3 片 |
| 橡皮大小与"粗细"共用字段 | 语义上没冲突（橡皮没有笔画宽度），但读代码时要知道这件事 |
| 杀进程仍丢笔迹 | T2.4 |
