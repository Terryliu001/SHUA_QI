# 014 · 滚动模式第三版：固定布局 + 单一变换矩阵

| 项 | 值 |
|---|---|
| 日期 | 2026-10-22（GMT+8，15:35–15:50） |
| 用户反馈 | 双指放大后再缩小，**图层发生混乱**（页与页错位叠压）；要求推倒重来，必须跟手好用 |
| 结论 | 结构性问题已消除：缩放不再参与布局，页与页的相对位置永不重算 |

---

## 1. "图层混乱"的根因

第二版在每次 `onScaleUpdate` 里改每个 `Positioned` 的 `top` / `height`：

```dart
top: _tops[i] * _scale + _offset.dy,
height: _heights[i] * _scale,        // ← 每帧都变
```

这等于**每帧重新布局一遍**。缩小过程中 `_scale` 连续变小，浮点尺寸逐帧累积误差，
页与页之间的间隙（`_gap * 2` 也参与缩放）被反复四舍五入，边界就会错开、互相叠压。

**这不是调参数能解决的**——只要"缩放 = 改布局"，就必然有这个误差累积。

## 2. 第三版：布局与变换彻底分离

```text
内容坐标系（永不改变）：页在 baseWidth 下排一次版，_tops / _heights 固定
屏幕坐标系（唯一可变）：矩阵 = translate(offset) × scale
```

```dart
ClipRect(
  child: Transform(
    alignment: Alignment.topLeft,
    transform: Matrix4.identity()
      ..translateByDouble(offset.dx, offset.dy, 0, 1)
      ..scaleByDouble(scale, scale, 1, 1),
    child: SizedBox(width: baseWidth, height: contentH, child: Stack(页们)),
  ),
)
```

由此得到三个保证：

1. **不可能错位**：页的相对位置在整个生命周期内不变，缩放只是把它们一起放大/缩小。
2. **必然跟手**：只有矩阵参数变，没有布局、没有 `jumpTo`、没有 post-frame 回调。
3. **不会位图风暴**：`PageLayer` 的 `width` 恒定（`baseWidth`），缩放过程中不会触发重新请求。

焦点缩放公式不变（现在它是纯数学，不再被重排打断）：

```text
focalContent = (focalScreen - offset) / scale
offset'      = focalScreen - focalContent * scale'
```

## 3. 顺带修的两个问题

| 问题 | 修法 |
|---|---|
| AppBar 百分比与画面不同步（曾出现"标签 200%、画面 100%"） | 菜单只调 `setScale()`，标签由 `onZoomChanged` 回调更新，**单一数据源** |
| 高倍率单页位图过大 | 位图宽度上限 4096px（≈1.9 倍清晰度），更高倍率略软；真正的高倍清晰要分块（T1.5.1，未做） |

## 4. 真机验证

| 场景 | 结果 |
|---|---|
| 滚动模式 100% | ✅ 内容居中、页序正确、页码 2/4 |
| 档位 200% | ✅ 以视口中心放大，页面无错位、无叠压，公式清晰 |
| 200% → 100% 往返 | ✅ 尺寸回退后页面边界仍准确（布局从未参与缩放，结构上无累积误差） |
| 单指拖动 | ✅ 平移跟手 |
| **双指捏合** | ⏳ adb 注入不了多指，需手指验；公式已是焦点缩放 |
