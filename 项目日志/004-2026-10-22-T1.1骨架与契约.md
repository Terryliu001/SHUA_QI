## 2. 本轮决策

| ID | 决策 | 理由 |
|---|---|---|
| **D-11** | 路由用 Navigator 1.0 的 `onGenerateRoute`，**不引 go_router** | go_router 不在 §5.3 白名单。本项目只有 6 个页面，手写路由表更可控，也不会引入"隐式重定向"这类难查行为 |
| **D-12** | `ReaderPrefs` / `ViewMode` / `PaperStyle` 放 `domain/reader/`，**不是** §7 写的 `ui/reader` | `app` 与 `domain` 都要用这套偏好（session 记忆阅读位置、export 决定是否走原图）。放 ui 会让下层反向 import ui，架构测试会直接拦下 |
| **D-13** | `PaperRenderer` 放 `infra/pdf/`，不是 `ui/` | 它是"渲染服务"，要读 PDF、要管位图缓存，属于 infra 职责（§4.2 模块表里 pdf 就是干这个的） |
| **D-14** | `themeModeProvider` 放 `ui/app.dart`，不放 `state/` | 它返回 Material 的 `ThemeMode`，是展示层概念；`state/` 只放纯状态与用例入口 |
| **D-15** | 接口一律 `abstract interface class`，**不写空实现** | 只给"骨头"，不给人造肌肉。空实现会让人误以为"这块能用了" |
| **D-16** | 分层规则写成 4 条测试，不写进文档 | 口头/文档约定一定会被违反；测试会在 CI 与本地 `flutter test` 同时生效 |
| **D-17** | 暂不建空目录（`app/` 下 6 个子模块等） | 空目录不会提醒你"这里还没实现"，反而制造"结构已完成"的错觉。对应任务块开工时再建 |

## 4. 七个契约一览（§7 签名原样保留）

| 接口 | 位置 | 实现任务 | 实现方必须记住的最后一条 |
|---|---|---|---|
| `InkStore` | domain/ink | T2.4 | 原子写（临时文件 + rename），并发调用要排队 |
| `PdfSource` | infra/pdf | T0.4 / T1.5 | 出本层前坐标必须翻成左上原点、单位 pt；`maxEdgePx` 由调用方乘过 dpr |
| `PaperRenderer` | infra/pdf | T1.6 | 按 `(page, style, intensity)` 缓存；`original` 走零处理分支 |
| `OcrEngine` | infra/ocr | T4.1 / T4.2 | 失败/取消返回 `OcrOutput.empty`，**不抛异常** |
| `FormulaEngine` | infra/formula | T4.5 | 未就绪返回 false → 调用方静默退裁图，不许弹窗 |
| `MathView` | ui/widgets/math | T6.7 | 渲染失败必须返回 fallback，绝不返回空白 |
| `LlmClient` | infra/ai | T6.2 | 超时保留已收内容；提示词策略不在这层 |

另外三个值对象做了**减法设计**，值得单独提：

1. `InkStroke.excludeFromOcr` 是**计算属性**而不是字段 —— 只要 `style == highlighter` 就一定被排除，
   从类型上消灭了"忘了设标志"的可能（§6.2 规则 6）。
2. `InkDoc` 不可变，`append()` 返回新实例并 `revision + 1` —— 异步回写的版本校验（INV-02）才有依据。
3. `ReaderPrefs.fromJson` **任何非法值都回落默认，绝不抛** —— 一个被手改坏的设置项不该让 app 起不来；
   `forSurfaceBrightness(isDark:)` 把「深色与纸感互斥」变成可单测的纯函数。
